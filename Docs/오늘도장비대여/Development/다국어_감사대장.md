# 다국어_감사대장

> [!abstract] 한 줄 요약
> **"빠진 게 하나도 없다"를 사람 눈이 아니라 스크립트로 증명하기 위한 감사 도구**와 그 기준선. 작업 대장은 [[다국어_진행상황]], 절차는 `/localize` 스킬에 있다.

---

## 1. 왜 만들었나

기존 완료 판정은 프리팹의 「한글 수 - `LocalizeStringEvent` 수」였는데, 이 방식은 완료를 증명하지 못한다.

| 문제 | 내용 |
|---|---|
| 코드 구동 플레이스홀더를 못 가림 | 코드가 `text =`로 덮어쓰는 자리에도 프리팹엔 한국어가 남아 있다. 그래서 완료된 화면도 계속 카운트에 잡힌다 |
| **정규식이 한글 일부를 통째로 놓쳤다** | `\\u[A-C][0-9A-F]{3}` 로 세고 있었는데 한글 완성형은 **AC00~D7A3**이다. 첫 글자가 `평`(평) 같은 **D 대역이면 그 줄 전체가 안 잡혔다.** 실제로 4건 누락 |
| `m_text` 밖의 한국어를 아예 안 봤다 | `MainMenuScene`의 `SoundManager.bgmVariantGroups[].displayName` 6건이 BGM 변경 화면에 그대로 노출되는데 한 번도 집계된 적이 없었다 |
| 코드 쪽은 셀 방법이 없었다 | `grep`으로 세면 주석·`[Header]`·로그가 섞여 실제 대상이 몇 건인지 알 수 없었다 |

---

## 2. 도구 (`Tools/Localization/`)

①~③은 **측정**, ④~⑦은 **작업**, ⑧은 **컬렉션 신설**, ⑨·⑨-B는 **일관성 QA와 값 교체**, ⑩은 **폰트 문자 목록**, ⑪은 **컴파일 게이트**다.

전부 **PowerShell 5.1 / 순수 ASCII**로 작성했다. 한글이 들어가면 5.1이 ANSI로 읽어 조용히 깨뜨린다(`/localize` 스킬 5-A 참고).

### ① `Audit-UiText.ps1` - 프리팹/씬 전수 대장

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "Tools\Localization\Audit-UiText.ps1"
```

프리팹/씬 YAML의 오브젝트 그래프를 훑어 한국어가 구워진 TMP를 **한 건씩 행으로** 뽑는다. 세는 게 아니라 대장을 만든다.

산출: `Tools/Localization/out/ui-ledger.csv`

| 컬럼 | 의미 |
|---|---|
| `Verdict` | `ATTACHED` / `CODE_DRIVEN` / `REVIEW` / `UNKNOWN_SCRIPT` / `MISSING` / `EXCLUDED` |
| `GoPath` | 루트부터의 GameObject 경로 |
| `Anchor` | TMP 컴포넌트 fileID (부착 스크립트가 쓰는 키) |
| `Refs` | 이 TMP를 참조하는 `스크립트.필드` 전부 |
| `Writers` | 그중 실제로 `.text =` / `+=` / `SetText(` 를 하는 것 |
| `Text` | `\uXXXX` 디코드한 원문 |

**핵심은 `Refs`/`Writers`다.** YAML에서 `필드명: {fileID: <TMP앵커>}` 를 역추적해 어느 스크립트의 어느 필드인지 알아낸 뒤, 그 `.cs`에 `필드.text =` 쓰기가 **실제로 있는지** 대조한다. 이걸 눈으로 하다가 `QuestBoardView`의 확정/파견 버튼(코드가 색만 바꿈)을 코드 구동으로 오분류해 빠뜨린 적이 있다.

판정 규칙:

```
exclusions.csv 에 있음                   -> EXCLUDED
LSE 부착돼 있음                          -> ATTACHED
참조 필드가 .text / SetText 를 직접 씀     -> CODE_DRIVEN    (부착 금지, 코드에서 키 조회)
참조 필드가 메서드 인자로 넘어감            -> REVIEW         (사람이 확인. 대개 코드 구동)
참조하는 스크립트 GUID를 못 찾음           -> UNKNOWN_SCRIPT (판단 불가. 절대 부착하지 않는다)
그 외                                   -> MISSING        (부착 대상)
```

> [!danger] `REVIEW`와 `UNKNOWN_SCRIPT`는 왜 필요했나
> - **`REVIEW`** — `PreparationEventRateTooltip`은 `SetRow(battleRateText, ...)`처럼 TMP를 **인자로 넘겨** 헬퍼 안에서 `label.text = ...`를 한다. 「`필드.text =`가 있는가」만 보면 이게 **부착 대상으로 보인다.** 그대로 부착했으면 로케일 변경 시 코드와 컴포넌트가 같은 TMP를 서로 덮어썼다
> - **`UNKNOWN_SCRIPT`** — 참조하는 MonoBehaviour의 스크립트를 못 찾으면 코드 구동 여부를 판단할 방법이 없다. 이걸 `MISSING`으로 떨어뜨리면 **모르는 것을 부착해도 된다고 말하는 셈**이다. 실제로 `ScoutProgressItem.prefab`이 여기 걸렸고, 추적해 보니 스크립트가 사라진 고아 프리팹이었다
>
> 여전히 도구가 못 잡는 것: `GetComponentInChildren<TextMeshProUGUI>().text = ...` 처럼 **직렬화 필드를 거치지 않는** 코드 구동(`DialogueChoiceButton`). 이런 건 제외 레지스트리에 사유와 함께 등록한다.

`m_text` 외의 직렬화 필드에 있는 한국어(위 `displayName` 같은 것)는 `Kind = field:<필드명>` 행으로 따로 나온다.

### ② `Audit-CodeText.ps1` - 코드 문구 대장

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "Tools\Localization\Audit-CodeText.ps1"
```

런타임 C#(에디터 스크립트 제외)을 **토크나이즈해서** 한국어 문자열 리터럴을 뽑는다. 줄 단위 grep이 아니라 문자 단위 스캐너라, 여러 줄에 걸친 `Log.Info(...)`나 `[Header(...)]` 안의 문자열도 정확히 걸러낸다.

산출: `Tools/Localization/out/code-ledger.csv` (`Status` = `TODO` / `EXCLUDED`, `Context` = 그 리터럴이 속한 문장의 앞부분)

자동 제외 규칙:

| 규칙 | 사유 |
|---|---|
| `Debug.Log*` / `Log.Info·Warn·Error` | 로그 (`Log`는 이 프로젝트의 `Debug` 래퍼 - `Scripts/Utils/Log.cs`) |
| `[Header]` `[Tooltip]` `[CreateAssetMenu]` `[MenuItem]` 등 | 에디터 전용 어트리뷰트 |
| `AddGold(...)` / `SpendGold(...)` / `AddReputation(...)` 의 **아직 닫히지 않은** 인자 | 골드·평판 사유 문자열은 **내부 식별자**다. `Log.Info`와 Analytics `source` 매핑에만 쓰이고 화면엔 안 나온다 |
| `reason == "..."` / `reason.StartsWith("...")` | 같은 사유 문자열의 비교 (`EconomyManager.GetSourceAnalyticsName`) |

> [!danger] 「같은 문장에 있기만 하면 제외」는 틀렸다
> 처음엔 `AddGold(`가 문장 어딘가에 있으면 제외했는데,
> ```csharp
> if (!EconomyManager.Instance.SpendGold(price, "암시장 구매")) return (false, "골드가 부족합니다.");
> ```
> 이건 한 문장이라 **뒤쪽 UI 문구까지 조용히 제외**됐다. 그래서 「그 호출의 괄호가 아직 닫히지 않았을 때만」으로 좁혔는데, 이번엔 `SpendGold(GetRefreshCost(), "...")`의 **중첩 호출 닫는 괄호**를 오판했다. 최종적으로 **괄호 깊이**로 판정한다. 이 두 번의 수정으로 6건 + 1건이 새로 드러났다.

그 외 개별 제외는 `code-exclusions.csv`에 `파일명|리터럴` 또는 `파일명|*` 형식으로 사유와 함께 등록한다.

### ③ `Verify-Localization.ps1` - 무결성 검사

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "Tools\Localization\Verify-Localization.ps1"
```

문제가 하나라도 있으면 **exit 1**을 낸다. 배치 완료 게이트로 쓴다.

| # | 검사 | 잡는 것 |
|---|---|---|
| 1 | 테이블 ID 정합성 | Shared Data와 4개 로케일 테이블의 `m_Id` 집합 불일치 |
| 2 | 빈 번역값 | ID는 있는데 `m_Localized:`가 비어 있음 |
| 3 | LSE 참조 건전성 | 존재하지 않는 테이블/키 참조, 타깃이 TMP가 아님, 타깃이 다른 GameObject에 있음 |
| 4 | 코드 키 실존 | `GetLocalizedString("표","키")`의 키가 테이블에 없음 |
| 5 | 프리팹 YAML 건전성 | 앵커 중복, 어느 GameObject에도 등록 안 된 LSE 컴포넌트 |
| 6 | 데이터에 저장된 키 | 텍스트 대신 **번역 키**를 담는 필드(씬의 BGM 그룹 `displayName` 등)의 값이 실제 키인지 |
| 7 | 미번역 값 | en / ja / zh-Hans 값에 **한국어가 그대로 남아 있는** 엔트리 |
| 8 | 컬렉션 배선 | 에디터용 컬렉션 자산 누락/오배선, Addressables 미등록 |
| 9 | SO 표시 키 | Phase 5 키(`{종류}_{StaticID}_{필드}`)가 `Data` 테이블에서 안 풀림 |

> [!danger] 검사 ⑧ - 컬렉션은 반대 방향으로 각각 조용히 깨진다
> 컬렉션 하나는 **독립적으로 고장 나는 두 절반**으로 되어 있다.
> - **런타임 절반** - 로케일 테이블 4개 + Shared Data의 Addressables 등록. 빠지면 에디터에선 멀쩡하고 **디바이스 빌드에서만** 사라진다
> - **에디터 절반** - `<이름>.asset`(`StringTableCollection`). Localization Tables 창이 **이 자산만 보고** 컬렉션 목록을 만든다. Addressables에 넣으면 안 되는 에디터 전용 자산이다. 빠지면 런타임 번역은 완벽한데 **창에 아예 안 떠서 아무도 편집할 수 없다**
>
> `New-LocCollection.ps1`이 이 자산을 안 만들던 시절에 태어난 `Data` / `Names` / `Dialogue` 세 컬렉션이 전부 이 상태였고(키 605개), 사용자가 `Data` 하나만 눈치챘다. 검사 1~7 어디에도 안 걸린다.

> [!danger] 검사 ⑨ - Phase 5 키는 코드에 문자열로 안 적혀 있다
> `DataLocalizer.Key()`가 SO의 `StaticID`로 **런타임에 조립**하므로(`Dungeon_DGN_COM_001_Name`) 검사 ④의 시야 밖이다. `StaticID`를 바꾸면 키가 깨지고 **모든 언어가 조용히 한국어로 되돌아간다** - 에러도, 미번역 표시도 없다. 그래서 `so-ledger.csv`의 모든 행이 실제 키로 풀리는지 대조한다(`$MIGRATED`에 나열된 종류만). **키 충돌**(두 값이 같은 키를 만드는 경우)도 여기서 잡는다.
> 이 검사를 쓰려면 `Audit-SoText.ps1`을 먼저 돌려 대장이 최신이어야 한다. 종류를 새로 마이그레이션하면 `$MIGRATED`에 추가한다.

> [!note] 검사 ⑨의 슬라이스 단위는 `Config`만 다르다
> 다른 종류는 `$MIGRATED`에 **필드 이름**을 나열해 「이 필드는 이관했다」를 표시하지만, `Config`는 **자산 이름**(대장의 `StaticID` 칸)을 나열한다. 잎 필드 이름이 자산끼리 겹치기 때문이다 — `lines`는 `TutorialConfig.steps[].lines`이기도 하고 `WeaponShopConfig.merchantGreetings[].lines`이기도 해서, 필드로 열면 **아직 안 끝낸 자산이 딸려 들어와 실패**한다(실제로 겪었다). Config는 자산 하나씩 끝내므로 자산 단위가 작업 방식과도 맞는다.

> [!warning] `Get-SoKey`는 `DataLocalizer`의 **사본**이다 - 손으로 맞춰야 한다
> 키 규칙이 지금 **세 군데**에 있다: `DataLocalizer`(런타임, 진실) · `Verify-Localization`의 `Get-SoKey`(검사) · 번역 투입 스크립트(테이블 생성). 검사 ⑨는 뒤의 둘이 서로 맞는지만 증명하고, **런타임 C#이 갈라져도 통과한다.**
> 그래서 (a) 규칙을 세 곳 모두 짧고 뻔하게 유지하고, (b) 배치 끝의 **F11 실동작 확인을 생략하지 않는다.** 자동으로 못 잡는 유일한 구멍이다.

> [!note] 검사 ④는 네 가지 호출 형태를 전부 본다
> 처음엔 `GetLocalizedString("표","키")` 리터럴만 찾고 있어서 **54건만 검사**했다. 이 코드베이스에는 파일별 헬퍼(`L("키")`, `M("키")`, `LCommon("키")`)와 삼항 분기(`cond ? "KeyA" : "KeyB"`)가 흔한데 그게 전부 사각지대였다. 네 형태를 모두 잡도록 고쳐 **382건 검사**가 됐다.

> [!danger] 왜 이게 필수인가
> String Database는 `UseFallback`이 켜져 있다. **어떤 로케일에 값이 없으면 에러 대신 한국어가 조용히 나온다.** 화면만 봐서는 "아직 번역 안 됨"과 구별이 안 되므로, ID 정합성과 빈 값 검사를 스크립트로 안 돌리면 절대 못 잡는다.

### ③-B `Audit-SoText.ps1` - SO 데이터 전수 대장 (Phase 5)

```powershell
powershell -File Tools\Localization\Audit-SoText.ps1   # out/so-ledger.csv
```

ScriptableObject에 들어 있는 표시 텍스트를 **한 값당 한 행**으로 뽑는다. `Type | Asset | StaticID | Field | Index | Text` - 리스트 필드는 항목마다 `Index`가 붙는다.

- 대상 필드는 **명시적으로 나열**한다(스크립트 상단 `$SPEC`). 「한국어면 전부」로 잡으면 금칙어 목록·정규식·에디터 라벨까지 딸려온다
- `NicknameConfig.asset`은 통째로 제외 — 한글 금칙어 4,278줄은 표시 텍스트가 아니라 Phase 6 항목이다
- **접힘(folding) 처리 포함** — 긴 설명문은 YAML에서 여러 줄로 저장되는데, 첫 줄만 읽으면 번역문이 잘린다
- **대화는 전용 구조 인식 파서**를 쓴다 (`Read-DialogueRows`) — 아래 참고

> [!danger] 중첩된 텍스트는 평면 스캔으로 못 뽑는다
> `DialogueData`는 텍스트가 두 단계 안에 있다 — `nodes[].dialogueText` / `nodes[].choices[].choiceText`. 평면 스캔은 한 자산의 모든 노드에 **같은 `Field` + 빈 `Index`**를 줘서, 188행 중 고유 키가 166개뿐이고 **한 키에 최대 5개 문자열**이 몰렸다.
>
> **등장 순서로 번호를 매기는 것은 해결책이 아니다.** 한국어가 없거나 빈 노드는 대장에 안 올라오므로 그 뒤 인덱스가 전부 밀리고, 결과적으로 **다른 노드의 대사가 화면에 뜬다.** 폴백이 멀쩡한 문장을 내보내니 눈으로는 못 잡는다.
>
> 그래서 들여쓰기 구조를 실제로 따라가며 진짜 노드/선택지 번호를 싣는다. `choices`는 노드의 마지막 필드라서 「choices 안이다」 상태는 다음 노드가 시작될 때까지 유지하면 된다.
>
> 다른 SO에 같은 형태의 중첩 리스트가 생기면 **똑같이 전용 파서를 붙인다.** `$SPEC`의 `Lists`는 문자열 리스트(`greetingLines` 등) 전용이다.

> [!danger] `Config`는 **일곱 자산 전부**가 같은 병에 걸려 있었다 (`Read-ConfigRows`)
> 착수 문서에는 `SeerConfig` 163건이 *중첩이 없어 지금 파서로 잘 나온다*고 적혀 있었지만 틀렸다. 그중 100건이 `AbstractLuckLines` 구조체 5개 안에 있어서, 평면 스캔은 `descGreat.bad[0]`~`descGrim.bad[0]` **5개에 같은 키**를 줬다. 전체로 보면 **374행 -> 고유 121개**였다.
>
> `$CONFIG_SPEC`이 자산마다 「직속 리스트 / 중첩 구조체 / 구조체 리스트(+식별자)」를 기술하고, `Read-ConfigRows`가 그대로 훑는다. **구조체 리스트는 위치가 아니라 그 구조체가 이미 갖고 있는 식별자로 주소를 만든다** — 인스펙터에서 순서를 바꿔도 안 깨지게 하기 위해서다.
>
> | 자산 | 식별자 | 키 |
> |---|---|---|
> | `TutorialConfig.steps[]` | `TutorialLineKey` (enum) | `Config_Tutorial_{키}_lines_{i}` |
> | `BlacksmithConfig.blacksmithDataArray[]` | `BlacksmithData.StaticID` | `Config_Blacksmith_{StaticID}_{필드}[_{i}]` |
> | `LegacyConfig.upgrades[]` | `UpgradeKey` (enum) | `Config_Legacy_{키}_description` |
> | `AdventureInfoConfig.bonusVisuals[]` | `BonusType` (enum) | `Config_AdventureInfo_{타입}_displayName` |
> | `PriceTierConfig.stepNotices[]` | 없음 — **위치가 곧 의미**(주차 계단) | `Config_PriceTier_stepNotices{n}_{필드}_{i}` |
> | `WeaponShopConfig.merchantGreetings[]` | 없음 — 위치가 곧 의미(주차 구간) | `Config_WeaponShop_merchantGreetings{n}_lines_{i}` |
>
> 결과: **374행 -> 고유 374개, 충돌 0.**
>
> Config SO는 `BaseData`가 아니라 진짜 `StaticID`가 없으므로, 대장의 `StaticID` 칸에는 **짧은 자산명**(`Seer`·`Tutorial`…)을 싣는다. 그러면 키가 `Config_{StaticID}_{Index}`로 떨어지고 — **경로 전체가 `Index` 칸에 들어 있다** — 검사 ⑨의 「빈 StaticID는 실패」 규칙도 그대로 성립한다.

**`Get-EnumMap` — enum 매핑을 이 파일에 베끼지 않는다**

`TutorialLineKey`·`UpgradeKey`·`BonusType`을 **C# 원본에서 읽어** 만든다(명시값·암묵 증가 모두 처리). 그래서 enum 멤버를 추가해도 도구를 고칠 필요가 없고, 에셋에 enum에 없는 값이 들어 있으면 **이름을 지어내지 않고 예외를 던진다.**

**`Measure-ConfigValues` — 완결성 트립와이어**

「값을 시작하는 줄 중 한국어가 있는 것」을 세어, 구조 파서가 뽑은 수 + 제외한 수와 대조한다. 다르면 예외로 멈춘다.

> 이게 **즉시 값을 했다.** `WeaponShopConfig.merchantGreetings`를 0건으로 놓치고 있었다 — 구조체의 첫 필드가 리스트라 `  - lines:` 대시 줄이 **리스트 헤더를 겸하는데** 파서가 그걸 몰랐다. 트립와이어가 없었으면 20건이 소리 없이 사라졌을 것이다. 자산에 새 필드를 추가하고 `$CONFIG_SPEC`을 안 고치는 경우도 여기서 걸린다.

새 SO 타입이나 새 텍스트 필드를 추가하면 `$SPEC`에도 넣는다. 안 넣으면 조용히 빠진다.

**제외 레지스트리 두 층** — 둘 다 사유를 요구하고, 실행할 때마다 사유와 건수를 다시 출력한다. 목록에서 지우는 게 아니라 **사유를 붙여 남기는** 방식이라 나중에 판단을 다시 검토할 수 있다.

| 레지스트리 | 단위 | 현재 항목 |
|---|---|---|
| `$SKIP_ASSETS` | 자산 파일 | `NicknameConfig.asset` |
| `$SKIP_FIELDS` | `종류/필드` | `Adventurer/adventurerName`(10), `VisitorEvent/description`(9), `Dialogue/dialogueName`(54) |

- `Adventurer/adventurerName` — 유명 모험가 이름은 이미 **`Names` 테이블**로 풀린다(`nameKey = Name_<StaticID>`). SO 필드는 에디터 표시용 겸 세이브 폴백 사본이라 `Data`에 또 넣으면 같은 문장을 두 테이블에서 이중 관리하게 된다
- `VisitorEvent/description` — 값이 말 그대로 `"<이벤트명> 이벤트"`인 에디터 메모다. 런타임 콜사이트가 하나도 없다
- `Dialogue/dialogueName` — 대화 자산 자체의 에디터 라벨. 필드 선언 말고는 코드에서 아무도 안 읽는다
- `DungeonEvent/summary` — 런타임에서 아무도 안 읽는다. 전투용은 Animator 컨트롤러명 접두사(식별자), 비전투용은 `description`과 겹치는 짧은 라벨
- `Quest/requirementText` · `Quest/description` — `WeeklyQuestGenerator`가 구운 값 (아래 참고)
- `Config/label` — **죽은 직렬화 데이터.** `MoodLabelEntry`에서 필드가 제거됐는데 `.asset` YAML에만 20줄이 남아 있다. `MoodLabelCalculator`는 색만 돌려주므로 번역해도 화면에 뜰 수 없고, 자산을 다시 저장하면 사라진다

> [!tip] 제외 판단은 「콜사이트가 있는가」로 한다
> 필드 이름만 보고 정하면 틀린다 — `WeaponData.description`·`MaterialData.description`도 콜사이트가 0건이지만 **플레이어에게 보일 목적의 플레이버 텍스트**라 번역했고, `VisitorEvent.description`은 같은 이름이지만 에디터 메모라 뺐다. 종류를 착수하기 전에 필드마다 표시 지점을 먼저 찾는다.

> [!danger] 구워진 문자열은 번역 대상이 아니라 **조립 대상**이다
> `Quest/requirementText` 147건은 「`{던전} 클리어 {n}회`」류 템플릿 5개에서 나온 값이고, 그 부품(던전 이름·무기 타입·등급)은 **이미 전부 번역돼 있었다.** 이걸 통째로 번역하면
> - 같은 문장을 SO와 테이블 두 곳에서 관리하게 되고
> - 생성기(`WeeklyQuestGenerator`)를 다시 돌리면 **한국어만 바뀌고 번역은 옛 문장으로 남는다**(폴백이 안 걸리므로 다른 언어에서만 조용히 틀린 문장이 뜬다)
>
> 그래서 테이블에는 **템플릿 5개만** 넣고 `UITranslator.QuestRequirementText`가 런타임에 조립한다. 147 -> 5.
>
> **판별법:** 그 문자열을 만드는 코드가 저장소에 있는가? 있으면 조립으로 간다. 에디터 생성기·`string.Join`·`$"..."` 보간으로 SO 필드를 채우는 코드가 보이면 신호다.

입력 CSV(`Collection,Id,Key,Smart,ko,en,ja,zhHans`, UTF-8 BOM)를 받아 **5개 파일(Shared + 4로케일)에 동시에** 엔트리를 넣는다. Smart String이면 각 로케일의 `SmartFormatTag` 메타데이터에도 id를 등록한다. 손으로 넣다가 ID 집합이 어긋나는 사고를 막기 위한 도구 - 하나라도 문제가 있으면 **아무 파일도 건드리지 않고** 실패한다.

### ④-B `Build-BatchCsv.py` - 번역 파일 -> 투입 CSV (Phase 5)

```powershell
python Tools\Localization\Build-BatchCsv.py <종류> <번역.tsv> <시작ID> <출력.csv> [--asset <자산명>]
```

번역 파일에는 **en/ja/zhHans만** 적는다. **한국어는 이 스크립트가 `so-ledger.csv`에서 가져온다.**

조인 키는 종류의 모양에 따라 둘이다.

| 종류 | TSV 헤더 | 키 |
|---|---|---|
| 평면 (`Weapon`·`Dungeon`·`Material`·`ActiveItem`·`VisitorEvent`·`DungeonEvent`·`Quest`) | `StaticID / Field / en / ja / zhHans` | `{종류}_{StaticID}_{접미사}` |
| `Config` | `Key / en / ja / zhHans` | `Config_{짧은자산명}_{Index}` — 경로가 이미 대장의 `Index` 칸에 있다 |

`Config`는 **완성된 키로 조인**하므로, 대장이 만든 키와 번역 파일이 서로를 검증한다. `--asset`으로 한 자산씩 잘라 작업한다.

> [!danger] ko를 손으로 옮겨 적으면 안 되는 이유
> 한 글자만 달라도 그 자리는 조용히 번역이 안 붙는다 - 폴백이 한국어를 내보내므로 **화면상 구별이 불가능**하다. 그래서 ko는 아예 적지 않고, 조인을 양방향으로 검사한다.
> - 대장에 있는데 번역이 없다 -> 에러
> - 번역에 있는데 대장에 없다(오타) -> 에러
>
> 추가로 `{자리표시자}` · **리치텍스트 태그** · **백슬래시 이스케이프** 세 가지가 ko와 **집합으로** 일치하는지 대조한다. 하나라도 어긋나면 **아무것도 쓰지 않고** 실패한다.

> [!danger] 「개수만 비교」와 「`<color=`만 검사」는 셋 다 구멍이었다 (2026-08-03 수정)
> - 자리표시자 정규식이 `\{[A-Za-z_]+\}` 라서 **`{0}`을 아예 못 봤다** — `SeerConfig.greetingLines`의 상담 비용 슬롯이 검사 밖이었다. 숫자를 포함하도록 넓혔다
> - 태그 검사가 `<color=`만 세고 있어서 `TutorialConfig`의 **`<b>` 37쌍을 전혀 안 봤다.** 모든 태그를 집합으로 비교하도록 바꿨더니, `<b>` 짝이 3개인 문장에 4개를 쓴 오역을 바로 잡아냈다
> - 그 태그 정규식에 **캡처 그룹**이 들어 있어 `re.findall`이 태그가 아니라 `=값` 부분만 돌려줬다 — `<b>`와 `<i>`가 같은 것으로 비교됐다는 뜻이다. 비캡처 그룹으로 고쳤다
> - `\n` **개수** 비교는 `\\n`(SeerConfig가 저장하는 두 글자짜리 리터럴, `PickRandom`이 개행으로 바꾼다)과 `\n`(진짜 개행)을 **구별하지 못했다.** 이스케이프 시퀀스를 통째로 집합 비교한다
>
> 넷 다 고친 뒤 **일부러 깨뜨려 실제로 실패하는지 확인**했다. 검사는 「있다」가 아니라 「실패한다」를 봐야 믿을 수 있다.

PowerShell이 아니라 Python인 이유: PS 5.1은 BOM 없는 UTF-8을 ANSI로 읽어 CJK를 깨뜨린다. 출력은 `Add-LocEntries.ps1`가 기대하는 **UTF-8 BOM**으로 쓴다.

키가 평면(`{종류}_{StaticID}_{접미사}`)이 아닌 종류 - `Dialogue`(노드/선택지 인덱스), `Config`(StaticID 자체가 없음) - 는 전용 빌더가 필요하다.

### ⑤ `Attach-Lse.ps1` - LocalizeStringEvent 부착

```powershell
powershell -File Tools\Localization\Attach-Lse.ps1 -Csv <입력.csv> [-WhatIf]
```

입력 CSV(`Path,Anchor,Collection,Key`)의 `Path`/`Anchor`는 **`ui-ledger.csv`에서 그대로 복사**한다. 에디터 우클릭 Localize와 같은 결과를 YAML 직접 편집으로 만든다.

- 멱등: 이미 LSE가 붙은 TMP는 건너뛴다

> [!danger] 이 도구를 고치다 실제로 낸 사고 두 가지
> - **줄바꿈 전멸** - `WriteAllLines`는 CRLF로 쓴다. LF로 저장된 씬/프리팹에 쓰면 파일 전체가 다시 쓰여 진짜 변경이 diff에 묻힌다. `core.autocrlf=true`라 워킹트리에 CRLF 파일과 LF 파일이 섞여 있으므로 **원본 줄바꿈을 감지해 그대로 쓴다**
> - **PowerShell 배열 리터럴의 콤마 우선순위** - `@('m_Name:' + $SP, ...)`에서 `,`가 `+`보다 강하게 묶여 공백이 **다음 줄로 분리**됐다. Unity가 빈 문자열을 `key: `(뒤 공백)로 쓰므로, 그런 줄은 **큰따옴표 안에 공백을 포함**시켜 만든다

### ⑥ `Apply-CodeEdits.ps1` - 코드 리터럴 일괄 치환

```powershell
powershell -File Tools\Localization\Apply-CodeEdits.ps1 -EditsFile <data.ps1> [-WhatIf]
```

`@{ F=파일; Old=원문; New=대체 }` 목록을 받아 치환한다. **모든 항목이 정확히 기대한 횟수만큼 매칭되지 않으면 아무 파일도 건드리지 않는다.** 원본 줄바꿈을 보존하고, `Using =` 항목으로 using 지시문도 넣는다.

> [!danger] PowerShell 함정 세 가지 (전부 여기서 실제로 겪음)
> - **`Count` 키 금지** — 해시테이블에는 이미 `Count` 속성(키 개수)이 있어 조용히 가려진다. 반복 횟수는 `Times`를 쓴다
> - **파라미터 이름을 `$Edits`로 두면 안 된다** — PowerShell 변수는 대소문자를 구분하지 않으므로 `[string]$Edits` 파라미터가 데이터 파일의 `$edits` 배열을 **문자열로 강제 변환**해 버린다. `-EditsFile`로 이름을 다르게 둔다
> - **함수 안의 지역 변수가 상위 스코프를 가린다** — 같은 계열의 세 번째 사고가 `Audit-SoText.ps1`에서 났다. `Read-ConfigRows`의 지역 `$root`가, 거기서 호출한 `Get-EnumMap` 안의 **스크립트 파라미터 `$Root`를 가려** `Assets\...` 대신 `bonusVisuals\Assets\...`를 열려고 했다. PowerShell은 대소문자를 구분하지 않는 데다 **호출 스택을 타고** 변수를 찾는다. 스크립트 파라미터를 함수에서 쓸 때는 `$script:Root`처럼 스코프를 명시한다

### ⑨ `Audit-Consistency.py` - 번역 일관성 QA (기계 판정분)

```powershell
python Tools\Localization\Audit-Consistency.py   # out/qa/*.csv + summary.txt
```

번역 **품질**은 검사 대상이 아니지만, **일관성**은 상당 부분 기계가 판정할 수 있다. 2,108키 x 4로케일을 전수로 훑어 6가지를 본다.

| 검사 | 잡는 것 |
|---|---|
| A `shape` | 자리표시자 · 리치텍스트 태그 · 백슬래시 이스케이프 · 중괄호 짝이 ko와 다름 |
| B `forward` | **같은 한국어가 서로 다르게 번역됨** |
| C `reverse` | **같은 영어가 서로 다른 한국어에서 나옴** |
| D `length` | 로케일 중앙값 대비 지나치게 긴 번역 (레이아웃 깨짐 후보) |
| E `blank` | 빈 값 |
| F `smart` | Smart String 문법인데 Smart 플래그가 없음(문자열이 그대로 화면에 뜬다), 또는 로케일마다 플래그가 다름 |

`all.csv`(전체 키 x 4로케일)도 함께 떨어진다 — `.asset`은 `\uXXXX`라 사람이 못 읽으므로, 손으로 문구를 볼 때는 이 파일을 본다.

> [!note] B·C가 **완전 일치**로만 판정하는 이유
> 오탐이 0이기 때문이다. 한국어가 바이트 단위로 같은 두 항목은 의도적으로 달리 쓴 게 아니라면 모든 언어에서 같아야 한다. 부분 일치·유사도로 넓히면 보고서가 노이즈로 덮여 아무도 안 읽는다.

> [!danger] A를 만들 때 오탐 15건을 먼저 걷어냈다 — 그 과정이 규칙이다
> 처음 돌렸을 때 15건이 나왔는데 **전부 정상**이었다. 걷어낸 근거를 규칙으로 박아 뒀다.
> - `{particle}` — 한국어 목적격 조사 전용 슬롯. `UITranslator.ObjectParticle`이 다른 로케일에선 빈 문자열을 돌려주므로 **번역문에 없는 게 맞다**
> - `{days:plural:day|days}` — 영어 Smart String 복수 처리. `{days}`와 **같은 인자**를 가리키므로 자리표시자 집합으로는 동일하다
> - 같은 인자를 두 번 쓰는 것도 정상(`{days} {days:plural:day|days}`) — 그래서 **다중집합이 아니라 집합**으로 비교한다
>
> 규칙을 좁힌 뒤 실제로 `{days}`를 지워 보고 검출되는지 확인했다. 「0건」은 검사가 잠든 것과 구별돼야 한다.

### ⑨-B `Set-LocValues.py` - 기존 항목의 **값** 교체

```powershell
python Tools\Localization\Set-LocValues.py <edits.csv> [--dry-run]
# edits.csv: Collection,Key,Locale,Value
```

`Add-LocEntries`(생성)·`Remove-LocEntries`(삭제)에 없던 **세 번째 동사**. 번역 자체가 바뀔 때(용어 통일, QA 후속) 쓴다.

- (Collection, Key, Locale)이 전부 풀리고 현재 값을 찾아야 하며, 하나라도 실패하면 **아무것도 쓰지 않는다**
- 바꿀 필요가 없는 항목은 「이미 맞음」으로 **보고**한다 (조용히 넘어가지 않는다)
- **CRLF와 BOM 없음을 보존**한다 — 이 파일들은 Unity가 BOM 없이 CRLF로 쓰므로, 통째로 다시 쓰면 3줄 수정이 4,000줄 diff가 된다
- id·메타데이터는 건드리지 않으므로 ID 집합 정합성(검사 ①)은 깨질 수 없다

> [!important] 값을 손으로 옮겨 적지 않는다
> 용어 검수 106건을 적용할 때, 새 문장을 타이핑하는 대신 **「이 키의 현재 값에서 A를 B로」** 규칙만 적고 스크립트가 치환하게 했다. 오타가 섞이면 폴백 때문에 화면에서 구별되지 않기 때문이다 — `Build-BatchCsv.py`가 ko를 대장에서 가져오는 것과 같은 이유다.

### ⑩ `Export-FontCharset.py` - 폰트 아틀라스용 실사용 문자 목록

```powershell
python Tools\Localization\Export-FontCharset.py   # out/charset/<로케일>.txt + .range
```

게임이 **실제로 표시할 수 있는** 문자만 로케일별로 뽑는다 — 테이블 6종의 모든 번역값 + SO에 남은 한국어(ko는 테이블을 안 타므로 대장에서 가져온다). Font Asset Creator의 `Custom Characters`에 그대로 붙여넣는 용도다.

`ja+zh-Hans.txt`가 CJK 아틀라스용 합집합이다(2,074자).

> [!danger] 이 목록에 **닉네임은 없다** — 그래서 Dynamic 폴백을 지워선 안 된다
> 게임 텍스트는 열거 가능하지만 플레이어가 입력하는 닉네임은 아니다. 닉네임 허용 문자를 ja/zh로 넓혔으므로(Phase 6), **Static 아틀라스만 남기면 순위표에 뜨는 남의 닉네임이 두부(□)로 깨진다.**
>
> 「상용 한자를 통째로 굽는다」는 해법이 아니다 — 실사용(6.4MB)의 **3.8배(24MB)** 가 되면서도 사람 이름에 흔한 목록 밖 한자(`喆`·`玥`·`昱`)를 못 덮어 **원래 목적에 실패한다.** 열거 가능한 쪽은 Static, 열거 불가능한 쪽은 Dynamic이 맞다.
>
> 한국어가 전체(11,318자) Static인 것은 한글 완성형이 11,172자로 **닫혀 있어서** 가능한 것이고, CJK엔 같은 수를 쓸 수 없다.

### ⑪ `dotnet build` - 컴파일 게이트

```powershell
dotnet build "Assembly-CSharp.csproj" -v q --nologo
```

Unity가 생성해 둔 프로젝트 파일을 `dotnet`으로 **7초 만에** 컴파일한다. 일괄 치환 뒤 반드시 통과시킨다 - 헬퍼 메서드를 메서드 본문 안에 잘못 넣거나, 보간 문자열의 `$`가 남는 사고를 전부 여기서 잡았다. 에디터를 열 필요가 없다.

> [!warning] 새로 만든 `.cs` 파일은 게이트가 못 본다
> `Assembly-CSharp.csproj`는 Unity가 생성하므로, 에디터를 아직 안 연 신규 파일은 `<Compile Include>` 목록에 없다. **그 파일의 오류가 통과로 나온다** - `DataLocalizer.cs`를 만들었을 때 실제로 이렇게 지나갔다.
> 신규 파일을 만들면 csproj에 항목을 직접 넣어 게이트를 통과시키고, Unity를 한 번 열면 정식으로 재생성된다.

## 4. 완료 기준

배치 하나를 끝냈다고 말하려면 **네 가지가 동시에** 성립해야 한다.

1. `ui-ledger.csv`에서 그 배치 파일들의 `MISSING` = 0 (그리고 `REVIEW`/`UNKNOWN_SCRIPT` 행은 사람이 확인)
2. `code-ledger.csv`에서 그 배치 파일들의 `TODO` = 0
3. `Verify-Localization.ps1` exit 0
4. `dotnet build` 오류 0개

전체 완료는 위 4개가 **전 파일에 대해** 성립하는 것이다. **Phase 3은 2026-08-03에 이 기준으로 완료**했고, 감사를 3회 연속 돌려 같은 결과가 나오는 것까지 확인했다.

> [!danger] 검사가 절대 못 보는 것 — **세이브에 구워지는 번역**
> 대장·검사 9항목 전부가 「키가 테이블에서 풀리는가」만 본다. 그래서 **번역된 문장을 세이브에 저장해 버리는** 실수는 어디에도 안 걸린다 — 키는 멀쩡히 풀리고, 저장된 문장도 그 자체로는 정상적인 번역문이기 때문이다.
>
> 증상은 「언어를 바꿨는데 그 값만 안 바뀐다」이고, 주변 문구는 정상적으로 바뀌므로 **한 화면 안에서 언어가 섞인다.** Phase 5-Config에서 `SeerResult.description`이 실제로 여기 걸렸다(`gamedata.json`에 저장됨).
>
> **규칙: 값이 세이브에 들어가면 문장이 아니라 키를 저장하고, 표시할 때 푼다.** 선례가 둘 있다 — `AdventurerInstance.nameKey`, `SeerResult.descriptionKey`. 구버전 세이브는 키가 비어 있으므로 `DataLocalizer.Get`이 원문을 돌려줘 자동으로 호환된다.

> [!note] 아직 대장이 못 보는 것
> - **동적 키 조합** (`$"WeaponEffectType_{type}"` 같은 코드 조합 키)은 검사 ④가 검증하지 못한다. enum 멤버를 순회해 키 존재를 확인하는 별도 확인이 필요하다
> - **직렬화 필드를 안 거치는 코드 구동** (`GetComponentInChildren<TextMeshProUGUI>().text = ...`)은 프리팹 쪽에서 감지할 수 없다. 제외 레지스트리로 처리한다
> - **실제 렌더링**은 스크립트로 확인할 수 없다. F11(언어 순환) / Shift+F11(씬 리로드)로 사람이 봐야 한다
> - **번역 품질**은 검사 대상이 아니다. 검사 ⑦은 「한국어가 남아 있는가」만 본다
