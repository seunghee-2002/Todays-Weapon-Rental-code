# 데이터 구조

> [!abstract] 한 줄 요약

## 저장 데이터 두 갈래

| 구분 | 클래스 | 경로 | 생명주기 |
|---|---|---|---|
| **한 회차** | `GameData` | `persistentDataPath/gamedata.json` | 게임오버 시 **삭제** |
| **영구** | `PlayerData` | `persistentDataPath/legacy.json` | 계정에 누적 (유산·영구 업그레이드) |

```csharp
// SaveManager (static class, Scripts/Systems/)
SaveManager.SaveGame(gameData);     // -> gamedata.json (한 회차)
SaveManager.LoadGame();             // -> GameData
SaveManager.HasGameData();
SaveManager.SavePlayer(playerData); // -> legacy.json (영구)
SaveManager.LoadPlayer();
```

> [!warning] 직렬화 제약
> **`JsonUtility` 사용 (Newtonsoft 아님).** Dictionary는 커스텀 `SerializableDictionary<K,V>` 구현을 쓴다.
> 새 저장 데이터를 추가하면 `GameData` 또는 `PlayerData`에 필드를 넣고 `SaveDataConverter`를 갱신한다.

### `GameData` 구조

```
GameData
├── int gold, reputation, currentDay, legacyPoints, playerInsight
├── float bgmVolume, sfxVolume
├── List<WeaponInstanceSaveData>        ownedWeapons
├── List<MaterialInstance>              ownedMaterials
├── List<ActiveItemInstanceSaveData>    ownedActiveItems
├── List<AdventurerInstanceSaveData>    namedAdventurerInstances
├── List<AdventurerInstanceSaveData>    normalAdventurerInstances
├── List<string>                        deadAdventurerStaticIDs
├── List<AdventureInstanceSaveData>     ongoingAdventures
├── List<AdventureResult>               completedAdventureResults
├── List<string>                        unlockedWeaponRecipes
├── List<string>                        completedEventIDs
├── List<VisitorNPCSaveData>            activeVisitorStates
├── SerializableDictionary<string, DungeonStatData> dungeonStats
└── int currentWeek, BlacksmithType lastRequestedBlacksmithType
```

> 저장 시스템의 기획 관점 설명(클라우드 동기화·복원 코드·안전장치)은 [[저장]]에 있다.

## 정적 데이터 (ScriptableObject)

위치: `Scripts/Data/StaticData/` · 에셋: `Assets/_Projects/Data/`

| 클래스 | 주요 필드 |
|---|---|
| `WeaponData` | `weaponName`, `baseGrade`(Grade), `weaponType`(WeaponType), `basePrice` |
| `AdventurerData` | `adventurerName`, `isNamed`, `strRange`/`dexRange`/`intRange`/`lukRange`(Vector2Int), `trait`(TraitType) |
| `DungeonData` | `dungeonName`, `grade`, `armorType`, `baseStatThreshold`, `dropMaterials`, `baseDuration`, `eventPool` |
| `MaterialData` | `materialName`, `baseValue`, `buyPrice`, `materialType`(MaterialType) |
| `WeaponEffectData` | `grade`, `effectType`(WeaponEffectType), `baseValueRange`(Vector2), `weight` |
| `WeaponRecipeData` | `resultWeapon`, `requiredMaterials`, `requiredGold` |
| `ActiveItemData` | `itemName`, `effectType`, `duration`(days) |
| `WeeklyQuestData` | `questName`, `requirements`, `rewards`, `questWeight` |

그 밖에 `BlacksmithData`, `DialogueData`, 던전/방문자 이벤트 Data, 외형 Data 등이 있다.
스탯 전용 SO는 `Scripts/Data/StatData/` (`AdventurerStatData`, `DungeonStatData`).

> [!danger] SO를 건드리면 CSV Importer도 같이 고친다
> `Scripts/Data/StaticData/` 아래 SO의 필드·타입을 추가/삭제/변경했다면 **같은 작업 안에서** `Scripts/Editor/CSV*.cs`를 함께 수정한다.
>
> - `CSVExportTab.cs` — `BuildRows_XXX()` 컬럼/필드
> - `CSVImportTab.cs` — `Diff_XXX()` 헤더, `Apply_XXX()` 컬럼 수, `Validate` 규칙 배열, 신규 enum이면 `IsValidEnum`
> - `CSVToolWindow.cs` — 새 SO 타입이면 경로 필드, `TypeNames` 배열, `InjectPaths`
> - 보조: `CSVApplierTab.cs`, `CSVDiffCore.cs`
>
> 안 고치면 **빌드는 통과해도 컬럼 인덱스가 밀려 데이터가 무음으로 깨진다.**

## 런타임 인스턴스

위치: `Scripts/Data/RuntimeInstance/`

| 클래스 | 주요 필드 | 주요 메서드 |
|---|---|---|
| `WeaponInstance` | `weaponData`, `instanceID`(GUID), `currentGrade`, `enforceLevel`, `rerollCount`, `effects`, `isRented` | `Enforce()`, `Evolve()`, `Reroll(lockedIndices)`, `GenerateEffects(grade)` |
| `AdventurerInstance` | `adventurerData`, STR/DEX/INT/LUK, `affection`, `rentedWeapon`, `isAlive`, `isAdventuring` | `GetStatScore(WeaponType)`, `GetBestWeaponType()`, `RentWeapon(weapon)` |
| `AdventureInstance` | `adventurer`, `weapon`, `dungeon`, `startTime`, `isCompleted`, `isSuccess`, `isDeath`, `accumulatedGold`, `accumulatedMaterials`, `progress` | — |
| `WeaponEffect` | `effectData`(SO 참조), `effectDataID`(저장용), `baseValue`, `currentValue` | — |
| `MaterialInstance` | `materialData`(SO 참조), `materialDataID`(저장용), `quantity` | `Add()` |
| `ActiveItemInstance` | `activeItemData`, `instanceID`, `targetAdventurerID`, `activedDay`, `expiryDay` | `Use(day, advID)`, `IsExpired(day)` |

그 밖에 `WeeklyQuestInstance`, `VisitorNPC` 등이 있다.

> SO 참조를 어떻게 들고 어떻게 굽는지는 [[데이터_접근_원칙]]을 반드시 따른다.

## Config 시스템

위치: `Scripts/Data/Config/` + 에셋 `Assets/_Projects/Data/Config/`

**밸런싱 수치는 전부 Config SO에서 관리하고 `ConfigManager.Instance`로 접근한다.**

| Config | 주요 내용 |
|---|---|
| `VisitorConfig` | 방문자 스폰 간격, 대기 시간 |
| `WeaponConfig` | 효과 확률, 레벨당 효과 수 |
| `AdventureConfig` | 성공률 계산, 이벤트 확률, 재료 드롭 가중치 |
| `BlacksmithConfig` | 강화/진화 비용, 성공률 |
| `ReputationConfig` | 평판 임계값, 스폰 간격 |
| `TimeConfig` | 시간 진행 설정 |
| `InventoryConfig` | 인벤토리 한도 |
| `QuestBoardConfig` | 퀘스트 보드 설정 |
| `WeaponShopConfig` | 무기점 설정 |
| `PriceTierConfig` | 주차 계단 가격 체계 |
| `EndlessQuestConfig` | 41주차 이후 엔드리스 구간 |
| `AdventureInfoConfig` | 성공률 표시·기분 색상 |

> [!warning] 예외 — `ConfigManager`를 거치지 않는 Config
> `LegacyConfig`와 `NicknameConfig`는 각 매니저(`LegacyManager` / `NicknameManager`)가 직접 보유한다.

> [!tip] 밸런싱 수치를 바꿨다면
> 반드시 [[Balance]]에 변경 건별 기록을 남긴다 — 근거(왜) / 대상 시스템(무엇을) / 수정 전후(어떻게).
