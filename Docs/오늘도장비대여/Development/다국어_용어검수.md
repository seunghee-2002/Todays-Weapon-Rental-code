# 다국어_용어검수

> [!abstract] 한 줄 요약
> 번역이 **끝난 뒤** 돌린 일관성 검수. 2,108키 x 4로케일 = 8,432 문자열 전수. **기계 판정 6종은 전부 통과**했고(자리표시자·태그·Smart String·빈 값 이상 0건), 남은 것은 **용어 통일** 문제였다 — 확인 35건 / 기각 23건.
> **2026-08-03 전부 수정 완료** — 값 106개 변경. 아래 2절 표의 「현재」는 수정 **전** 상태이고, 「권장」이 지금 들어가 있는 값이다.
> 도구는 [[다국어_감사대장]] ⑨·⑫, 진행 이력은 [[다국어_진행상황]].

> [!success] 수정 결과
> | 검사 | 수정 전 | 수정 후 |
> |---|---|---|
> | B 같은 ko가 다르게 번역됨 | 84행 (42그룹) | **42행 (26그룹)** — 남은 것은 전부 **의도된 분리** |
> | D 길이 이상치 | 8 | 7 |
> | A·E·F (기계 판정) | 0 | **0** |
>
> `Verify-Localization.ps1` exit 0 · 검사 ⑦(번역 로케일에 남은 한국어) 0건 유지.
>
> **남은 26그룹은 고치면 안 되는 것들이다** — 한국어 한 단어가 두 개념을 덮는 경우다.
> `강화` = Enhance(무기) / Upgrade(유산) · `고급` = Uncommon(등급) / Premium(테스트) · `골드` = 黄金(평판 티어) / 金币(화폐) · `일반` = Common(등급) / Regular(모험가) · `확정` = Confirm(버튼) / Guaranteed(확률) · `수리검` = クナイ(아이템) / 手裏剣(무기 타입, **이번에 의도적으로 분리**).

## 1. 검수·수정 방법

```powershell
python Tools\Localization\Audit-Consistency.py            # 기계 판정 6종 -> out/qa/*.csv
python Tools\Localization\Set-LocValues.py <edits.csv>    # 기존 항목 값 교체 (--dry-run 지원)
```

> [!important] 수정은 **부분 문자열 치환**으로 했다 — 문장을 다시 타이핑하지 않는다
> 106건을 손으로 옮겨 적으면 오타가 섞이고, 그 오타는 폴백 때문에 화면에서 구별되지 않는다. 그래서 「이 키의 현재 값에서 `重随`를 `重赋`로」 형태의 규칙만 적고, **규칙이 해당 키에서 정확히 매칭되지 않으면 아무것도 쓰지 않고 실패**하게 했다. 규칙 90여 개가 전부 한 번에 매칭됐다.
>
> `Set-LocValues.py`는 `Add-LocEntries`(생성)·`Remove-LocEntries`(삭제)에 없던 **세 번째 동사**다. CRLF와 BOM 없음을 보존하므로 3줄 수정이 4,000줄 diff가 되지 않는다.

기계가 판정할 수 있는 것과 없는 것을 **먼저 갈랐다.** 8,432 문자열을 사람이 훑는 방식은 실패하기 때문이다.

| 층 | 방법 | 결과 |
|---|---|---|
| 기계 판정 | 전수 대조 (자리표시자·태그·이스케이프·중괄호·빈 값·Smart 플래그) | **문제 0건** |
| 기계 증거 수집 | 같은 한국어의 번역 갈림 / 같은 영어의 한국어 갈림 / 길이 이상치 | 42 + 27 + 8건 |
| 사람 판단 | 5개 관점(고유명사·시스템 용어·UI 문구·화자 문체·데이터 정확도)으로 검토 후 **각 건을 반증 시도** | 확인 35 / 기각 23 |

> [!note] 기각 23건도 의미가 있다
> 「검토했고 문제 아님」이 기록으로 남는다. 예: `평범한` -> zh `普通的`(제안된 `平凡的`은 중국어에서 사람·추상에만 쓰여 오히려 어색), `마녀 레이븐`/`레이븐` 분리(별명 풀과 이름 풀은 다른 층), `라그나르`/`라그나` 음차(둘 다 표준 표기).

## 4. 전체 번역 품질 평가

| 항목 | 평가 |
|---|---|
| **기계적 무결성** | **문제 없음.** 자리표시자·리치텍스트·Smart String·이스케이프·빈 값 전부 0건. 8,432 문자열에서 이 수치는 드물다 |
| **의미 정확도** | **높음.** 뜻이 뒤집힌 사례 0건. 물건이 바뀐 것 2건(`철퇴`, `참나무 활`)뿐 |
| **용어 일관성** | **여기가 약점.** 확인된 35건 중 22건이 용어 갈림. 원인이 분명하다 — 배치를 **화면 단위·자산 단위로 나눠 진행**했기 때문에, 같은 개념이 다른 배치에서 다른 단어를 얻었다 |
| **고유명사** | **양호.** 이름 208 x 아이템 189 전수 대조에서 충돌 **1건**. ko/en/ja는 0건 |
| **문체** | 화자별 개성은 대체로 유지됨. zh가 상대적으로 약하다(직역체 3건) |
| **레이아웃 위험** | 길이 이상치 8건 전부 정상적으로 긴 영어 명사. 별도 오버플로 작업은 이미 진행됨 |

**언어별**: ja가 가장 안정적, en은 표기 통일(미국/영국)만 남음, **zh에 지적이 집중**(35건 중 16건) — 특히 일본어식 한자어를 그대로 쓴 사례(`素材`, `中介`)와 직역체.

## 5. 공식 용어집

## 6. 번역 스타일 가이드

| 항목 | 규칙 |
|---|---|
| **영어 철자** | **미국식**. `armor`(not armour) · `judgment` · `license`. enum 라벨이 이미 미국식이고 노출 빈도가 높다 |
| **영어 버튼** | 명령형 동사 단독 (`Confirm` / `Cancel` / `Close`). 대문자는 Title Case |
| **일본어 시스템 메시지** | 평서 정중체 `〜てください`. 존경어(`ご〜ください`)는 섞지 않는다 |
| **일본어 고유명사** | 나무·재료는 **일본어 단어**로(`カシ`·`トネリコ`), 영어 음차 금지 — `オーク`처럼 종족으로 오독될 수 있다 |
| **중국어 확인 팝업** | 되돌릴 수 없는 동작만 `确定要…吗？`, 나머지는 `要…吗？` |
| **중국어 어휘** | 일본어식 한자어를 그대로 쓰지 않는다 (`素材`->`材料`, `中介`(동사)->`介绍`) |
| **중국어 직역 금지** | `见到你很好` 류. 한국어 관용구는 중국어 관용구로 바꾼다 |
| **화자 문체** | 점술가=부드러운 존대 / 전령=밝은 설명체 / 상인=예스러운 노년 / 대장장이 8인=각자 성격 유지. **수정구 서사만 3인칭 문어체**(의도된 차이) |
| **한국어 원문** | 손대지 않는다. ko가 소스다 |

## 7. 추가 검토가 필요한 것

- **아이템 이름 vs 타입 라벨 이중 관리** — `ActiveItem_*_Name`(SO)과 `ActiveItemType_*`(enum)이 **같은 물건을 각각 번역**한다(`신속의 신발`·`해체용 단검`·`작은 인형`·`탈출용 로프`·`명예의 두루마리`). 지금은 값을 맞추는 것으로 해결하지만, 구조적으로는 **한쪽이 다른 쪽을 참조**하는 게 맞다
- **폴백 문구가 SO 대사와 중복** — `WeaponShop_GreetingFallback`·`Seer_EasterEggFollowUp`이 SO의 첫 줄과 **같은 한국어**인데 번역이 다르다. 폴백을 다른 문장으로 바꾸거나 SO를 참조하게 하는 편이 낫다
- **`WeaponType_Axe`의 한국어가 `망치`** — enum 이름과 내용이 어긋나 있다(번역은 `Hammer`로 일관). 번역 문제는 아니지만 혼동 소지
- **`고급 석궁`이 Epic 등급** — 이름의 `고급`(=Uncommon 등급명)과 실제 등급이 다르다. **한국어 원문 자체의 문제**라 번역으로 풀 수 없다
- **금칙어 ja/zh** — 닉네임 허용 문자를 넓혔으므로 필요 (사용자가 직접 처리 예정)
