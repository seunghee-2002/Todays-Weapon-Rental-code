## RuntimeInstance <-> 정적 SO

- RuntimeInstance는 정적 SO를 **참조로 직접 보유**한다.
	- 예: `WeaponInstance.weaponData : WeaponData`, `MaterialInstance.materialData : MaterialData`, `WeaponEffect.effectData : WeaponEffectData`
- **저장 시점에만** SaveData에서 **ID 문자열로 굽는다.**
	- 예: `WeaponInstanceSaveData.weaponDataID : string`
- RuntimeInstance는 **`DataManager`를 모른다.** 자기 정적 데이터는 SO 참조로 직접 접근한다 (`instance.weaponData.weaponName`).
- 같은 의미의 필드를 RuntimeInstance에 **중복으로 들지 않는다.** SO에 이미 있는 정적 필드는 참조 경유로 접근한다.

```csharp
// ✅ 좋음
string name = weaponInstance.weaponData.weaponName;

// ❌ 나쁨 - 중복 필드
public class WeaponInstance { public string weaponName; }

// ❌ 나쁨 - RuntimeInstance가 DataManager를 안다
public class WeaponInstance { void Foo() => DataManager.Instance.GetWeapon(id); }
```

## SaveData -> RuntimeInstance 변환

> [!important] 변환은 **도메인 매니저의 `Initialize(GameData)`**에서 수행한다

- 예: `InventoryManager.Initialize(gameData)`가 `WeaponInstanceSaveData -> WeaponInstance`를 reify한다.
- 매니저가 `DataManager.Get*(id)`로 SO를 가져와 RuntimeInstance의 **rich 생성자**에 주입한다.
- RuntimeInstance에 **SaveData 생성자**(`new WeaponInstance(WeaponInstanceSaveData)` 형태)는 **두지 않는다.** rich 생성자(`new WeaponInstance(WeaponData, ...)`)만 유지한다.
- **신규 생성 시점의 데이터 의존도 매니저가 주입한다.**
	- 예: `VisitorManager`가 모험가 스폰 시 `defaultWeapon`을 만들어 `AdventurerInstance`에 주입한다. `AdventurerInstance.CreateDefaultWeapon()`은 `VisitorManager.Spawn`으로 이동했다.

## `DataManager`의 책임 (4가지)

`DataManager`는 **정적 SO 카탈로그**로 응축된다. 아래 4가지만 책임진다.

| # | 책임 | 예시 |
|---|---|---|
| 1 | **ID -> SO lookup** | `GetWeapon(id)`, `GetAdventurer(id)` |
| 2 | **카탈로그 필터** | `GetWeaponsByType(type)`, `GetDungeonsByGrade(grade)`, `GetWeaponEffectsByGrade(grade)` |
| 3 | **역방향 인덱스** | `GetDropSourcesForMaterial(id)`, `GetSpecialDropSourceForMaterial(id)` — 초기화 시 `Dictionary<materialID, List<DungeonData>>`를 미리 구축 |
| 4 | **UI 표시용 효과 메타 조회** | `GetEffectGroups()`, `GetEffectByTypeAndGrade(...)` (WeaponShop 부가효과 목록 표시) |

> [!note] 새 SO 타입을 추가할 때
> `DataManager`의 로드 로직을 갱신해야 하는지 반드시 확인한다. -> [[데이터_구조]]

## 도메인 헬퍼 매핑

**ID 컨벤션·게임 룰을 코드로 들고 있는**(= 단순 카탈로그 필드 lookup이 아닌) 헬퍼는 **도메인 매니저**에 둔다.

| 헬퍼 | 위치 | 도메인 의미 |
|---|---|---|
| `GetEnforceMaterialByGrade(grade)` | `BlacksmithManager` | `Grade -> "MAT_ENF_xxx"` ID 컨벤션을 강화 시스템이 보유 |
| Effect evolve 업그레이드 계산 (`ApplyEvolveUpgrades` 등) | `BlacksmithManager` | 진화 시 효과 등급 상승 룰 |

반대로 **단순히 카탈로그 필드 값으로 SO를 조회/필터하는 메서드**는 **카탈로그 필터**로 보고 `DataManager`에 둔다.

- 기준 필드: `weaponType`, `weekNumber`, `unlockedDay`, `morningEventType`, `eventType` 등
- 예: `GetWeaponsByType`, `GetUnlockedWeaponRecipes`, `GetQuestByWeek`, `GetDungeonEventByType`, `GetDefaultWeapon`

> [!tip] 판정 기준
> "이 메서드가 **게임 규칙**을 알고 있는가, 아니면 **필드 값만** 보고 있는가?"
> 규칙을 알면 도메인 매니저, 필드만 보면 `DataManager`.

## View의 데이터 접근

| 접근 | 허용 | 비고 |
|---|:---:|---|
| View -> `DataManager` (카탈로그, 읽기 전용) | ✅ | 직접 호출 가능 |
| View -> `AnalyticsManager` | ✅ | 관측 전용, 게임 상태 미변경 -> [[Analytics]] |
| View -> 도메인 매니저 | ❌ | **반드시 Controller 경유** |

> [!important] 표시용 정적 데이터는 SO 참조로 접근한다
> 이름·아이콘·등급 등은 RuntimeInstance의 SO 참조로 직접 읽는다.
> **`DataManager.Get*(id)`로 SO를 다시 가져오지 않는다.**
>
> ```csharp
> // ✅ 좋음
> icon.sprite = weaponInstance.weaponData.icon;
>
> // ❌ 나쁨 - 이미 참조가 있는데 다시 조회
> icon.sprite = DataManager.Instance.GetWeapon(weaponInstance.weaponDataID).icon;
> ```
