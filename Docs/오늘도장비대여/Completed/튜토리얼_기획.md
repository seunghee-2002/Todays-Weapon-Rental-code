# 튜토리얼 기획 (구현 완료)

> 1회차 **1일차 하루** 동안 게임의 전 기능을 실제 플레이 순서대로 체험시키는 12단계 튜토리얼.
> 플레이어는 **초보 길드 매니저**로 부임하고, 길드 본부에서 파견된 전용 안내 캐릭터 **"길드 전령"**(존댓말)이 대화창으로 각 단계를 하나하나 도와준다.
>
> **상태: 1~12단계 전 구간 구현 완료.** 남은 것은 에디터 실기 검수뿐([6절](#6-남은-검수)).
>
> | 목적 | 문서 |
> |---|---|
> | **현행 사양 + 작업 규칙**(시작·완료·스킵·복원·입력 차단·새 단계 추가 시 체크리스트) | [[튜토리얼|Systems/튜토리얼.md]] |
> | **설계 기록**(이 문서) | 컨셉·단계별 흐름·대사 전문·고정 데이터·피로도 |
>
> 문서 구성 — ① 개요 ② 12단계 요약 ③ 단계별 상세(흐름 + 대사 전문) ④ 피로도 ⑤ 고정 데이터 ⑥ 남은 검수

---

## 1. 개요

### 컨셉·목적

- 플레이어는 **새로 부임한 초보 길드 매니저**. 모험가에게 무기를 빌려주고 **수수료**를 받아 길드를 꾸린다.
- 첫 플레이어가 1일차 안에 **핵심 루프(무기 확보 → 강화 → 대여 → 모험 → 수수료)** 와 주변 시스템(아침 이벤트·의뢰판·퀘스트)을 전부 한 번씩 손으로 해보게 한다. 통찰은 상세 설명 없이 "안목" 정도로만 언급한다.
- 성공 체험과 **자연스럽게 유도된 실패 체험**을 모두 겪게 해 "왜 정보를 모으고 조합을 맞춰야 하는지"를 몸으로 익히게 한다. 실패는 "일부러"라고 밝히지 않고, **길드 전령도 함께 속는 서사**로 유도한다.

### 안내 캐릭터 — 길드 전령

| 항목 | 내용 |
|---|---|
| 컨셉 | 길드 본부에서 **초보 매니저의 부임을 지원**하러 파견된 튜토리얼 전용 안내역 |
| 말투 | 존댓말 ("~해요 / ~해보세요"), 밝고 상냥한 톤. 플레이어 호칭은 **"매니저님"** |
| 서사 | 1~7단계는 본부 물자로 비용을 보전해 주고, 8단계부터 지원이 끊기며 실패 체험과 맞물린다 |
| 구분 | 아침 이벤트 NPC "길드 사절단", 9단계 결과 보고 NPC **"보고 전령"**과는 **모두 별개 캐릭터**. 이름이 겹치지 않게 안내역은 항상 **"길드 전령"**, 저녁 6시 결과 보고 NPC는 항상 **"보고 전령"**으로만 적는다 |
| 표시 | `TutorialDialogueView` — 초상 + 텍스트 1~2줄 + 화면 탭으로 다음. 조작을 시킬 때는 대상 UI를 하이라이트 |
| 표정 | 초상 5종(`HeraldPortrait`) — **기본**(Default) / **당황**(Embarrassed) / **인사**(Hello) / **수면걸기**(Magic) / **의문**(Question). 대사 묶음(`TutorialLineKey`)별로 `TutorialConfig.asset`에서 지정 |

### 진행 원칙

- 대화는 **한 박스 2줄 이내**, 조작 1회당 대사 1박스를 넘기지 않는다.
- "말로 설명"보다 **직접 조작**.
- **위치 지시어를 쓰지 않는다** ("화면 아래", "왼쪽 버튼" 등 금지) — 대상 버튼을 하이라이트로 지목한다.
- **개발 용어를 쓰지 않는다** — "탭" 대신 "단계"(준비 화면의 진행 스텝) 등 게임 안 언어로 부른다.
- **등장 요소는 전부 고정한다** — 무기·모험가·던전·시뮬레이션 가정 타입·판정 결과까지 사전 확정([5절](#5-튜토리얼-고정-데이터)). 랜덤에 기대는 연출 없음.
- 1~7단계의 비용(부적 재료, 강화·점술·수색 골드)은 **길드 전령(본부)이 증정/보전**한다. 8단계부터 지원 종료. 단, **테스트의 게임 내 시간 비용은 예외 없이 정상 차감**한다.
- 8단계에서 출발하는 실패 체험 모험 외에는 **성공을 보장**한다(강화·종합 테스트 성공 보장 포함).

## 2. 12단계 요약

| # | 단계 | `TutorialStep` | 시점 | 배우는 것 | 남기는 게임 상태 |
|---|---|---|---|---|---|
| 1 | 무기상점 | `WeaponShop` | 1일차 아침 | 무료 무기 **4종 전부** 구매 | 무기 4종 획득 |
| 2 | 대장장이 | `Blacksmith` | 아침 | 재료 증정 → 부적 **제작** → 조잡한 단검 **강화·진화·재부여** | 부적 1개 + 강화/진화/재부여된 단검 |
| 3 | 아침 이벤트 | `MorningEvent` | 아침 | 길드 사절단 상호작용(선물 고정) → **아침 스킵**으로 낮 진입 | 사절단 선물, 낮(09:00) 진입 |
| 4 | 의뢰판 | `QuestBoard` | 낮 진입 | 던전 매물(A/B/C) 확인·확정 → **2배 던전** 개념 → 던전 A **수색꾼 파견** | 의뢰판 확정, 던전 A 수색 |
| 5 | 모험 준비 진입 | `PrepEnter` | 낮 | 첫 손님(모험가1) 등장 → 준비 화면 **세 단계 구조** 소개 | (스폰 전용) |
| 6 | 모험 보내기 | `SendAdventure` | 낮 | 무기 조사·종합 테스트 → 검 대여 → 부적 선물 → 던전 A/B/C **비교** → A 선택 → 모험 정보·**점술** → **출발** | 첫 모험 시작(모험가1 → 던전 A) |
| 7 | 가방 확인 | `Inventory` | 낮 | 인벤토리 열기 → **대여중** 토글 → 대여 무기 확인 | (조회 전용) |
| 8 | 두 번째 손님 | `SecondGuest` | 낮 | 모험가2 등장 → 무기 조사(검은 대여 중) → **활 대여** → 던전 B **경갑 시뮬레이션** → 출발 | 둘째 모험 시작(모험가2 → 던전 B) |
| 9 | 모험 결과 | `AdventureResult` | 낮~저녁 | 진행 관찰 → **수면 마법**(두 모험 완료·18:00) → **보고 전령의 보고**로 성공(A) 리플레이·**수수료**·재료 **매입** → 실패(B) 리플레이·**무기 파괴** | 두 모험 완료·확정(A 보상·검 반납 / B 활 파괴) |
| 10 | 퀘스트 소개 | `Quest` | 저녁 | 퀘스트 화면 → 요구/진행/보상 + **벌금·게임오버** 경고 | (조회 전용) |
| 11 | 나머지 UI | `RemainingUI` | 저녁 | 상단바 순차 하이라이트(날짜·시간·골드·평판·배속·유산) | (조회 전용) |
| 12 | 마무리 | `Finish` | 저녁 | 안목(통찰) 언급 → 작별 → **20:00 스킵**(자막 연출) → 정식 완주 | 시간 정상화, 영구 완주 플래그 |

- 5단계는 끝나면 같은 모험가로 **6단계로 끊김 없이 이어진다**(독립 진입점이 없어 복원 시 5단계로 remap).
- 6·9단계는 규모가 커서 하위 단계로 쪼개 구현했다 — 6-A(조사·테스트) / 6-B(지원·대여·선물) / 6-C(던전 비교·선택) / 6-D(모험 정보·점술) / 6-E(출발), 9-A(관찰·수면) / 9-B(성공 보고) / 9-C(실패 보고).

## 3. 단계별 상세

표기 규칙 — `길드 전령:` 대사는 대화 박스 1개. `[표정]`은 그 묶음의 초상. `(플레이어: …)`는 강제 조작(해당 UI만 하이라이트, 나머지 입력 차단). `(연출: …)`은 자동 진행. 대사 앞의 숫자는 `TutorialLineKey` 값이다.

> 대사 원문은 `TutorialConfig.asset`이 소스다. 문구를 고칠 때는 이 문서가 아니라 **에셋을 수정**한다(아래는 현재 에셋 내용을 옮긴 것).

### 3.1 무기상점 (1단계)

**트리거** — 1일차 아침 시작 직후(`VisitorManager`의 아침 NPC 스폰 시). 시간 강제 정지, 무료 무기 상점 NPC 등장.

**흐름** — 길드 전령 인트로 → 무기 상인 클릭 → 무기 **4종 전부** 수령. 한 종류라도 빠진 채 상점을 닫으려 하면 "네 자루를 모두 구매해야 합니다!" 경고가 뜬다(6·8단계에서 서로 다른 타입 무기가 필요하다).

**대사**
> **100** [인사]: "안녕하세요! 길드 본부에서 왔어요. 새 매니저님이 부임하신다는 소식을 듣고 바로 달려왔답니다!"
> "매니저님은 모험가들에게 모험을 중개하고, 무기를 빌려주며 수수료를 받아 길드를 운영하게 돼요. 모험가들이 좋은 성과를 낼수록 매니저님의 평판도 높아진답니다!"
> "그런데... 지금은 빌려줄 무기가 하나도 없네요. 마침 무기 상인이 와 있으니 먼저 무기를 구매해 볼까요?"
>
> (플레이어: 무기 상인 클릭 → 무기상점 오픈)
>
> **101**: "부임 기념으로 이번 매물은 전부 무료예요! 검, 단검, 지팡이, 활은 각각 쓰임새가 다르니 네 자루 모두 챙겨두세요!"
>
> (플레이어: 무기 4종 구매)
>
> **102**: "좋아요! 필요한 무기를 충분히 구매해 두세요!"

### 3.2 대장장이 (2단계)

**트리거** — 1단계 완료 직후, 대장장이 NPC(`blacksmithIntroNPCID` 고정) 등장. 길드 전령이 **부적 레시피 재료 + Common 진화 재료 일체**(`GetEvolveMaterials(Grade.Common)` = MAT_ENF_001 ×5 + MAT_ENF_002 ×3)를 증정하고, 강화·진화·재부여 골드는 `ApplyCostReduction` 가드로 0원.

**흐름** — 재료 증정 → 대장장이 클릭 → ① 제작: 행운의 부적 → ② 강화: **조잡한 단검**(성공 강제) → ③ 진화(Uncommon 등급업) → ④ 재부여. **강화석 선택 단계는 건너뛴다.**
※ Common 무기는 이펙트가 1개라 **강화 1회**로 진화 조건이 채워진다. 강화 대상을 **모험에 내보내지 않는 단검**으로 고정했으므로, 진화·재부여로 옵션이 어떻게 바뀌어도 6·8단계 모험(A/B)에 영향이 없다.

**대사**

>
> (플레이어: 대장장이 클릭 → 대장간 오픈)

> **201**: "**제작**에 필요한 재료를 선물로 드렸어요! **행운의 부적**을 만들어 보세요. 모험 성공 확률을 높여주는 유용한 소모품이랍니다."
>
> (플레이어: 제작 → 행운의 부적)
>
> **202**: "이번에는 **강화**예요. 아까 받은 단검을 선택해서 강화해 보세요. 이번 비용은 길드 본부에서 지원해 드릴게요!"
>
> (플레이어: 조잡한 단검 선택 → 강화 — 성공 보장)

### 3.3 아침 이벤트 (3단계)

**트리거** — 2단계 완료 직후. 1일차 아침 이벤트는 **길드 사절단으로 고정**, 판정도 **선물 수령으로 고정**(`ExecuteGuildEnvoy`의 `isGift=true` 강제, 강제 납부 없음).

**흐름** — 아침 손님 개념 소개 → 사절단 클릭 → 선물 수령 → 평판에 따라 대접이 달라진다는 여운 → **기존 아침 스킵 버튼**을 하이라이트해 낮으로 진입. 아침 스킵은 평소 잠겨 있고 이 시점(`IsMorningSkipAllowed`)에만 열린다.

**대사**
> **300** [인사]: "아침에는 가끔 **특별한 손님**이 길드를 찾아와요. 오늘은 누가 찾아왔을까요?"
> "짜잔! 오늘은 길드 사절단이 찾아왔어요. 어서 가서 만나보세요!"
>
> (플레이어: 사절단 클릭 → 선물 수령)
>
> **301**: "부임을 축하드리는 선물이에요! 앞으로도 사절단은 종종 찾아올 거예요. 길드의 평판이 높으면 **선물**을 주지만, **평판**이 낮으면 **벌금**을 부과할 수도 있으니 신경 써 주세요."
> "이것으로 아침 일과는 끝이에요! 이제 영업을 시작해 모험가들을 맞이해 볼까요?"
>
> (플레이어: 아침 스킵 버튼 클릭 → 낮 진입)

### 3.4 의뢰판 (4단계)

**트리거** — 낮 진입(09:00) 시 의뢰판 자동 오픈. 매물은 `QuestBoardManager` 내부 가드로 **튜토리얼 고정 풀(A/B/C)** 이 된다 — Bronze 규정 `bronzeSelectCount:3`과 풀 크기가 같아 잘못 고를 방법이 없다. 새로고침도 막힌다. 수색 비용은 `CalcScoutCost` 가드로 0원.

## 4. 피로도 설계

| 지표 | 값 |
|---|---|
| 대화 박스 총량 | **약 70박스** (박스당 2줄 이내) + 보고 전령 대사 |
| 강제 조작 총량 | **약 40회** |
| 대기 연출 | 모험 진행 관찰 1회(9-A, 3초), 수면 마법 암전 1회(9-A), 리플레이 2회(9-B/9-C, **스킵 불가**), 마무리 자막 1회(12) |
| 예상 소요 시간 | **약 10~13분** |

### 부하 곡선

- 고부하 구간은 **2단계(대장간 4연속 조작)** 와 **6단계(준비~출발, 대사 15박스/조작 9회)** 두 곳. 각각 직후에 저부하 단계(3단계 선물 휴식, 7단계 관찰)를 배치해 회복 구간을 확보했다.
- 8단계는 6단계에서 배운 조작의 복습이라 체감 부하가 낮고, 9단계는 결과 관람 중심이라 **성공 보상 → 실패 교훈**의 감정 낙차에 집중한다. 파괴되는 무기는 무료로 받은 활이라 손실감이 낮다.
- 10~12단계(저녁)는 조작이 거의 없는 "정리 강의" 구간 — 지루해지지 않도록 하이라이트 템포를 빠르게 유지한다.

### 페이스 원칙

1. 조작 1회당 대사 1박스 초과 금지.
2. 결과 연출(강화·점술 등)은 터치 스킵 허용. 단, 9단계 리플레이는 스킵 버튼을 숨겨 끝까지 시청시킨다.
3. 1~7단계 비용은 전부 증정/보전 — "돈이 모자라서 막히는" 상황을 원천 차단. 8단계부터 지원 종료(서사와 일치). 테스트의 시간 비용만은 처음부터 정상 차감.

## 6. 남은 검수

> 코드·데이터·인스펙터 작업은 완료. 아래는 **에디터 실기 테스트**라 사용자가 직접 실행해야 한다.

- [ ] **전 구간 통과(정상 순차)** — 1일차 아침 신규 시작 → 1~12단계를 유도대로 끝까지. 단계 전환·하이라이트 정렬·대사 박스 수 확인. 12단계 20:00 스킵 후 시간 재개, 재접속 시 튜토리얼 재생 안 됨(`tutorialStep=0`).
- [ ] **중도 강제종료 복원** — 각 단계 진입 직후 강제 종료 → 재실행 → 해당 단계 **진입 상태부터** 깨끗이 재생되는지(중복 스폰·유령 패널 없음). 5→6은 5단계로 remap, 7·8은 첫 모험 진행 중, 9는 두 모험 진행 중 상태에서 재생되며 이중 보상·이중 파괴가 없어야 한다.
- [ ] **완주 계정 스킵** — 2·4·6·8·9 등 여러 단계에서 스킵 → 매번 최종 상태 동일(모험 2개 완료·확정, A 보상·검 반납, **활 파괴로 없음**, 단검 1회 강화+진화+재부여, 던전 A 수색 완료, 무기 검/단검/지팡이). 정상 완주 결과와 대조.
- [ ] **"매입" vs "구매" 라벨 통일** — 대사 904는 "매입", `MaterialPurchasePopup` 코드는 "구매". 프리팹 버튼 라벨을 확인해 한쪽으로 맞춘다.
- [ ] **[경미] catch-up 이론적 구멍** — 강화 대상 단검이 30회 재굴림에도 `CanEnforce=false`로 지급되면 catch-up의 강화 체인이 통째로 스킵된다(확률 극히 낮고 경고 로그 있음).
