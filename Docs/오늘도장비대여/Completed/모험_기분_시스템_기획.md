# 모험 기분(Mood) 시스템 기획

## 개요

모험 결과의 결정론을 약화시키고 동일 조건의 반복 플레이에 변동을 주기 위해 **3중 구조**의 성공률 체계를 도입한다.

```
[1] 기본 성공률   = 무기 타입 + 모험가 스탯 + 던전 방어구 타입
[2] 이벤트 배율   = 기본 성공률 × eventData.difficultyMultiplier (기존 유지)
[3] 기분 변동     = 모험 시작 시 결정된 Mood에 따른 이벤트별 곱셈 변동 (신규)
```

기분은 **모험 출발 시점에 단 한 번 결정**되고, 그 모험 동안 적용되는 변동의 **분포**(범위·균등/이중모드)를 정한다. 매 전투/함정 이벤트마다 그 분포에서 새로 한 번 굴려 일회성 보정을 부여한다.

**유저에게는 노출하지 않는 내부 랜덤 로직이다.** UI/결과창에 표시하지 않으며, 디버그 로그로만 추적 가능하게 둔다.

---

## Mood enum

```csharp
public enum AdventurerMood
{
    Normal,         // 평범     — 기본 3종
    Moody,          // 기분파   — 기본 3종
    Depressed,      // 우울     — 기본 3종
    Overconfident,  // 자기과신 — 특수 (점수 낮을 때 출현)
    Confident,      // 자신감   — 특수 (점수 높을 때 출현)
}
```

기본 3종은 항상 후보, 특수 2종은 매칭 점수에 따라 등장 확률이 변동.

## 기분별 변동 분포

이벤트 단위 보정은 **곱셈**으로 적용. `successRate *= moodMultiplier` 형태.

| Mood | multiplier 분포 | 평균 배율 | 비고 |
|------|----------------|----------|------|
| Normal        | Uniform(0.70, 1.30)                              | 1.00 | 진폭 큼, 균등 |
| Moody         | Uniform(0.70, 0.85) ∪ Uniform(1.15, 1.30) (각 50%) | 1.00 | 양극화 (50/50 고정) |
| Depressed     | Uniform(0.90, 1.10)                              | 1.00 | 진폭 작음, 안정 |
| Overconfident | Uniform(0.75, 1.10)                              | 0.925 | 하향 편향 |
| Confident     | Uniform(0.90, 1.25)                              | 1.075 | 상향 편향 |

> 모든 값은 `AdventureConfig`로 빼낸다. 위 값은 초기 권장값이며 플레이테스트 후 조정.

### 곱연산의 비대칭성 — 인지해둘 것

곱연산이라 **양 끝에서 효과가 비대칭**으로 나타난다:

| 기본 성공률 | ×0.70 (Normal 최저) | ×1.30 (Normal 최고) |
|-----------|--------------------|--------------------|
| 30% | 21% (-9%p)  | 39% (+9%p)  |
| 50% | 35% (-15%p) | 65% (+15%p) |
| 70% | 49% (-21%p) | 91% (+21%p) |
| 90% | 63% (-27%p) | 117% → clamp 95% (+5%p) |

- 낮은 성공률에서는 변동 폭이 작다 → "이미 어려운 모험"은 큰 사고가 잘 안 남.
- 높은 성공률에서는 음수 방향만 강하게 작동 → "안정 빌드"가 갑자기 망할 위험은 남고, 이미 확실한 성공률에 보너스는 거의 없음.
- 곱연산의 자연스러운 특성으로, 합연산 대비 **상위 빌드의 안정성을 살짝 깎는** 방향으로 작동한다.

## 기분 배정 로직

### 1) 매칭 점수 정규화

기존 `GetEffectStatScore(adventurer, weapon)` (모험가 스탯 + 무기 효과 적용 후 점수)을 던전과 무관한 **고정 임계값**으로 정규화. 같은 모험가-무기 조합이면 어떤 던전에 가도 같은 매칭 점수.

```
matchScore = Clamp01(GetEffectStatScore(adventurer, weapon) / Config.moodScoreThreshold)
// 0 = 점수 최악, 1 = 점수 최고
```

> 임계값은 별도 Config 값 (`moodScoreThreshold`). 던전의 `baseStatThreshold`나 무기-방어구 상성, 호감도, 특성 등 외부 요인은 일절 들어가지 않는다 — 기분은 "이 모험가가 이 무기를 들었을 때의 매칭 품질"만 본다.
>
> 초기값은 기존 `baseStatThreshold`와 동일한 **200** 권장. 플레이테스트로 조정.

### 2) 확률표 (구간별 선형 보간)

| matchScore | Overconfident | 기본 3종 합 (Normal+Moody+Depressed) | Confident |
|-----------|---------------|------------------------------------|-----------|
| 0.0 (최악) | **35%** | 60% (각 20%) | 5%  |
| 0.5 (중간) | 10%     | 80% (각 약 26.7%) | 10% |
| 1.0 (최고) | 5%      | 60% (각 20%) | **35%** |

특수 2종은 점수 양 끝에서 솟고 중간에서 꺼진다 → 기본 3종이 중간에서 가장 두꺼워지는 종 모양 분포.

#### 보간 공식 (piecewise linear)

```csharp
float pOver = matchScore <= 0.5f
    ? Mathf.Lerp(0.35f, 0.10f, matchScore * 2f)
    : Mathf.Lerp(0.10f, 0.05f, (matchScore - 0.5f) * 2f);

float pConf = matchScore <= 0.5f
    ? Mathf.Lerp(0.05f, 0.10f, matchScore * 2f)
    : Mathf.Lerp(0.10f, 0.35f, (matchScore - 0.5f) * 2f);

float pBaseEach = (1f - pOver - pConf) / 3f;
// pNormal = pMoody = pDepressed = pBaseEach
```

기본 3종 내부는 균등 배분.

## 적용 위치

### 적용 이벤트와 강도

| 이벤트 | 적용 여부 | 강도 |
|-------|---------|------|
| Battle      | ○ | 100% (full) |
| MiniBoss    | ○ | 100% (full) |
| Boss        | ○ | **50% (half)** |
| Trap        | ○ | **50% (half)** — TrapNegation 회피 확률에 적용 |
| TreasureChest / RareDrop / Rest / Entrance / Return / Retry / Protection | × | — |

- **Boss 절반 적용**: 1회성 판정에 ±30%급 변동은 무겁다. 사망/무기 손실과 직결되므로 절반으로 완화.
- **Trap 절반 적용**: TrapNegation 효과의 회피 확률 자체에 곱연산. 절반 강도는 모험가 성격이 회피 운에도 영향을 주되 무겁지 않게.

### 절반 적용 방식

multiplier를 1을 중심으로 절반 압축한다:

```csharp
// halfStrength=true면 변동 폭 절반
float ApplyHalf(float mult) => 1f + (mult - 1f) * 0.5f;
// 예: ×0.70 → ×0.85, ×1.30 → ×1.15
```

### 코드 통합 지점

#### Battle / MiniBoss / Boss — `CalculateEventSuccessRate()`

```csharp
private float CalculateEventSuccessRate(AdventureInstance adventure, DungeonEventData eventData)
{
    float baseRate = CalculateSuccessRate(...);
    float rate = baseRate * eventData.difficultyMultiplier;
    rate += adventure.cumulativeModifier;        // 점술가 운세 + 함정 페널티

    float mult = RollMoodMultiplier(adventure.mood);
    if (eventData.eventType == DungeonEventType.Boss)
        mult = 1f + (mult - 1f) * 0.5f;          // Boss는 절반
    rate *= mult;

    return Mathf.Clamp(rate, Config.successRateMin, Config.successRateMax);
}
```

#### Trap — `CalculatePendingTrap()`

`TrapNegation` 효과의 회피 확률(`effect.currentValue`)에 절반 강도 multiplier를 곱한다. 효과별로 굴리지 말고 **이벤트 단위로 한 번만 굴려** 모든 TrapNegation 효과에 같은 multiplier 사용.

```csharp
float halfMult = 1f + (RollMoodMultiplier(adventure.mood) - 1f) * 0.5f;
foreach (var effect in adventure.weapon.effects)
{
    if (effect.effectType == WeaponEffectType.TrapNegation)
    {
        float negChance = Mathf.Clamp01(effect.currentValue * halfMult);
        if (UnityEngine.Random.value <= negChance) { negated = true; break; }
    }
}
```

> `escapeRopeBonus`(아이템 효과)는 mood 영향 받지 않음 — 액티브 아이템 효과는 별개.

### 점술가 LuckIndicator와의 관계

- 점술가 = **모험 단위** 가산 보정 (`cumulativeModifier` 초기값)
- 기분 = **이벤트 단위** 곱셈 보정 (매번 새 분포 굴림)
- 변수와 연산이 분리되어 효과 추적이 명확.

## 노출 정책

- **UI 표시 없음.** 출발 패널, 진행 화면, 결과창, 리플레이 어디에도 기분 정보를 노출하지 않는다.
- **디버그 로그만.** `Debug.Log($"[Mood] {adventurer.Name} → {mood} (matchScore={matchScore:F2})")` 정도.
- 추후 노출 필요해지면 별도 기획.

### 위험 사항

- **유저가 패배 원인을 영영 모름.** 결과창에 표시 안 하므로, 같은 빌드로 반복 실패 시 시스템 의심으로 이어질 수 있음 → QA에서 분포가 의도대로 작동하는지 모니터링 필수.
- **마태효과 (완화됨).** 곱연산이라 이미 어려운 모험에서는 변동 폭이 작아져 합연산 대비 마태효과가 자연 완화. 다만 자기과신 35%(점수 0)는 여전히 강한 처벌이므로, 신규/저급 모험가의 고등급 던전 도전이 위축될 수 있음 → 플레이테스트 후 35% 캡 조정 검토.

## 결정 확정 사항

| # | 항목 | 결정 |
|---|------|------|
| 1 | 적용 이벤트 범위 | Battle/MiniBoss(full) + Boss(half) + Trap(half) |
| 2 | 보정 누적/일회성 | 일회성 (이벤트마다 새 굴림) |
| 3 | 점수 정규화 분모 | 별도 임계값 `Config.moodScoreThreshold` (던전 무관) |
| 4 | 점수에 armorBonus 포함 | 제외 (스탯 + 무기 효과만) |
| 5 | Boss 변동 폭 | 절반 (`1 + (m-1)*0.5`) |
| 6 | 자기과신 비대칭 | ×0.75 ~ ×1.10 (평균 0.925) — 기존 유지 |
| 7 | 기분파 양극 비율 | 50/50 균등 (matchScore는 mood 배정에만 영향) |
| 8 | 기본 3종 내부 분배 | 균등 (각 1/3) |

## 진행 순서

1. enum + Config 필드 정의
2. `AdventureInstance.mood`/`EventResult.moodMultiplier` 필드 + SaveData 동기화
3. `DetermineMood()`/`RollMoodMultiplier()` 구현 (디버그 로그 포함)
4. `CalculateEventSuccessRate()`에 Boss half 분기 포함해 통합
5. `CalculatePendingTrap()`에 half 강도로 통합
6. Battle/MiniBoss/Boss/Trap의 EventResult에 굴린 값 기록
7. 플레이테스트 → 분포·확률·임계값 튜닝
