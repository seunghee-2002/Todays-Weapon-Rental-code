## 0. 핵심 설계 결정 / 코딩 전 확인 필요 (⚠️ 승인 후 구현)

> 프로젝트 규칙상 코드 작성 전 플랜 승인이 필요하다. 아래 결정 사항을 먼저 확정해야 한다.

### 0-1. ✅ 몬스터는 RenderTexture로 렌더 (채택됨)
- 모험가는 **SkeletonGraphic**이라 카드 안 UI로 직접 들어감(Replay 검증). 몬스터 프리팹(`Assets/Layer Lab/2D Minimal-EnemyMonster/EnemyMonster 1/Prefabs`)은 **SpriteRenderer+Animator 월드 오브젝트**라 캐러셀 겹침에서 옆 카드 블리딩 위험 → 전용 카메라가 `MonsterStage` 레이어를 **RenderTexture**에 렌더하고 카드의 `monsterView`(RawImage)가 표시.
- 결과: 몬스터도 평범한 UI가 되어 계층 순서 정렬·`RectMask2D` 클리핑·`CanvasGroup` 페이드가 그대로 동작(서브캔버스/`SortingGroup`/`SpriteMask`/스케일 보정 불필요). 카메라+RT+`Assets/_Projects/Scripts/UI/Components/MonsterStageRenderer.cs`는 씬에서 1개 공유, 활성 카드만 `Spawn`/`Clear`. (상세 구성 → §7-2)

### 0-2. ✅ 몬스터 Animator 상태 이름 차이 — 공통 래퍼 `MonsterStageActor` 생성 완료
- 상태 이름이 `Animal_Idle`, `Bird_Attack`, `Wolf_Dead`처럼 **`{카테고리}_{동작}`** 으로 prefix가 붙는다.
- 컨트롤러에 파라미터/트랜지션이 없어 `animator.Play("상태이름")` 직접 호출 방식이다.
- 기존 공통 래퍼는 **없었음**(코드 검색 결과 없음) → 신규 생성: `Assets/_Projects/Scripts/UI/Components/MonsterStageActor.cs`
  - 논리 동작 `PlayIdle/Walk/Attack/Hit/Dead()` 제공, 내부에서 `{statePrefix}_{동작}` 으로 `Animator.Play`.
  - `statePrefix`는 비워두면 **Animator 컨트롤러 이름에서 자동 추출**(`Animal.controller` → `"Animal"`). 프리팹별 인스펙터 작업 없이 동작.
  - 운용: 몬스터 인스턴스화 시 스테이지가 `GetComponent<MonsterStageActor>() ?? AddComponent`로 부착(런타임 부착이면 100여 개 프리팹 수정 불필요).
  - ⚠️ `Goby`는 사망 상태 이름이 `GoBy_Dead`(대문자 B)일 수 있음 → 해당 프리팹만 `statePrefix` 수동 지정 또는 상태 이름 수정 필요.

### 0-3. ✅ 프롭/타입별 비주얼은 Config에 (채택됨)
- 전투 외 이벤트(TreasureChest/Rest/Trap/RareDrop/Protection)는 프롭 스프라이트 사용. 타입 단위 공통 비주얼(프롭·파티클·단계 애니 매핑·지속시간)은 신규 Config SO **`AdventureProgressAnimConfig`** 에 모으고, 이벤트 개체별 다양성(몬스터 프리팹·맵)만 `DungeonEventData`에 둔다. (`AdventureResultMotionConfig` 패턴과 동일)

### 0-4. 단계(Phase) 모델 — frac 기반 4단계 + 소프트 경계(애니메이션 atomic)

**결과를 미리 안다**: `evt.pendingResult`는 이벤트 **시작 시점**에 이미 계산됨(EventProcessor.cs:47 (`Assets/_Projects/Scripts/Systems/AdventureManager/AdventureManager.EventProcessor.cs`)). → 스테이지는 시작부터 승패를 알고 **전체 연출을 frac으로 미리 choreograph** 한다. (매니저 `OnAdventureEventTriggered`를 기다리지 않음)

**frac**: `frac = (TimeManager.CurrentTime - evt.startTime) / duration` (연속, CurrentTime은 게임-분이라 부드럽게 증가).
- `duration = Floor(intervalHours × cachedDurationMultiplier × 60 / 3) × 3` 게임-분, `intervalHours = (eventData.intervalHours>0 ? : AdventureConfig.eventIntervalHours) × LegacySpeed`.
- ⚠️ 이 공식 중복을 피하려고 **`AdventureManager`에 `GetEventDuration(evt, adventure)` 헬퍼를 추가**해 단일 소스로 쓴다. (소규모 매니저 추가 — 구현 시 처리)

**4단계 (경계는 Config, 소프트 타깃)**:
| 단계 | 기본 구간 | 내용 |
|---|---|---|
| 시작(입장) | 0 ~ 5% | 달려 진입, 배경 스크롤, (전투)몬스터 Idle |
| 실행 | 5 ~ 80% | 전투 공방 등 루프. **80% 넘으면 새 공방을 시작하지 않음** |
| 완료 | 80 ~ 90% | 승패 연출(승=몬스터 Dead, 패=Die/Hit) |
| 이동 | 90 ~ 100% | 다음 노드로 달려가며 여유(buffer) |

**소프트 경계 = 애니메이션 atomic (핵심)**:
- 단계 경계에서 **재생 중인 애니메이션을 자르지 않는다.** 진행 중 동작을 끝까지 재생한 뒤 다음 단계로 넘어가며, **이후 단계를 뒤로 밀어(압축)** 자연스럽게 잇는다.
- 예(전투): 실행 79%에 공격(소요 ~10%)이 시작됨 → **89%까지 그 공격을 그대로 재생** → 완료(89~99%) → 이동(99~100%). 경계가 탄력적으로 밀린다.
- 구현: 실행 루프는 **새 공방 시작 전에만** `frac < executePhaseEnd`를 확인. 일단 시작한 공방(공격+피격)은 atomic하게 끝낸 뒤 완료로 전환.

**이동 단계 후 대기**: 시각 연출이 100%에 도달했는데 매니저가 아직 다음 이벤트를 시작 안 했으면(시간 흐름 차이), 다음 `OnAdventureEventTriggerStarted`가 올 때까지 `Run`/`Idle`로 자연스럽게 대기.

### 0-6. 배경(맵) 스크롤 — 단일 스프라이트 무한 이동 (RawImage.uvRect)
- **방식**: `RawImage`에 맵 텍스처를 넣고 매 프레임 `uvRect.x += backgroundScrollSpeed × dt`. 머티리얼 인스턴스 불필요(텍스처 오프셋과 동일 효과를 UI 네이티브로). 단일 스프라이트로 무한 스크롤.
- **필수 임포트 설정**: 맵 배경 텍스처 **Wrap Mode = Repeat** (+ 아틀라스에 패킹되지 않은 독립 텍스처). 안 그러면 UV 래핑이 깨진다.
- **소스**: `dungeon.mapBackground`(Sprite, 던전 고정) → 런타임에 `.texture`를 RawImage에 할당.
- 스크롤은 **입장/실행 중 전진감 줄 때만** 켜고, 정지형(Rest/Protection) 등에서는 멈춘다.

### 0-5. 성능
- 캐러셀 5슬롯 중 **중앙 카드만** 실시간 연출(Spine 갱신 + 몬스터 렌더). 좌우 카드는 정지 프레임 또는 비활성.
- 카드의 진행률 갱신은 매 프레임 대신 `TimeManager.OnTimeChanged` 구독으로 처리.

## 2. 모험가 애니메이션 정리

모험가 Spine: **Fantasy Character** (SpineData (`Assets/Layer Lab/2D Art Maker/AMFantasy Character/Demo/SpineAnimation/Fantasy Character.json`)), UI에서는 `SkeletonGraphic`로 표시.

### 2-1. 보유 애니메이션 클립
| 클립 | 용도 |
|---|---|
| `Idle` | 기본 정지 |
| `Idle2` | 정지 변형(선택) |
| `Idle_Bow` / `Idle_Bolt` | 활/석궁 든 정지(선택 폴리시) |
| `Walk` | 천천히 걷기 (보물 탐색 등) |
| `Run` | 달리기(맨손) |

| `Attack1` / `Attack2` / `Attack3` | 근접 공격 변형 |
| `Attack_Bow` | 활 공격 |
| `Attack_Bolt` | 석궁 공격 |
| `Attack_Magic` | 마법 공격 |
| `Hit` | 피격 |
| `Die` | 사망 |

### 2-2. 무장 상태 판정 (맨손 = 무기 미대여 = 기본무기)
- 모험가는 **항상 `adventure.weapon`** 을 든다. 이 값은 null이 아니다 — 무기를 대여하면 대여 무기, **대여하지 않으면 모험가의 `defaultWeapon`**(미대여)이 들어간다. (기본무기는 `DataManager`가 `WeaponType`별로 보유: `GetDefaultWeapon(type)`)
- **판정 기준은 `adventure.isUsingDefaultWeapon`** (= `weapon.isDefaultWeapon`).

| 상태 | 조건 | 무기 비주얼 | 이동 | 공격 |
|---|---|---|---|---|
| **무장(대여)** | `!isUsingDefaultWeapon` | `gear_right = weapon.weaponData.gearRightIndex` | `Run_Gear` | WeaponType 매핑(2-3) |
| **맨손(미대여=기본무기)** | `isUsingDefaultWeapon` | gear_right **숨김** (`SetHideItem(Gear_Right, true)`) | `Run` | `Attack1`(기본 타격) |

> 즉 `gearRightIndex == -1` 여부가 아니라 **무기 대여 여부**로 맨손을 판정한다.

### 2-3. WeaponType → 공격 애니메이션 매핑 (무장 시) *(초안, 확정 필요)*

## 3. 몬스터 애니메이션 정리

상태 이름은 **`{카테고리}_{동작}`**. 동작 5종 고정: `Idle / Walk / Attack / Hit / Dead`. 기본 상태 = `{카테고리}_Idle`.

| 논리 동작 | 호출 시점 | 실제 상태 |
|---|---|---|
| `PlayIdle()` | 입장 단계 대기 / 패배 후 정지 | `{cat}_Idle` |
| `PlayAttack()` | 실행 단계, 몬스터 공격 차례 | `{cat}_Attack` |
| `PlayHit()` | 모험가 공격 적중 시 | `{cat}_Hit` |
| `PlayDead()` | 완료(모험가 승리) → 재생 후 비활성/소멸 | `{cat}_Dead` |
| `PlayWalk()` | (필요 시) 몬스터 등장 이동 | `{cat}_Walk` |

### 3-3. 단계별 몬스터 동작 (전투: Battle/MiniBoss/Boss)
| 단계 | 몬스터 |
|---|---|
| 입장(0~5%) | `Idle` 로 우측 대기 |
| 실행(6~99%) | 모험가 공격 → `Hit`(+피격 파티클) → 몬스터 `Attack`(모험가 `Hit`+파티클) 교대 |
| 완료 승리 | `Dead` 재생 → 종료 후 **비활성화/제거** |
| 완료 패배 | `Idle` 로 가만히 (모험가가 `Die`) |

> Battle / MiniBoss / Boss는 **동일 로직**, 몬스터 프리팹/배경 덮어쓰기로 격차 표현(Boss는 `mapBackgroundOverride` 권장).

## 7. 프리팹(animationArea) 구성 가이드

> `AdventureProgressStage`는 카드 프리팹 `animationArea` GameObject에 부착한다. 아래 자식들을 만들고 SerializeField에 연결.
> 핵심: 몬스터만 **RenderTexture**(MonsterStageRenderer)로 렌더해 RawImage로 표시 → animationArea의 자식은 **전부 UI**라 **계층 순서로만 정렬**(서브캔버스·Canvas sort order 불필요, 0-1).

### 7-1. 계층 트리 (전부 UI, 계층 순서 = 그리기 순서: 위=뒤, 아래=앞)
```
animationArea            ← AdventureProgressStage + RectMask2D (UI 클리핑)
├─ Background            ← RawImage [Stage.backgroundRaw]  (stretch 전체, uvRect 스크롤, 맵 텍스처 Wrap=Repeat)
├─ AdventurerRoot        ← RectTransform (좌측, x≈ -영역폭*0.28)
│  ├─ AdventurerRig      ← AdventurerAppearanceApplier [Stage.adventurerApplier] (SkeletonGraphic + PartsManager, Replay rig 복제)
│  └─ AdvParticleAnchor  (빈 Transform) [Stage.adventurerParticleAnchor]
├─ MonsterView           ← RawImage [Stage.monsterView]  (우측, MonsterStageRenderer의 RT 표시, 평소 비활성)
├─ PropRoot              ← RectTransform [Stage.propRoot]
│  ├─ Prop               ← Image [Stage.propImage]
│  └─ PropParticleAnchor (빈 Transform) [Stage.propParticleAnchor]
└─ typeIcon              ← Image (전경, 기존 카드 typeIcon)
   (eventLogText는 카드 Bottom에 그대로 — animationArea 밖)
```

### 7-2. MonsterStageRenderer (씬에 1개, 공유)
별도 GameObject에 `Assets/_Projects/Scripts/UI/Components/MonsterStageRenderer.cs` 부착 + 구성:
- **레이어 추가**: `MonsterStage` (Project Settings > Tags and Layers)
- **RenderTexture 에셋** 생성(예: 512×512, ARGB32, Depth 16) → `renderTexture`에 연결
- **MonsterCam**(Camera): Projection=Orthographic, **Culling Mask=MonsterStage만**, Clear Flags=Solid Color(**알파 0 = 투명**), Target Texture=그 RT → `stageCamera`에 연결. (스크립트가 평소 비활성화 = 렌더 정지)
- **SpawnPoint**(빈 Transform): MonsterCam 정면, 게임플레이 영역 밖 → `spawnPoint`에 연결
- **메인 카메라**: Culling Mask에서 **`MonsterStage` 제외**(월드에 안 보이게)
- 카드의 `monsterView` RawImage Texture에 같은 RT 지정(코드도 런타임에 세팅)

### 7-3. RT 채택으로 사라진 작업
- ❌ 서브캔버스 overrideSorting / 몬스터 `SortingGroup` / Canvas sort order — **불필요**
- ❌ 몬스터 스케일 보정 / `SpriteMask` 클리핑 — **불필요** (표시 크기 = `monsterView` RawImage 크기, 프레이밍 = MonsterCam ortho size, 클리핑 = `RectMask2D`)
- 몬스터 피격 파티클은 RT 스테이지에서 렌더(`MonsterStageRenderer.SpawnParticle`). 모험가/프롭 파티클은 UI 앵커(별도 폴리시 단계).

### 7-4. 좌표/앵커 권장
- 모험가: 좌측 0.25~0.3 지점, 바닥 정렬. 몬스터: 우측 대칭. Prop: 모험가 약간 우측(접근 종착점).
- Background: animationArea에 stretch로 꽉 채움.

### 7-5. 구축 순서
1. (씬) MonsterStageRenderer + `MonsterStage` 레이어 + RT + MonsterCam + SpawnPoint 구성 (7-2). 메인 카메라 Culling Mask에서 MonsterStage 제외
2. animationArea에 `AdventureProgressStage` + `RectMask2D`
3. Background(RawImage, Wrap=Repeat) / AdventurerRig(Replay rig 복제) / MonsterView(RawImage, RT 지정) / PropRoot+Prop / 앵커들 배치 — 전부 UI, 계층 순서 정렬
4. Stage SerializeField 연결 + **카드 `AdventureProgressCard.stage`에 이 Stage 연결**
5. typeIcon은 전경(맨 아래 자식). currentEventIcon은 추후 제거(6-2)
6. ✅ 카드↔스테이지 코드 배선은 완료(E) — 인스펙터 연결만 남음

## 9. Progress 구조 전체 리팩터 — ✅ 완료 (커밋 eb3e8153)

이벤트 생성 시 결과를 1:1로 확정(`AdventureEvent.result`), "현재 진행 이벤트"는 `currentEventIndex` + `startTime` 단일 포인터로 추적. `eventResults` 리스트·`isStarted/isTriggered` 제거. 모험 시작 시 `ResolveSequence`가 순차 시뮬레이션으로 전체 해결(삽입·누적·`isDeath`)하고, 런타임은 시간 경과로 포인터만 전진하다 마지막 이벤트 도달 시 `CompleteAdventure`(플레이어 지급은 그 시점).

> ⚠️ **구버전(진행 중) 세이브는 로드 시 드롭된다** — `AdventureManager` 로드 가드가 `events[^1].result == null`이면 legacy로 간주해 스킵. 완료 세이브 리플레이는 `pendingResult`→`result`(`FormerlySerializedAs`) 매핑에 의존(구버전 완료 모험 1회 검증 권장).
