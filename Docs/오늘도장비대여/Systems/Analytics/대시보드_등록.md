# Analytics 대시보드 등록

> UGS 대시보드 Event Manager 에 커스텀 이벤트 스키마를 등록하는 절차.
> **스키마의 단일 원본은 `Tools/Analytics/events.json` 이다.** 아래 목록은 그 파일에서 자동 생성된다.
> 등록이 안 된 이벤트는 invalid 처리로 버려진다.

## 자동화

Unity 는 Analytics 이벤트 스키마용 공개 API 를 제공하지 않는다(공식 Analytics API 경로는 이벤트 전송용 2개뿐이고, `ugs deploy` 지원 목록에도 Analytics 가 없다). 그래서 대시보드 조작을 브라우저로 대신하는 비공식 경로를 쓴다.

`pull` 은 대시보드 화면이 부르는 내부 API 응답을 가로채 읽는다 — 인증 헤더를 흉내 내지 않으므로 세션만 살아있으면 동작한다.

```
GET .../api/live-ops/events/v3/organizations/{org}/projects/{p}/environments/{e}/schemas
GET .../api/live-ops/events/v3/organizations/{org}/projects/{p}/environments/{e}/parameters
```

> [!warning] 이벤트별 파라미터는 `parameters` 필드에 없다
> `schemas` 응답의 `parameters` 는 **항상 빈 배열**이다. 실제 연결은 `schema`(JSON Schema 문자열)의 `properties.eventParams.properties` 에 들어있다. 여기를 잘못 읽으면 "전 이벤트 파라미터 연결 누락"이라는 가짜 결과가 나온다.
> `platform` / `clientVersion` / `sdkMethod` / `userCountry` 는 SDK 가 모든 이벤트에 자동으로 붙이는 표준 파라미터라 `isPredefined` 로 걸러낸다.

```powershell
cd Tools\Analytics

# 코드 <-> events.json 대조 (자격증명 불필요. CI가 자동 실행)
python analytics.py check

# events.json -> 이 문서의 생성 섹션 갱신
python analytics.py render

# 대시보드 반영 (최초 1회 pip install -r requirements.txt && playwright install chromium)
python dashboard_sync.py login        # 브라우저에서 직접 로그인 -> 세션 저장
python dashboard_sync.py pull         # 현재 등록 상태 읽기
python dashboard_sync.py diff         # 무엇이 빠졌는지
python dashboard_sync.py apply        # 부족한 파라미터/이벤트 생성 (삭제는 안 함)
python dashboard_sync.py pull         # 반드시 재확인
```

> [!warning] apply 는 만능이 아니다
> 대시보드 UI 가 바뀌면 셀렉터가 깨진다. 실패한 항목은 로그에 남으므로 그것만 아래 체크리스트로 직접 처리하면 된다. `apply` 후에는 항상 `pull` 로 결과를 검증한다.

> [!note] 브라우저는 설치된 Edge/Chrome 을 쓴다
> 이 환경에서는 Playwright 번들 chromium 이 **창을 띄우는 실행에서만** 즉시 죽는다(headless 는 정상). 그래서 `msedge` -> `chrome` -> 번들 순으로 시도하고 처음 성공한 채널을 `.auth/config.json` 에 기억한다. 직접 고르려면 `--channel msedge` 처럼 넘긴다.
> 로그인 상태는 `state.json` 이 아니라 `.auth/profile/` 의 실제 브라우저 프로필에 남는다.

> [!info] 코드와 스키마는 CI 가 지킨다
> `.github/workflows/analytics-schema-check.yml` 이 코드↔`events.json`↔이 문서를 매 푸시마다 대조한다. 코드에만 있는 이벤트/파라미터가 생기면 빌드가 실패한다. -> [[Analytics_구현_메모]]

## 접속 (수동 작업 시)

1. https://cloud.unity.com 접속 → Unity 에디터와 같은 계정으로 로그인
2. 상단 프로젝트 선택 드롭다운에서 이 게임 프로젝트 선택 (에디터 `Project Settings > Services` 에 연결된 프로젝트)
3. 왼쪽 메뉴 → **Analytics** → **Event Manager**
4. 환경(Environment) 선택이 보이면 기본값 **production** 그대로 사용

## 등록 방법 (수동 작업 시)

- 이벤트 생성: **Add New → Custom Event** → 이름 입력 (아래 목록의 이름 그대로, 소문자+언더스코어)
- 파라미터 연결: 이벤트 화면에서 **Assign Parameter** → 이미 만든 파라미터는 검색해서 연결, 없으면 **Create New Parameter** 로 생성(이름 + 타입)
- 파라미터는 전역 공용이므로 **한 번 만들면 여러 이벤트에 재사용**된다. 파라미터를 먼저 다 만든 뒤 이벤트에 연결하는 순서가 빠르다.
- 필수(required) 옵션은 **전부 선택 안 함**으로 둔다 — `dialog_open_duration_sec`, `duration_sec`, `blacksmith_type` 등 조건부 파라미터가 많다. 특히 `btn_clicked` 는 버튼마다 붙는 파라미터가 달라서 **어느 하나라도 required 면 이벤트 전체가 invalid 로 버려진다.**

## 0. 현재 등록 상태 (2026-08-04 `pull` 실측)

아래 목록은 **이미 production 환경에 전부 등록돼 있다.** 처음부터 등록하는 경우가 아니라면 목록을 따라 찍을 필요가 없다.

| 항목 | 결과 |
|---|---|
| 커스텀 이벤트 | 28/28 등록, 전부 enabled |
| 커스텀 파라미터 | 73개 전부 등록 (+ 폐기 잔재 2개) |
| 이벤트별 파라미터 연결 | 누락 0 |
| 타입 불일치 | 0 |
| **required 가 걸린 이벤트** | **0 (가장 중요한 항목 - 정상)** |
| Invalid 이벤트 | 0건 |

남아있는 무해한 잔재 2가지. 고쳐도 되고 안 고쳐도 된다.

- `btn_clicked` 에 `level_before` 가 연결돼 있다. 코드는 `btn_clicked` 에 이 값을 넣지 않는다(원래 자리는 `blacksmith_enforce_done`). **required 가 아니므로 무해**하다. 신경 쓰이면 연결만 끊는다.
- `grade`, `level` 파라미터가 남아있지만 **어떤 이벤트에도 연결돼 있지 않다.** 값이 들어올 경로가 없으므로 그대로 둬도 된다.

> [!note] 폐기 배경과 과거 데이터
> `grade` 는 `weapon_grade` 와 역할이 같아 통합했고, `level` 은 `blacksmith_enforce_done.level_before` 와 값이 같아 제거했다.
> `grade` 로 이미 수집된 데이터가 있으면 그 시점을 기준으로 컬럼이 갈린다. 과거·현재를 한 번에 보려면 `COALESCE(EVENT_JSON:weapon_grade::int, EVENT_JSON:grade::int)` 가 필요하다. 출시 전 테스트 데이터뿐이라면 지표 기준일을 출시일 이후로 잡으면 신경 쓸 필요 없다.

> [!info] 파라미터는 환경 단위다
> 대시보드 안내: "Parameters now exist at the environment level and are not shared between each other." 환경을 추가하면 파라미터도 그 환경에 다시 만들어야 한다.

## 3. 등록 후 검증 (전 이벤트 수신 테스트)

### 준비

- 스탠드얼론 빌드로 테스트한다 — 에디터는 전송이 차단돼 있음 (에디터에선 콘솔 로그로 발행 여부만 확인 가능)
- 빌드 씬 목록에 MainMenuScene + InGameScene 포함, **디버그 메뉴가 씬에서 활성 상태**인지 확인
- 에디터와 빌드가 같은 persistentDataPath(gamedata.json)를 공유하므로, 전체 테스트는 **새 게임**으로 시작
- 이벤트는 배치 업로드라 대시보드 반영까지 1~2분 지연될 수 있다. 앱을 강제 종료하면 마지막 배치가 유실될 수 있으니 확인 전 잠시 대기하거나 정상 종료할 것
- 디버그 메뉴로 만든 테스트 데이터도 실지표에 그대로 쌓인다 — 출시 전이라 무방하지만, 출시 시점에는 지표 기준일을 출시일 이후로 잡을 것

### 수신 확인 방법

대시보드 → Analytics → **Event Browser**: 수신 이벤트가 시간순으로 표시된다. 이벤트를 클릭하면 파라미터 값 확인 가능. **Invalid** 표시가 있으면 클릭해 사유 확인 (대부분 이름 오타/타입 불일치/미등록).
