# 버튼 이벤트 (Level 3)

> [!abstract] 한 줄 요약
> 단일 이벤트 `btn_clicked`에 **116개 클릭 지점**이 `panel` + `button` 조합으로 들어간다.
> 공통 파라미터: `panel: string`, `button: string`, `day`, **`is_first_time: bool`**

> [!important] 이 문서는 설계 근거, 등록 원본은 `Tools/Analytics/events.json`
> `panel`/`button` 의 **값**은 대시보드 등록 대상이 아니다(문자열 파라미터일 뿐). Event Manager 에 필요한 것은 `btn_clicked` 에 연결된 파라미터 이름 목록뿐이며 그것은 `events.json` 이 갖는다. 아래 표에 조건부 파라미터를 추가하면 `events.json` 의 `btn_clicked.parameters` 에도 넣어야 한다. -> [[대시보드_등록]]

> [!important] Level 3이 재는 것은 "눌렀는가"다
> 성패는 Level 4 도메인 이벤트가 담당한다. 따라서 발행은 **자원 부족·조건 미충족 조기 return 앞**에 둔다. 단, 파라미터가 null 참조를 요구하면 그 null 가드 뒤로 내린다. -> [[Analytics_구현_메모]]

## 통찰 (대화)

`panel = "adventurer_talk"` · 발행 위치: `AdventurePreparationController`

> [!info] 독립 패널이 아니다
> 통찰 액션은 모험 준비 패널의 **Tab1**에 있다. `panel` 값만 `adventurer_talk`으로 분리해 지표를 구분한다.
> 일반 버튼은 **인게임 시간**을, 유산 버튼은 **유산 포인트**를 소비하며 후자는 100% 성공한다. -> [[통찰_시스템]]

| `button` | 추가 파라미터 | 의미 |
|---|---|---|
| `reveal_stat` | `stat: string` (STR/DEX/INT/LUK) | 스탯 테스트 요청 |
| `reveal_all_stats` | — | 종합 테스트 요청 |
| `reveal_trait` | — | 특성 테스트 요청 |
| `weapon_type_hint` | — | 무기 타입 힌트 요청 |
| `test_premium_toggle` | `is_on: bool` | 확인 패널의 유산 결제 토글 |
| `test_proceed` | `is_on: bool`, `legacy_cost: int` | 확인 패널의 실행 버튼 |

> [!warning] 일반/유산 4쌍(`*_legacy`)은 코드에 없다
> 유산 결제는 별도 버튼이 아니라 확인 패널의 **토글 + 단일 실행 버튼** 구조다. `test_premium_toggle.is_on`과 `test_proceed.is_on`으로 같은 정보를 얻는다.
> **`success`는 넣지 않는다** — 버튼 지표는 "요청했는가"만 잰다.
> 미니 정보 패널의 스탯/특성/무기힌트 클릭은 위 3개 메서드로 위임되므로 별도 발행하지 않는다(중복 방지).

## 모험 준비

`panel = "adventure_preparation"` · 3탭 구조(탐색 / 지원 / 최종 준비)

탭 전환은 진행도 클릭과 화살표 이동이 같은 메서드를 타므로 **탭 기준으로 한 번만** 발행한다.

|---|---|---|
| `tab_explore` / `tab_support` / `tab_dungeon` | — | 탭 전환 (진행도 클릭 + 화살표 공통) |
| `dungeon_card_click` | `dungeon_id: string` | 던전 카드 클릭(상세 표시) |
| `dungeon_selected` | `dungeon_id: string` | 던전 선택 확정 |

## 무기 선택

| `button` | 추가 파라미터 | 의미 |
|---|---|---|
| `weapon_card_click` | `weapon_id`, `weapon_grade: int` | 무기 카드 클릭(상세 표시) |
| `weapon_selected` | `weapon_id`, `weapon_grade: int` | 대여 확정 |
| `cancel_weapon` | — | 대여 취소(기본 무기로 복귀) |
| `back` | — | 무기 상세 닫기 |
| `type_filter` | `filter_index: int` | 타입 필터 변경 |

> [!warning] `type_filter` 해석 주의
> Tab2 진입 시 `AdventurePreparationView.SwitchTab(1)`이 무기 필터를 `0`(전체)으로 되돌리며 토글 이벤트를 발생시킨다. 따라서 이 지표에는 **사용자가 누르지 않은 `filter_index = 0` 건이 섞인다.** 필터 사용량을 볼 때는 `filter_index > 0`만 집계할 것.
> (어느 분석 목표에도 쓰이지 않는 보조 지표라 코드는 수정하지 않았다.)

> [!note] 제외
> `sort` — 정렬 UI가 없다.

## 아침 이벤트

`panel = "morning_event"` · 추가 파라미터 `event_type: string`이 **모든 버튼에 자동 첨부**된다.

> [!important] 발행 위치가 다르다 — View에서 발행
> 아침 이벤트 컨트롤러 9종은 버튼명을 갖지 않는 도메인 실행기이고, 실제 버튼 핸들러는 각 View의 private 메서드에 있다. 따라서 `MorningEventViewBase.SendButtonClick(button, extra)` 헬퍼를 통해 **View에서 발행**한다. 이 헬퍼가 `event_type`을 항상 동봉하므로 호출부는 버튼명만 넘긴다. -> [[아침이벤트_UI]]

| `event_type` | `button` |
|---|---|
| `black_market` | `weapon_icon`, `buy`, `reject` |
| `blacksmith_event` | `weapon_card`, `back`, `confirm`, `select_close` |
| `collector` | `weapon_card`, `back`, `sell`, `minigame_card`, `minigame_back` |
| `guild_envoy` | `result_close`, `material_card` |
| `investor` | `confirm` |
| `mystery_box` | `buy`, `pass`, `material_card`, `weapon_card`, `result_close` |
| `refugee` | `donate`, `reject` |
| `weapon_enhance` | `weapon_card`, `back`, `confirm`, `result_close` |
| `weapon_exchange` | `weapon_card`, `back`, `detail_confirm`, `detail_back`, `confirm` |

**공통 버튼명 규칙** — `weapon_card`/`material_card`(카드 클릭), `back`(상세 닫기), `confirm`(실행 확정), `result_close`(결과창 닫기), `reject`/`pass`(거절).

> [!note] 대화 선택지로 처리되는 것
> `guild_envoy`의 `donate`/`reject`와 `investor`의 `pass`는 별도 버튼이 아니라 **대화 선택지**라 버튼 이벤트가 없다. 선택 결과는 `morning_event_resolved.choice`로 잡힌다. -> [[대화]]
> 금액·무기 ID는 `gold_transaction`과 `morning_event_resolved`가 이미 기록하므로 생략한다.

> [!tip] Level 3의 역할
> G6(수락률) 자체는 Level 4 `morning_event_resolved.choice`가 담당한다. Level 3은 **"어느 화면에서 이탈하는가"**와 G3(발견율) 용도다.

## 유산 업그레이드

`panel = "legacy_upgrade"`

| `button` | 추가 파라미터 | 의미 |
|---|---|---|
| `category_selected` | `category: string` (UpgradeCategory) | 카테고리 탭 선택 |
| `buy` | `upgrade_key: string` | 업그레이드 구매 |
| `close` | — | 닫기 |

> [!note] 제외
> `confirm` — 코드에 별도 확인 단계가 없다(`buy`가 곧 구매 실행). `cost`도 Level 4 `legacy_transaction`이 기록한다.
