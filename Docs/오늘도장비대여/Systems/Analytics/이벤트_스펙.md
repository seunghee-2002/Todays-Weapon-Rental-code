# 이벤트 스펙 (Level 1 · 2 · 4)

> [!abstract] 이 문서의 범위
> 공통 파라미터와 **Level 1(게임 흐름) / Level 2(패널) / Level 4(도메인 결과)** 이벤트 정의.
> Level 3 버튼 이벤트는 분량이 커서 [[버튼_이벤트]]로 분리했다. 각 목표(G번호)의 의미는 [[분석목표]] 참조.

> [!important] 이 문서는 설계 근거, 등록 원본은 `Tools/Analytics/events.json`
> 대시보드에 실제로 등록되는 이벤트·파라미터 목록은 `events.json` 하나뿐이다. 이벤트를 추가·변경하면 **이 문서와 `events.json` 을 같은 작업에서** 고친다. 어긋나면 CI(`analytics-schema-check`)가 실패한다. -> [[대시보드_등록]]

## 공통 파라미터

모든 이벤트에 자동 포함한다.

| 파라미터 | 타입 | 설명 |
|---|---|---|
| `day` | int | 인게임 일수 |
| `game_time_min` | int | 인게임 시각 (분, 0~1439) |

> [!info] SDK가 자동 부여하는 것
> `session_id`, `timestamp`(UTC), `clientVersion`은 UGS SDK가 붙인다. 중복 수집하지 않는다.

## Level 2 — 패널 열림/닫힘

**이벤트 이름**: `panel_opened` / `panel_closed`

| 파라미터 | 적용 | 설명 |
|---|---|---|
| `panel` | 공통 | 패널 식별자 (아래 표) |
| `is_first_time` | `panel_opened` | 패널 자체를 처음 연 시점 추적 (G3) |
| `duration_sec` | `panel_closed` | 패널 체류 시간 |
| `blacksmith_type` | `blacksmith` 한정 | 대장장이 타입 (G23) |
| `delay_real_min` | `adventure_result` 한정 | 모험 완료 후 실경과 분 (G26) |

> [!important] 화이트리스트 발행
> `UIManager.analyticsPanelNames`(Type -> panel 문자열)에 등록된 View만 발행한다. 등록 51개 패널 중 **17개만 대상**이며 나머지(`TutorialHighlightView` 등)는 무시되므로 이벤트 볼륨이 튀지 않는다. -> [[Analytics_구현_메모]]

### UIManager 패널 (17종)

| `panel` 값 | View 클래스 | 진입 경로 | 분석 질문 |
|---|---|---|---|
| `inventory` | `InventoryView` | 하단바 인벤토리 버튼 | 인벤토리를 한 번도 안 연 유저 비율 |
| `weapon_detail` | `WeaponDetailPopup` | 대장장이 / 모험 리플레이 / 아침 이벤트에서 무기 클릭 | 무기 상세 확인 비율 |
| `material_detail` | `MaterialDetailPopup` | 대장장이 / 모험 준비 / 아침 이벤트 / 던전 상세에서 재료 클릭 | 재료 확인 비율 |
| `active_item_detail` | `ActiveItemDetailPopup` | 대장장이에서 아이템 클릭 | 액티브 아이템 인지율 |
| `adventure_progress` | `AdventureProgressView` | 하단바 모험 버튼 | 진행 중 모험 확인 빈도 |
| `adventure_result` | `AdventureResultView` | 모험 완료 후 | 결과 즉시 확인율 (**G26**) |
| `weapon_shop` | `WeaponShopView` | 무기 상인 NPC | 무기 상점 발견율 |
| `blacksmith` | `BlacksmithView` | 대장장이 NPC | 대장장이 발견율 (**G23**) |
| `adventure_dialog` | `AdventureDialogueView` | 방문자 클릭 | 방문자 대화 시작율 (**G1 시작점**, **G9**) |
| `adventure_preparation` | `AdventurePreparationView` | 대화창의 모험 준비 버튼 | 모험 준비 화면 도달율 |
| `seer` | `SeerView` | 모험 준비 Tab3 점술가 버튼 | 점술가 기능 발견율 (**G11**) |
| `quest` | `QuestView` | 하단바 퀘스트 버튼 | 퀘스트 발견율 |
| `quest_board` | `QuestBoardView` | 의뢰판 (매일 9시 자동 + 사이드바) | 의뢰판 발견율 (**G25**) |
| `morning_event` | `MorningEventViewBase` 9종 | 아침 이벤트 자동 표시 | — |
| `legacy_upgrade` | `LegacyUpgradeView` | 메인메뉴 유산 업그레이드 버튼 | 유산 시스템 발견율 |
| `option_popup` | `OptionPopupView` | 하단바 설정 버튼 / ESC | — |
| `game_over_popup` | `GameOverPopupView` | 게임 오버 자동 표시 | — |

> [!note] `morning_event`는 9종을 하나로 접는다
> BlackMarket / Blacksmith / Collector / GuildEnvoy / Investor / MysteryBox / Refugee / WeaponEnhance / WeaponExchange 9개 서브클래스를 단일 panel 값으로 묶는다. 유형 구분은 `morning_event_shown.event_type`이 이미 담당하므로 중복 수집하지 않는다. -> [[아침이벤트_시스템]]

> [!warning] 인벤토리 상세는 이 이벤트로 잡히지 않는다
> 인벤토리 안의 무기/재료/아이템 상세는 `InventoryView` 내부 인라인 GameObject를 `SetActive`로 토글하는 구조라 `UIManager`를 경유하지 않는다. 해당 지표는 `btn_clicked(inventory, weapon_item_click / material_item_click / active_item_click)`으로 대체 추적한다. -> [[버튼_이벤트]]

### 탭 기반 가상 패널 (3종)

독립 패널이 아니라 탭/페이즈이므로 **`panel_opened`만 수동 발행하고 `panel_closed`는 발행하지 않는다**(탭 이탈 훅이 없어 `duration_sec`이 의미를 갖지 않음).

| `panel` 값 | 발행 지점 | 분석 질문 |
|---|---|---|
| `weapon_selection` | `AdventurePreparationController.OnWeaponSubTabSelected()` | 무기 선택 화면 진입율 (**G13** 보조) |
| `active_item_selection` | `AdventurePreparationController.OnActiveItemSubTabSelected()` | 액티브 아이템 활용율 |
| `scout_dispatch` | `QuestBoardView.EnterScoutPhase()` | 수색꾼 파견 발견율 (**G8**, 퍼널 D) |

### 제외된 패널 3종

> [!danger] 영구 제외 — 다시 논의하지 않는다
> - **`scout_progress` / `scout_result`** — 패널을 **만들지 않기로 확정**. 수색 결과는 토스트로만 표시하고, 의뢰판·모험 준비 화면은 `ScoutManager.OnScoutComplete`로 인라인 갱신한다. 따라서 "결과 확인율" 지표 자체가 성립하지 않는다.
> - **`adventurer_talk`** — 통찰 탭(Tab1)은 모험 준비 패널의 **기본 착지 탭**이라, 여기서 `panel_opened`를 발행하면 "다른 탭에서 되돌아온 횟수"만 잡히고, 초기 진입까지 세면 `adventure_preparation`과 1:1이 되어 지표 가치가 없다. 원래 목적(통찰 기능 발견율)은 `btn_clicked(adventurer_talk, reveal_stat)` 계열이 정확히 측정한다. **Level 3의 `panel` 값으로만 유지한다.**

## Level 4 — 도메인 결과 이벤트

버튼 클릭과 별개로 **성공한 결과가 발생했을 때만** 기록한다. Level 3과 중복되지만 "실제로 완료된 행동"만 카운트할 때 쓴다.

### 모험

| 이벤트 | 파라미터 | 연결 목표 |
|---|---|---|
| `adventure_started` | `dungeon_id`, `weapon_id`, `weapon_grade: int`, `adventurer_id`, `dialog_open_duration_sec: int`, `seer_used: bool`, `revealed_stat_count: int`, `trait_revealed: bool`, `weapon_is_player_selected: bool`, `armor_type_match: bool`, `is_named_adventurer: bool` | **G1, G11, G12, G13, G19, G22** |
| `adventure_completed` | `dungeon_id`, `weapon_id`, `weapon_grade: int`, `outcome: string`, `duration_min: int`, `seer_used: bool`, `weapon_is_player_selected: bool`, `is_named_adventurer: bool`, `revealed_stat_count: int`, `trait_revealed: bool`, `armor_type_match: bool` | **G7, G11, G12, G13, G17, G19, G22** |

> [!tip] 통찰·매칭 파라미터를 completed에 복사하는 이유
> `started`/`completed` 간 조인 없이 **한 이벤트 안에서** 교차 분석이 끝나도록 하기 위해서다 (G12·G19).

### 대장장이

| 이벤트 | 파라미터 | 연결 목표 |
|---|---|---|
| `blacksmith_enforce_done` | `weapon_id`, `weapon_grade: int`, `level_before: int`, `level_after: int`, `success: bool` | **G4, G21** |
| `blacksmith_evolve_done` | `weapon_id`, `grade_before: int`, `grade_after: int` | **G4** |
| `blacksmith_disassemble_done` | `weapon_id`, `weapon_grade: int` | **G4** |
| `blacksmith_reroll_done` | `weapon_id`, `locked_count: int` | **G4** |
| `blacksmith_craft_done` | `recipe_id`, `result_type: string` (weapon/item) | **G4** |

### 퀘스트 · 이벤트 · 상점 · 경제

| 이벤트 | 파라미터 | 연결 목표 |
|---|---|---|
| `quest_completed` | `quest_id`, `issue_day: int`, `complete_day: int`, `days_to_complete: int`, `reward_type: string` | **G5** |
| `quest_failed` | `quest_id`, `issue_day: int`, `fail_day: int`, `fine: int` | **G5** |
| `quest_board_confirmed` | `dungeon_id: string`, `dungeon_grade: int` | **G16** |
| `morning_event_resolved` | `event_type`, `choice: string` (accept/reject) | **G6** |
| `weapon_purchased` | `weapon_id`, `weapon_grade: int`, `price: int` | 인기 무기 파악 |
| `scout_sent` | `dungeon_id`, `armor_type` | **G8** |
| `legacy_upgraded` | `upgrade_key`, `purchase_order: int` | **G10, G20** |

## 레벨 밖 — 운영 이벤트

플레이어 행동이 아니라 빌드 품질을 재는 이벤트라 4단계 체계에 넣지 않는다.

| 이벤트 | 파라미터 | 발행 위치 |
|---|---|---|
| `client_error` | `log_type: string` (Error/Exception/Assert), `message: string` (앞 200자), `stack_head: string` (앞 300자) | `Core/LogPolicy.cs` |

> [!note] 볼륨 제한이 코드에 박혀 있다
> 세션당 최대 20건, 같은 메시지는 세션당 1회만 보낸다. 리포팅 중 발생한 에러가 다시 리포팅을 부르는 재귀도 막혀 있다.

## 열거 값 목록

### `adventure_completed.outcome`

우선순위 순으로 `AdventureResult`의 bool 필드를 매핑한다.

| 값 | 설명 |
|---|---|
| `great_success` | 대성공 (`isGreatSuccess`) |
| `success` | 일반 성공 (`isSuccess`) |
| `failure` | 실패 (무기 손실 없음) |
| `death` | 사망 (`isDeath`) — 무기 손실·게임오버 주요 경로 |
| `retreat` | 후퇴 (`isRetreated`) — 플레이어 판단 |

### `gold_transaction.source`

`EconomyManager.AddGold/SpendGold`의 한국어 `reason` 문자열을 `GetSourceAnalyticsName()`이 아래 값으로 정규화한다. **매핑에 없는 reason은 `other`.**

| `direction` | `source` | 설명 |
|---|---|---|
| earn | `adventure_reward` | 모험 완료 보상 (대여 수수료 포함 — 코드상 `playerGoldReward`에 합산되어 `rental_return` 분리 불가) |
| earn | `morning_event` | 아침 이벤트 수익 (수집가 판매, 투자 결과, 상자, 사절단 선물 등) |
| earn | `quest_reward` | 퀘스트 보상 |
| earn | `legacy_gold_purchase` | 유산 -> 골드 변환 |
| earn | `chore_reward` | 방문자 잡일 보상 |
| earn | `scout_refund` | 수색꾼 환불 |
| earn | `blacksmith_disassemble` | 무기 분해 보상 |
| earn/spend | `dialogue` | 대화 선택지 골드 획득/지출 |
| spend | `weapon_purchase` | 무기 구매 |
| spend | `blacksmith_enforce` | 강화 비용 |
| spend | `blacksmith_evolve` | 진화 비용 |
| spend | `blacksmith_reroll` | 재련 비용 |
| spend | `blacksmith_craft` | 제작 비용 |
| spend | `seer` | 점술가 비용 |
| spend | `scout_dispatch` | 수색꾼 파견 비용 |
| spend | `scout_material` | 수색꾼 재료 구매 |
| spend | `shop_refresh` | 무기 상점 새로고침 |
| spend | `quest_board_refresh` | 의뢰판 새로고침 |
| spend | `quest_fine` | 퀘스트 벌금 |
| spend | `morning_event` | 아침 이벤트 지출 (투자, 상자 구매, 강제납부, 기부, 암시장 등) |
| spend | `adventurer_revive` | 모험가 부활 비용 |
