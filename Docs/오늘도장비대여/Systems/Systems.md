# Systems

> [!abstract] 이 폴더의 역할
> **코드에만 존재하던 기획 요소**(확률·규칙·영향 요소·UI 표시 방식)를 시스템별로 정리한 **기획 레퍼런스**.
> 코드를 몰라도 **① 어떤 기능이 있는지, ② 그 기능이 어느 코드에 구현돼 있는지**를 한곳에서 확인한다.

> [!tip] 찾는 법
> 알고 싶은 주제가 있으면 [주제로 찾기](#주제로-찾기)에서 키워드로 문서를 고르고, 전체를 훑어보려면 [전체 문서 목록](#전체-문서-목록)을 본다.

## 문서 체계 (분할 기준)

도메인 크기에 따라 문서를 나눈다. **새 도메인을 추가할 때 따른다.**

| 분할 | 폴더 | 파일 | 내용 |
|---|---|---|---|
| 대형 | `{도메인}/` | `{도메인}` + `{도메인}_시스템` + `{도메인}_UI` | 지도 / 로직 / 화면 3종 |
| 중형 | `{도메인}/` | `{도메인}_시스템` + `{도메인}_UI` | 로직 / 화면 2종 |
| 소형 | (없음) | `{도메인}` | 시스템+UI 통합 1종 |
| 특대 | `{도메인}/` | 주제별 다분할 | Analytics 7종 |

> [!warning] 파일명은 Vault 전체에서 유일해야 한다
> Obsidian의 `[[문서명]]`은 **파일명**으로 해석되므로, 하위 폴더에 넣더라도 `{도메인}_` 접두사를 유지한다.
> (`모험/시스템.md` 같은 이름은 다른 도메인과 충돌한다.)
