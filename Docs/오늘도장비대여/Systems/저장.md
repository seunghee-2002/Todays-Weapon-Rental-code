# 저장·클라우드

> 게임 데이터를 **기기(로컬)**와 **클라우드**에 보관하고, **기기를 바꿀 때 데이터를 옮기는(복원 코드)** 인프라다.
> 이 문서는 무엇이 어떻게 저장되고, 클라우드와 어떻게 맞춰지며, 기기 간 이전이 어떻게 이뤄지는지를 기획 관점에서 한곳에 정리한다(인프라 도메인이라 시스템·UI를 함께 다룬다).
>
> 각 도메인이 **무엇을** 저장하는지는 해당 문서에서 다룬다. 여기서는 **저장 자체의 구조와 흐름**에 집중한다.

---

## 1. 두 갈래의 저장 데이터

저장 데이터는 성격이 다른 두 종류로 나뉜다.

| 구분 | 담는 것 | 수명 |
|---|---|---|
| 회차 진행 데이터 | 한 회차의 모든 진행 상태(날짜·골드·평판·인벤토리·모험·퀘스트·방문자 등) | **게임오버 시 삭제** |
| 영구 데이터 | 유산 포인트·영구 업그레이드 | **항상 유지** |

- 회차 데이터는 저장할 때 **각 도메인 매니저가 자기 상태를 함께 구워 넣고**, 저장된 시각도 기록한다.
- 두 데이터는 **서로 다른 파일**로 따로 관리된다. 게임오버는 회차 데이터만 지우고 영구 데이터는 남긴다.

> 두 저장의 게임플레이상 의미는 [[유산_시스템]]·[[인벤토리_시스템]] 등에서 다룬다.

---

## 2. 로컬 저장 (기기 안)

- 데이터는 **JSON 파일**로 기기에 저장된다.
- **저장 시점**: 다음 날로 넘어갈 때, 설정에서 저장/나가기를 누를 때 등. 저장 때마다 **현재 시각**이 함께 기록된다(클라우드 동기화 기준).
- **불러오기**: 앱을 켜면 저장 파일이 있을 때 이어서 시작한다.
- **삭제**: 게임오버 시 회차 데이터 파일을 지운다(영구 데이터는 유지). 완전 초기화는 두 파일을 모두 지운다.

---

## 3. 클라우드 저장

기기를 잃거나 바꿔도 데이터를 지키도록 클라우드에도 함께 보관한다.

- **자동 연결**: 앱을 켜면 **익명 계정**으로 서버에 자동 로그인한다(별도 가입·로그인 절차 없음).
- **업로드**: 로컬에 저장할 때마다 클라우드에도 같은 데이터를 올린다(회차 + 영구).
- **오프라인 대응**: 인터넷이 없으면 "**아직 못 올림**" 표시만 남기고, **네트워크가 돌아오면 자동으로 다시 올린다**.
- **메인 메뉴 동기화**: 메인 메뉴에 들어오면 클라우드와 로컬을 비교해 **더 최신(저장 시각 기준)**으로 맞춘다.
- **게임오버 처리**: 게임오버 때는 클라우드의 회차 데이터를 비워, 다음 동기화에서 **끝난 회차가 되살아나지 않게** 한다.

---

## 4. 기기 간 데이터 이전 — 복원 코드

계정이 익명이라 로그인으로 데이터를 따라오게 할 수 없다. 그래서 기기를 바꿀 때는 **복원 코드**로 데이터를 옮긴다.

| 단계 | 동작 |
|---|---|
| 이전 기기에서 코드 생성 | **복원 코드를 만든다**(24시간 유효). 이 기기의 식별값이 곧 복원 코드가 되고, 생성해 둔 동안 **이 기기에서는 복원 입력이 잠긴다**. 코드는 복사할 수 있다. |
| 새 기기에서 코드 입력 | 받은 코드를 입력하면 그 데이터를 **내려받아 적용하고 재시작**한다. |
| 이전 기기 초기화 | 코드가 쓰인 것이 감지되면(주기적 확인 또는 앱 재시작 시) "**다른 기기로 이전됨 — 이 기기는 초기화**"를 알리고 데이터를 비운다. |

- 이렇게 해서 **한 계정의 데이터가 두 기기에 동시에 살아 있지 않도록** 한다.
- 복원 코드 상태는 **활성(24시간 내)·사용됨·만료·없음**으로 구분되며, 사용·만료된 코드는 정리된다.
- **자기 기기의 코드로는 복원할 수 없다**(다른 기기에서만 사용).

---

## 5. 화면 — 데이터 복원

설정에서 데이터 복원 화면으로 들어간다.

| 영역 | 내용 |
|---|---|
| 코드 생성 | "복원 코드 생성" 버튼, 생성 후 내 코드 표시 + 복사 버튼 |
| 코드 입력 | 코드 입력칸과 복원 버튼(입력 상태: 기본 · 입력 필요 · 오류) |
| 상태 표시 | 처리 중 로딩 표시, 안내·경고 토스트 |

- 생성 전 안내: 코드는 **24시간 유효**하며 그동안 이 기기에선 복원이 막힌다고 알린다.
- 복원/사용 불가·만료·오류 상황을 각각 토스트로 알린다.

## 6. 안전장치

- 저장·불러오기·삭제·클라우드 작업은 **실패해도 게임을 멈추지 않는다** — 오류를 잡아 로그만 남기고 진행한다.
- 저장 파일이 깨졌으면 **직전 백업본으로 자동 복구**를 시도한다. 그마저 실패하면 손상 상태로 취급해, 영구 데이터의 경우 **빈 데이터를 클라우드에 덮어쓰지 않는다**(전손 방지).
- 잘못된 저장값(예: 하루 종료 시각 초과)은 불러올 때 **보정**한다([[시간]]).

### 저장 계층 규약 (구현)

저장 관련 코드를 건드릴 때 반드시 지킬 3가지. 데이터 손실 버그가 반복적으로 나왔던 지점이라 공통 장치로 고정해 두었다.

| 규약 | 내용 |
|---|---|
| **원자적 쓰기** | 파일은 `SaveManager.WriteAllTextAtomic`으로만 쓴다 — 임시 파일에 쓰고 `File.Replace`로 교체하며 직전본을 `.bak`으로 남긴다. `File.WriteAllText` 직접 호출 금지(쓰기 도중 종료 시 파일이 깨진다). 저장 API는 성공 여부를 `bool`로 반환한다. |
| **확정 직후 저장** | 도박·재화가 확정되는 지점(강화·진화·재부여·제작·상자·투자·구매·모험 출발/완료/확정·벌금 등)은 처리 끝에 `GameManager.SaveAfterCommittedAction(reason)`을 호출한다. 이게 없으면 결과를 보고 강제 종료해 되돌리는 **세이브 스컴**이 가능하다. |
| **로드 후 sanity pass** | 복원에 실패한 데이터가 잡고 있던 잠금을 로드 직후 푼다 — 드롭된 모험의 무기 `isRented`·모험가 `isAdventuring` 해제(`AdventureManager.RepairDroppedAdventureReferences`), 고아 배정 아이템 반환, 복원 경로의 `isVisiting` 재구성. 폐기된 ID(무기 효과·액티브 아이템 등)는 로드 단계에서 스킵한다. |

- 새 재화·상태를 추가하면 **어느 규약에 걸리는지 먼저 확인**한다. 특히 "즉시 차감하고 나중에 확정"하는 흐름은 확정 시점 저장이 없으면 비용만 소모된 채 저장된다.
- 스폰 풀에서 제외되는 인스턴스(예: 튜토리얼 전용 모험가)는 **별도 저장 경로**가 필요하다 — 참조 ID만 저장하는 데이터(진행 중 모험 등)가 로드 시 대상을 찾지 못해 통째로 드롭된다.
