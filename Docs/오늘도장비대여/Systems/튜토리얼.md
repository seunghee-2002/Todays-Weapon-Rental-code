# 튜토리얼

> 게임을 처음 켠 플레이어가 **길드 경영의 핵심 순환 전체**(무기 구매 -> 강화 -> 아침 이벤트 -> 의뢰 선정 -> 모험 준비·출발 -> 결과 확인 -> 퀘스트·UI 이해)를 한 번에 익히도록 강제하는 **12단계 도입 과정**이다. **1일차 아침에 한 번** 시작한다.
> 이 문서는 튜토리얼이 언제·어떻게 시작되고, 무엇을 강제하며, 어떻게 끝나고(스킵·복원 포함) 무엇을 저장하는지를 기획 관점에서 한곳에 정리한다(소형 도메인이라 시스템·UI를 함께 다룬다).
>
> 튜토리얼 전용 화면은 **길드 전령 대화창**과 **하이라이트 오버레이** 둘뿐이고, 실제 조작은 모두 기존 게임 화면(무기점·대장간·의뢰판·모험 준비·모험 결과·퀘스트 등)을 그대로 재사용한다.
>
> **명칭 규칙** — 전령은 두 명이고 서로 다른 인물이다. 문서·코드 주석에서 그냥 "전령"이라고 쓰지 말 것.
> - **길드 전령** — 튜토리얼 안내역. `TutorialDialogueView`로 말한다. 밝고 상냥한 존댓말, 호칭은 "매니저님". 시세 계단 공지(`PriceTierConfig.stepNotices`)도 이 인물이 같은 대화창으로 전한다.
> - **보고 전령** — 저녁 18:00에 찾아와 모험 결과를 보고하는 방문 NPC(`VisitorType.Herald`). 건조한 보고체. 보고를 다 받아야 다음날로 넘어갈 수 있다.

---

## 1. 언제 시작하나

- **1일차 아침**에 자동으로 시작된다(`VisitorManager`가 아침 NPC 스폰 시 `TutorialManager.StartTutorial()` 호출).
- 시작하면 **게임 시간이 강제로 멈추고**, 길드 전령이 등장해 대화로 안내하며 첫 조작(무기 구매)을 유도한다.
- 동시에 평소와 다른 **무료 무기 상점**이 길드 앞에 방문 NPC로 등장한다.
- 튜토리얼은 **매 회차 1일차마다** 진행된다. 이미 전체를 완주한 계정(영구 플래그)도 시작은 동일하게 하되, 대화창의 **상시 스킵 버튼**으로 언제든 건너뛸 수 있다(3절).

---

## 2. 무엇을 가르치나 (12단계)

각 단계는 대화(길드 전령) -> 하이라이트(대상 지목) -> 플레이어 조작 -> 다음 단계로 이어지는 체인이다. 단계 번호는 `GameData.tutorialStep`(int)에 저장되어 중도 복원 단위가 된다.

| 단계 | 이름 | 가르치는 것 | 남기는 게임 상태 |
|---|---|---|---|
| 1 | 무기상점 | 무료 무기 **4종(검·단검·지팡이·활)** 구매 | 무기 4종 획득 |
| 2 | 대장장이 | 재료 증정 -> 부적 **제작** -> 조잡한 단검 **강화·진화·재부여** | 부적 1개 + 강화/진화/재부여된 단검 |
| 3 | 아침 이벤트 | 길드 사절단 상호작용(선물 수령) -> **아침 스킵**으로 낮 진입 | 사절단 선물, 낮(09:00) 진입 |
| 4 | 의뢰판 | 오늘 던전 매물(A/B/C) 확인·확정 -> **2배 던전** 개념 -> 던전 A **수색꾼 파견** | 의뢰판 확정, 던전 A 수색 파견 |
| 5 | 모험 준비 진입 | 첫 손님(모험가1) 등장 -> 준비 화면 **세 단계 구조** 소개 | (스폰 전용, 영구 결과물 없음) |
| 6 | 모험 보내기 | 무기 조사·종합 테스트 -> 검 대여 -> 부적 선물 -> 던전 A/B/C **비교** -> 던전 A 선택 -> 모험 정보·**점술** -> **출발** | 첫 모험 시작(모험가1 -> 던전 A: 검+부적+점술) |
| 7 | 가방 확인 | 인벤토리 열기 -> **대여중** 토글 -> 대여 무기 확인 | (조회 전용) |
| 8 | 두 번째 손님 | 모험가2 등장 -> 무기 조사(검은 대여 중) -> **활 대여** -> 던전 B **경갑 시뮬레이션** -> 선택 -> 출발 | 둘째 모험 시작(모험가2 -> 던전 B: 활) |
| 9 | 모험 결과 | 모험 진행 관찰 -> **수면 마법**(두 모험 즉시 완료·저녁 18:00) -> 성공(A) 리플레이·**수수료**·재료 매입 -> 실패(B) 리플레이·**무기 파괴** | 두 모험 완료·확정(A 보상·검 반납 / B 활 파괴) |
| 10 | 퀘스트 소개 | 퀘스트 화면 -> 요구/진행/보상 + **벌금·게임오버** 경고 | (조회 전용) |
| 11 | 나머지 UI | 상단바 순차 하이라이트(날짜·시간·골드·평판·배속·유산) | (조회 전용) |
| 12 | 마무리 | 안목(통찰) 언급 -> 작별 -> **20:00로 스킵**(자막 연출) -> 정식 완주 | 시간 정상화, 영구 완주 플래그 |

> **판정·비용은 튜토리얼 내내 고정**된다(각 매니저의 `IsTutorialActive` 가드): 무기/제작/강화/수색/점술 **0원**, 강화·진화 **성공 강제**, 사절단 **선물 고정**, 모험 판정 **A 성공 / B 실패(+활 파괴, 사망 금지)**. 그래서 어느 단계에서 끝나도 결과 상태가 결정적이다.

## 3. 완료와 스킵

튜토리얼의 "완료"는 **두 층위**로 나뉜다.

- **회차별 1단계 완료** — 무료 무기 4종 수령 여부(`GameData.hasReceivedTutorialWeapons`). 게임오버로 회차가 끝나면 초기화되어 **새 회차마다 다시** 진행한다. 무료 상점·방문자 로직의 가드로 쓰인다.
- **영구 완주** — 계정이 12단계 전체를 한 번이라도 마쳤는지(`PlayerData`, `LegacyManager.HasEverCompletedTutorial`). 게임오버로도 초기화되지 않는다. **완주 계정에만 스킵 버튼이 노출**된다.

**단계별 완료 조건**
- 1단계는 **무기 4종을 모두 사야** 넘어간다. 한 종류라도 빠진 채 상점을 닫으려 하면 "네 자루를 모두 구매해야 합니다!" 경고가 뜨고 시간은 멈춘 채 남는다.
- 그 외 단계는 각 단계가 유도하는 조작(제작·강화·파견·대여·출발·닫기 등)을 마치면 자동으로 다음 단계로 넘어간다.

**스킵(완주 계정 전용)**
- 대화창의 상시 스킵 버튼 -> `SkipRemainingTutorial()`. 어느 단계에서든 튜토리얼 전체를 한 번에 종료한다.
- 스킵해도 **정상 완주와 동일한 최종 게임 상태**를 만든다(catch-up, 5절). 즉 스킵 = 두 모험 완료·확정 + 무기/부적/강화 등 밀린 결과물 반영. 열린 패널·튜토리얼 NPC를 정리하고 영구 완주로 처리한다.

## 4. 진행 강제 (잠금·입력 차단)

튜토리얼을 끝내기 전에는 다른 길로 새지 못하도록 막는다.

- **뒤로/닫기(ESC)** — `GuardBack()`이 "튜토리얼을 완료해주세요!" 토스트를 띄우고 막는다.
- **시간 진행** — 미완료 상태에서는 `ShouldBlockTimeResume()`이 시간 재개를 막는다(단계 진입 시 `ForcePause`). 필요한 단계(3단계 아침 스킵, 9단계 진행 관찰, 12단계 20:00 스킵)에서만 코드가 명시적으로 시간을 조작한다.
- **아침 스킵** — 평소엔 잠겨 있고, **3단계 여운 대사 이후에만** 열린다(`IsMorningSkipAllowed`, `VisitorManager.CanSkipMorning`).

### 4.1 오조작·연타 차단 (4개 방어층)

튜토리얼 중 연타·버퍼 클릭이 엉뚱한 UI를 눌러 흐름이 깨지는 것을 막는 다층 방어. 새 단계도 아래 "규칙"만 지키면 자동으로 커버된다.

1. **대화창 오버레이**(`TutorialDialogueView`) — 풀스크린 `advanceButton`이 클릭을 흡수(탭=다음). 대화가 떠 있는 동안 뒤 패널 버튼은 안 눌린다.
2. **하이라이트 필터 + 정착 지연**(`TutorialHighlightView`, `ICanvasRaycastFilter`) — 대상 구멍 외 전체 차단. 추가로 `SetTarget` 직후 `clickSettleDelay`(기본 0.2s) 동안은 **구멍도 막아**, 하이라이트가 뜨는 순간 연타가 즉시 통과하는 것을 방지한다.
3. **배경 차단**(`TutorialInputBlocker`, 매 프레임 폴링) — **빈틈**(대화창·하이라이트가 둘 다 꺼진 전환 순간)이면 배경 raycaster(NPC=`VisitorParent`, 상시UI=`ConsistenceCanvas`)를 끈다.
4. **패널 대기 차단**(`OpenDialogueDeferred` ↔ `SetPanelInputBlocked`) — 대사를 1프레임 미뤄 여는 동안, 패널이 열리기 전부터 대화 오버레이가 실제로 덮은 뒤까지 `PanelCanvas` raycaster를 끈다.

**⛔ 절대 건드리지 않는 것**

- **`PanelCanvas` 상시 차단 금지** — 결과창(강화/진화 결과, 부적 상세, 사절단 결과, `AdventureTalkAnimationPopup` 등)은 **하이라이트 없이 닫기/확인을 눌러 진행**한다. `PanelCanvas`를 빈틈에 끄면 그 버튼들이 죽어 진행 불가가 된다(과거 이 방식으로 2·3·6단계가 막혔다). 패널 차단은 (4)의 짧은 대기 구간뿐이다.
- **`PopupCanvas`**(팝업/토스트) — 경고 팝업 등은 항상 클릭 가능해야 한다.

> **왜 캔버스별 raycaster 토글인가**: 배경/NPC(World, 0) < `PanelCanvas`(100) < `ConsistenceCanvas`(300) < `PopupCanvas`(500). 막을 대상(0·300)이 살릴 대상(100)의 **양쪽에 걸쳐** 있어 단일 blocker로는 불가능하다.

**새 단계를 만들 때 지킬 것**

- 패널을 열고 유도할 땐 **`OpenDialogueDeferred`(인트로 대사) → `ShowHighlight`** 순서. 그러면 (4)가 패널 오픈 창을, (2)가 하이라이트 구멍을 자동으로 덮는다. 패널을 열자마자 대사 없이 `ShowHighlight`만 부르면 오픈 창이 노출된다.
- 유도 클릭은 항상 `ShowHighlight` 경유(정착 지연·구멍 자동 적용). 버튼을 코드로 직접 누르게 두지 말 것.
- 결과/확인 팝업의 닫기·확인은 항상 눌려야 한다. `PanelCanvas`를 막는 새 로직을 넣지 말 것.
- 튜토리얼 중 클릭 가능한 **새 배경 캔버스**가 생기면 그 `GraphicRaycaster`를 `TutorialInputBlocker.backgroundRaycasters`(인스펙터)에 추가한다.

## 5. 저장·복원

튜토리얼 도중 중단되는 경로는 두 가지이고, **동작 원리가 다르다**.

### 5.1 강제종료 -> 불러오기 (경로 B)

- 저장은 **단계 진입 시점에만** 이뤄진다(`SnapshotStepEntry` -> `SaveGame(force:true)`). 그 외 mid-step 자동/수동 저장은 **억제**된다(`GameManager.SaveGame`이 `tutorialStep >= 1`이면 force가 아닌 저장을 건너뜀). 따라서 저장 파일은 항상 "단계 진입 상태"다.
- 재시작하면 `TutorialManager.Initialize(gameData)`가 `tutorialStep`을 읽어 그 단계를 **진입 스냅샷부터 깨끗이 재생**한다(`RestoreTutorialAtStep`: 복원된 패널·방문자를 정리 후 재스폰). 단계 **도중** 조작은 버려지되 재생으로 복구되므로 누수가 원리적으로 없다.
- 독립 진입점이 없는 6단계(5단계에서 연 준비 화면을 이어받음)는 복원 시 **5단계로 remap**해 재생한다.

### 5.2 완주 계정 스킵 (경로 A) — catch-up

- 되돌리지 않고 완주하므로, 밀린 앞 단계의 **영구 게임 상태**를 `ApplyCatchUpOutcomes`가 채워 넣는다(무기 지급·부적 제작·강화·사절단 선물·수색 파견·**두 모험 시작·완료·확정**).
- 어디까지 적용했는지 `GameData.tutorialOutcomeAppliedThrough`로 기억해 **중복 적용을 막는다**. 각 결과물은 멱등(게임 상태 확인 또는 GameData 플래그)이며, 정상 진행이 쓰는 것과 **같은 매니저 API**로 조립한다(튜토리얼 가드 재사용).
- **불변 목표**: 어느 단계에서 스킵하든 = 정상 완주와 **구조적으로 동일한** 최종 상태(모험 수·강화 횟수·부적/점술 유무). reroll 새 효과·점술 랜덤값·사절단 선물 금액·재료 드롭 종류처럼 원리적으로 랜덤인 값은 "동일"의 대상이 아니다.

**핵심 비대칭** — 경로 B(복원)는 진입 스냅샷으로 되돌려 재생하므로 중도 조작 누수가 원리적으로 없다. **문제는 경로 A(스킵)** 다. 되돌리지 않고 완주하므로, 단계 도중 **즉시 커밋된 게임 상태**가 정리되지 않으면 샌다.

### 5.3 단계별 커밋 상태 대장

| 단계 | 즉시 커밋되는 영구 상태 | 스킵(A) 처리 | 복원(B) 처리 |
|---|---|---|---|
| 1 무기상점 | 무기 구매(무료) | `GrantMissingTutorialWeapons`(보유 확인 멱등) | 진입 스냅샷 재생 |
| 2 대장장이 | 재료 지급·부적 제작·강화/진화/재부여 | `ApplyBlacksmithOutcome`(플래그+상태 확인) | 진입 스냅샷 재생 |
| 3 아침이벤트 | 사절단 선물·아침 스킵 | `ApplyMorningEventOutcome`(`hasClaimedTutorialGuildGift`) | 진입 스냅샷 재생 |
| 4 의뢰판 | 의뢰판 확정·수색 파견·완료 | `ApplyQuestBoardOutcome`(`IsConfirmed`/`CanSendScout`) | 진입 스냅샷 재생 |
| 5 준비 진입 | (없음, 모험가 스폰 전용) | no-op | remap → 재스폰 |
| 6 모험 보내기 | **부적 배정**·검 대여·점술·**첫 모험 시작** | `ApplyFirstAdventureOutcome`(검 대여 유무로 멱등 + dangling 부적 회수 + 점술 재현) | `SendAdventure → PrepEnter` remap 재생 |
| 7 가방 확인 | (없음, 조회 전용) | no-op | 진입 스냅샷에 첫 모험 포함 |
| 8 두 번째 손님 | 활 대여·**둘째 모험 시작** | `ApplySecondAdventureOutcome`(활 대여 유무로 멱등) | 진입 스냅샷 + 모험가2 재스폰 |
| 9 모험 결과 | **두 모험 완료·확정**(A 보상·검 반납 / B **활 파괴**) + 재료 매입 | `ApplyAdventureResultOutcome`(확정 시 목록에서 제거되어 멱등) | 진입 스냅샷은 두 모험 진행 중 → 9-A부터 재수행 |
| 10~12 | (없음, 조회·연출 전용) | no-op | 진입 스냅샷 재생 |

- **catch-up 범위** = `[기록된 적용완료 다음 단계 .. 목표-1]`, 기준선은 `GameData.tutorialOutcomeAppliedThrough`. 정상 진행의 `AdvanceTo(step)`도 이 기준선을 올려 자연 플레이로 완료한 단계는 다시 적용하지 않는다.
- **최상위 결과물 단계 = 9**(`HighestOutcomeStep`). 10~12단계는 조회 전용이라 결과물이 없다.
- **비멱등 항목은 GameData 플래그로 방지** — 사절단 선물(`hasClaimedTutorialGuildGift`), 대장장이 재료(`hasGrantedTutorialBlacksmithMaterials`). 나머지는 게임 상태 확인으로 자동 멱등.
- 모든 결과물은 `isTutorialActive == true` 상태에서 **정상 진행이 쓰는 것과 같은 매니저 API**로 조립되므로 각 매니저의 튜토리얼 가드(0원·성공 강제·선물 고정)가 그대로 걸린다.

> 단계별 흐름·대사 전문·고정 데이터는 [[튜토리얼_기획|Completed/튜토리얼_기획.md]] 참조.

**저장되는 튜토리얼 플래그**(모두 `GameData`, 회차별): `tutorialStep`(진행 단계·복원 단위), `hasReceivedTutorialWeapons`(1단계 완료), `tutorialOutcomeAppliedThrough`(catch-up 기준선), `hasClaimedTutorialGuildGift`(사절단 선물 중복 방지), `hasGrantedTutorialBlacksmithMaterials`(대장장이 재료 중복 방지). 영구 완주 플래그만 `PlayerData`(유산)에 저장된다.

## 6. 화면

튜토리얼 전용 화면은 대화창과 하이라이트 오버레이 둘뿐이고, 조작은 기존 게임 화면에서 이뤄진다.

| 요소 | 내용 |
|---|---|
| 길드 전령 대화창(`TutorialDialogueView`) | 12단계 공유 단일 패널. 박스 단위 대사 + 상황별 길드 전령 초상(기본/의문/당황/인사/마법). 풀스크린 탭으로 다음 대사. 완주 계정엔 스킵 버튼 노출 |
| 하이라이트(`TutorialHighlightView`) | 대상 영역만 밝게 남기고 나머지를 딤 + 화살표로 지목. 대상 구멍 외 입력 차단(정착 지연 포함) |
| 경고 팝업 | 4종 미구매로 상점을 닫으려 할 때 "네 자루를 모두 구매해야 합니다!" |
| 무료 무기 상점 | 일반 무기점 화면을 그대로 재사용(매물만 0골드·고정·새로고침 불가) |
| 수면/마무리 암전 오버레이 | 9단계 수면 마법·12단계 20:00 스킵에서 코드가 생성하는 전체 암전(+자막) |

> 대사는 코드 리터럴이 아니라 `TutorialConfig`(SO)의 `TutorialLineKey`별로 관리한다. 조작 1회당 대사 1박스가 원칙이다. 미등록 키는 에러 로그 + 빈 목록(대화가 즉시 닫히고 흐름은 계속 진행).

### 6.1 하이라이트 대상 잡기 (자주 어긋나는 지점)

하이라이트 대상은 **각 View에 `RectTransform` 1줄 게터를 추가**해 코드로 조회한다(인스펙터 마커 미도입 — 수동 부착 누락이 런타임에서만 드러나기 때문). 씬 상주 UI(`TopBarView`/`BottomBarView`)만 `FindObjectOfType` 1회 캐시.

`TutorialHighlightView.SetTarget`은 **대상 위치를 그 시점 1회만** 계산한다. 그래서 다음 경우 하이라이트가 엉뚱한 곳에 잡힌다:

- **레이아웃그룹/스크롤 리스트 안의 동적 요소** → 접근자에서 `LayoutRebuilder.ForceRebuildLayoutImmediate(부모)` 후 반환.
- **방금 `SetActive`된 자식**(예: STR `ArrowGroup`)은 **대상으로 삼지 말 것** — 켜지는 순간 위치가 다음 패스에야 잡힌다. 항상 배치돼 있는 **부모**(예: `StatGroup`)를 대상으로 하고 상위(`StatInfo`)를 리빌드한다.
- **`ScrollRect.ResetPosition` 직후**(탭/토글 전환) — `WaitForEndOfFrame` 코루틴이라 같은 프레임 좌표가 어긋난다. 카드 하이라이트를 **대사 종료 후로 미뤄** 스크롤이 정착한 뒤 잡는다.
- **방금 활성화된 상시 바**(minimalUI 해제 직후 하단바) — `ShowHighlight`가 `OpenPanel` 직후·`SetTarget` 직전에 `Canvas.ForceUpdateCanvases()`로 전역 확정한다.
- **하이라이트보다 나중에 열리는 팝업**(재료 매입 팝업, 던전 상세 등)은 하이라이트를 덮는다 → 하이라이트를 **닫고 다시 열어** 팝업 위로 올린다.
- 카드 위 드래그로 목록이 밀리는 것은 `SetXxxScrollLocked`로 잠갔다가 선택 완료 시 해제한다.

> **레이아웃 구조가 애매해 리빌드 필요 여부나 대상 부모가 불확실하면, 추측하지 말고 사용자에게 물어 확인한다.**

## 7. ⛔ 새 단계를 추가할 때 (작업 규칙)

> **새 튜토리얼 단계(또는 기존 단계에 즉시 커밋되는 상태 변경)를 추가하면, catch-up도 같은 작업에서 반드시 함께 갱신한다.**
> CLAUDE.md의 "StaticData(SO) ↔ CSV Importer 동기화"와 같은 성격의 동기화 규칙이다. 빠뜨리면 빌드는 통과해도 **완주 계정이 스킵했을 때만 상태가 조용히 달라지는** 버그(모험 누락·아이템 누수)가 난다. 6~8단계에서 실제로 발생했다.

### 착수 전 반드시 답할 3가지

1. **이 단계가 즉시 커밋하는 영구 게임 상태가 있는가?**
   - "즉시 커밋" = 매니저 API가 인벤토리/골드/모험/배정 등 `GameData`에 반영되는 상태를 그 자리에서 바꾸는 것. (`ActiveItemManager.AssignItem`은 인벤에서 즉시 제거, `AdventureManager.StartAdventure`는 모험 생성, `BlacksmithManager.Execute*`는 무기/재료 변경.)
   - **펜딩 상태**(컨트롤러 지역 변수, 예: `pendingRentWeapon`)는 출발 전까지 커밋되지 않으므로 스킵 시 패널 닫힘으로 자동 폐기 — 안전.
2. **커밋되는 상태가 있다면 catch-up이 그것을 실현/정리하는가?**
   - 실현: `HighestOutcomeStep`을 그 단계까지 올리고 `ApplyStepOutcome` switch에 케이스 추가(결과물 없으면 `break`). `ApplyXxxOutcome`은 **멱등**(게임 상태 확인 또는 GameData 플래그)이어야 하고, 정상 진행이 쓰는 것과 **같은 매니저 API**로 조립한다.
   - 정리: 유령 대상에 귀속된 dangling 상태는 회수한다(준비화면 도중 스킵 시 부적이 유령 모험가에 배정된 채 남으므로 `ReturnAllAssignedItems`로 회수 후 실제 모험에 재배정).
3. **복원(경로 B) 시 그 단계 진입점이 스냅샷에 없는 상태를 전제하지 않는가?**
   - `StartStepXxx`가 전제하는 상태(예: 7·8단계는 "첫 모험 진행 중", 9단계는 "두 모험 진행 중")는 반드시 **직전 단계의 진입 스냅샷에 이미 굳어 있어야** 한다.
   - 독립 진입점이 없는 단계는 `RestoreTutorialAtStep`에서 앞 단계로 remap해 재생한다(현재 `SendAdventure → PrepEnter`).

### 검증도 함께

여러 단계에서 스킵한 결과와 정상 완주 결과를 대조한다. 위 [5.3 대장 표](#53-단계별-커밋-상태-대장)와 코드(`HighestOutcomeStep`·`ApplyStepOutcome`)를 **동시에** 갱신한다.
