# 사운드

> 배경음악(BGM)과 효과음(SFX)의 **구조**, 플레이어가 곡을 고르는 **사운드 변경 기능**, 등록된 소리 목록과 붙이는 방법을 담는다.
> 소리마다 **이름표(키 문자열)** 가 붙어 있고, 각 화면·연출은 이름으로 소리를 부른다. 코드 기준이며 문서가 코드와 다르면 코드가 맞다.

---

## 1. 사운드 구조

`SoundManager`는 `DontDestroyOnLoad` 단일 싱글톤이며 **실체는 MainMenuScene에만 존재**한다.
InGameScene에는 SoundManager 오브젝트가 없다 -> **슬롯 추가/삭제는 MainMenuScene에서만 한다.**

AudioSource는 전부 코드에서 생성한다(인스펙터 배선 불필요). BGM 3개 + SFX 풀 5개.

### 1-1. BGM - 3레이어 우선순위 구조

동시에 세 층의 음악이 겹칠 수 있고, 위층이 울리면 아래층은 자동으로 작아진다.

| 레이어 | 진입점 | 동작 |
|---|---|---|
| **1. 배경음** | `PlayBaseBGM(key)` | 항상 재생(loop). 테마가 활성이면 볼륨 0으로 더킹, 테마 종료 시 페이드인 복원 |
| **2. 테마음** | `EnterTheme(key)` / `ExitTheme(key)` | 상황별 배경음. **스택 top**을 재생. 스택이 비면 정지 + 배경음 복원 |
| **3. 스팅어** | `PlayStinger(key)` / `StopStinger()` | 순간 강조음 1회. 재생 중 하위 레이어를 더킹하거나 정지, 끝나면 복원 |

- 스택 방식이라 패널이 겹쳐 열려도 최상단 패널의 테마가 들리고, 닫으면 이전 테마로 되돌아간다.
- `ExitTheme(key)`는 LIFO로 **해당 키만** 제거한다(중간 패널이 먼저 닫혀도 순서가 깨지지 않음).
- 등록되지 않은 키로 `EnterTheme`하면 **push하지 않는다** - 배경음이 무음으로 더킹된 채 남는 사고를 막는다.
- 스택은 `(논리 키, 확정 키)` 쌍을 담는다. 변형 그룹(2장)은 **push 시점에 곡이 확정**되므로, 위에 열린 패널이 닫혀도 같은 곡으로 돌아온다.
- 스팅어의 하위 레이어 처리는 `StingerMode`로 A/B 테스트 가능: `DuckTheme`(겹쳐 재생, 현재 설정) / `PauseTheme`(완전 정지). 더킹 볼륨 0.1, 복원 2초.
- 페이드 시간 `bgmFadeDuration` 현재 0.5초. 페이드는 `unscaledDeltaTime` 기준이라 배속/일시정지와 무관.

### 1-2. 씬 · 페이즈 자동 연동

| 시점 | 재생 |
|---|---|
| MainMenuScene 진입 | 배경음 `MainMenu` |
| InGameScene 초기화 | 현재 페이즈에 맞는 배경음 (아래) |
| 페이즈 -> 아침 | 배경음 `HomeMorning` |
| 페이즈 -> 낮 | 배경음 `HomeLoop` |
| 페이즈 -> 저녁/밤 | 낮 배경음 유지 (전환 없음) |

넘기는 것은 전부 **변형 그룹의 논리 키**다. 실제 곡은 플레이어 선택(2장)이 정한다.

씬 전환 시 테마 스택·스팅어·SFX 억제 플래그를 모두 리셋한다(패널이 Close를 안 타고 파괴되므로).

### 1-3. SFX

- 진입점: `PlaySFX(string clipName, float pitch = 1f, bool ignoreSuppression = false)`
- **무음 처리 3가지 (의도된 동작)**
  1. `clipName`이 빈 문자열 또는 `"NULL"` -> 무시. Config에서 "끄기"를 표현할 때 `"NULL"`을 쓴다.
  2. `SuppressSFX(true)` 구간 -> 묵음 (`ignoreSuppression: true`로 관통 가능)
  3. **게임 배속 4배 초과** -> 스킵. 빠른 진행 중 효과음이 쏟아지는 것을 막는다.
     > ⚠️ 이 판정은 `TimeManager.CurrentTimeScale`(게임 시간 배속)만 본다. **모험 다시보기의 배속은 View 로컬 값이라 이 가드를 타지 않는다**(5장).
- **변형 클립 랜덤:** 이름이 숫자로 끝나는 슬롯은 접두사로 묶여, 정확한 키가 없을 때 그중 하나를 랜덤 재생한다. 현재 유일 사례는 `Battle1~5` -> `PlaySFX("Battle")`.
  > ⚠️ **이 변형 랜덤은 SFX 전용이다.** `PlayBaseBGM`/`EnterTheme`/`PlayStinger`는 딕셔너리를 직접 조회하므로 변형 그룹을 타지 않는다.
- AudioSource 풀 5개를 라운드로빈. pitch는 소스 단위 속성이라, 재생 중 소스에 다른 pitch를 넣어야 할 때만 기존 재생을 끊는다(보이스 스틸링).

### 1-4. 볼륨 · 음소거

- BGM·SFX 각각 별도로 조절한다. `PlayerData`(영구 저장)에 보관하며 앱 시작 시 1회 로드한다 -> 회차와 무관하게 유지된다([[저장]]).
- 슬라이더 값이 0이 되면 음소거와 동일하게 취급하고, 음소거를 해제할 때 볼륨이 0이면 0.5로 되돌린다.

## 2. 사운드 변경 기능

같은 상황에 곡이 여러 개인 슬롯은 **플레이어가 어느 곡을 들을지 고를 수 있다.**

### 2-1. 변형 그룹 - 곡이 정해지는 규칙

슬롯을 `기본키 + 번호`로 등록한다(`WeaponShop1`, `WeaponShop2`). 호출부는 번호 없는 **논리 키**(`"WeaponShop"`)만 넘기고, `ResolveBgmKey()`가 실제 곡을 정한다.

```
정확한 키가 clipDictionary에 있으면        -> 그대로 재생 (변형 없는 슬롯, 미리듣기)
변형 그룹이고 선택값이 특정 곡이면         -> 그 곡 재생
변형 그룹이고 선택값이 RANDOM이면          -> 그룹 중 랜덤 1곡
```

- 선택은 `PlayerData.bgmVariantSelections`(baseKey -> `"RANDOM"` 또는 정확한 키)에 **영구 저장**된다. 항목이 없으면 그룹의 `defaultRandom`을 따르므로 **기존 세이브는 종전 동작 그대로**다.
- 노출 그룹은 MainMenuScene -> `SoundManager` -> `Bgm Variant Groups`에서 정한다(`baseKey` / `displayName` / `defaultRandom`).

**현재 등록된 변형 그룹 6개**

| 표시 이름 | 논리 키 | 곡 수 | 기본값 |
|---|---|---|---|
| 메인 메뉴 | `MainMenu` | 2 | 1번 고정 |
| 아침 | `HomeMorning` | 2 | 1번 고정 |
| 낮 | `HomeLoop` | 5 | 랜덤 |
| 무기 상점 | `WeaponShop` | 2 | 1번 고정 |
| 대장장이 | `Blacksmith` | 4 | 1번 고정 |
| 모험 준비 | `AdventurePrepare` | 4 | 랜덤 |

### 2-2. BGM 변경 화면 (`BGMChangeView`)

- **진입:** 옵션 팝업의 `BGM 변경` 버튼. 인게임(`OptionPopupView`)과 메인메뉴(`MainMenuOptionView`) 양쪽에 있다.
- **행 구성:** 위 변형 그룹마다 한 행(`BGMChangeItem`). `그룹 표시 이름 + 현재 선택 + 좌우 이동 버튼`.
  - 선택지 순서는 `랜덤` -> 번호순 변형 키. 목록 양 끝에서는 해당 방향 버튼을 숨긴다.
  - 현재 선택 표시는 **슬롯 키 문자열 그대로**다(`랜덤`, `Blacksmith1`, `Blacksmith2` ...).
  - 등록된 변형 클립이 하나도 없는 그룹은 행을 만들지 않고 경고 로그만 남긴다(슬롯 이름 오타 방지).
- **즉시 적용:** 좌우 버튼을 누르면 그 자리에서 선택이 반영되고 `PreviewBgm()`으로 미리듣기가 재생된다. **저장 버튼이 없다.**
  - 지금 흐르는 배경음/테마가 그 그룹이면 곡을 즉시 교체하고, 스택 아래에 잠긴 항목의 확정 키도 같이 갱신한다.
- **미리듣기는 테마 스택 최상단을 점유**한다(전용 예약 키 `__BGM_PREVIEW__`). 창을 닫을 때 `StopBgmPreview()`로 짝을 맞춘다.
- **저장 시점:** `Close()`에서 미리듣기를 끄고 `SyncSettingsToPlayerData()` + `SaveLegacy()`를 호출한다. 닫기 버튼·ESC·오버레이 클릭 어느 경로로 닫혀도 저장된다.
  > `OnEscapeClicked`를 오버라이드하면 `Close()`가 두 번 돌아 저장이 중복되므로 오버라이드하지 않는다.

### 2-3. 곡 추가 · 그룹 신설

- **기존 그룹에 곡 추가:** `Bgm Clips`에 다음 번호로 슬롯만 추가한다(`Blacksmith5`). 코드·`Bgm Variant Groups` 수정 없이 BGM 변경 화면에 자동으로 나타난다.
- **새 그룹 신설:** 기존 단일 슬롯 이름을 `키1`로 바꾸고(`WeaponShop` -> `WeaponShop1`) 나머지 곡을 추가한 뒤, `Bgm Variant Groups`에 한 줄 등록한다. 호출부는 논리 키를 쓰므로 코드는 그대로 둔다.

## 3. 등록 슬롯

MainMenuScene -> `SoundManager`의 `Sfx Clips`(39개) / `Bgm Clips`(40개).

### 3-1. SFX - 호출 경로

- **코드** - 소스에 문자열이 하드코딩됨
- **Config** - `AdventureResultMotionConfig.asset`의 키로만 재생 (인스펙터에서 교체 가능)
- **인스펙터** - 프리팹/씬의 `SfxButton` 컴포넌트

#### UI · 팝업

| 슬롯 | 경로 | 언제 울리나 |
|---|---|---|
| `ButtonClick` | 인스펙터 + 코드 | `SfxButton` 부착 버튼(**현재 13개뿐**) / 옵션 슬라이더 조작 |
| `PopupWarning` | 코드 | 경고·거부 팝업·토스트 (골드 부족, 인벤 가득, 실패 등) |
| `PopupConfirm` | 코드 | 확인/취소 팝업 (`ShowPopup` 기본값) |
| `PopupNotify` | 코드 | 일반 알림 토스트 (`ShowToast` 기본값) |

팝업 소리는 `UIPopupController`의 `PopupSfxType { Warning, Confirm, Notify }`로 결정된다.
`ShowPopup` 기본 `Confirm`, `ShowToast` 기본 `Notify`, `ShowLegacyGoldPurchase`는 `Confirm` 고정.
전체 호출처 90곳 중 **기본값과 다른 43곳에만** 인자를 명시했다(Warning 34 + Notify 9).

#### 방문자 · 모험가

| 슬롯 | 경로 | 언제 울리나 |
|---|---|---|
| `VisitorEnter` | 코드 | 방문객 입장 (3개 지점) |
| `VisitorLeave` | 코드 | 방문객 퇴장 |
| `NamedAdventurer` | 코드 | 네임드 모험가 등장 연출(`EffectManager`가 파티클과 함께) |
| `SeerConsult` | 코드 | 점술가 의뢰 |
| `AdventureStart` | 코드 + Config | 모험 파견 확정 / 다시보기 던전 입장(`entrySfxKey`) |

#### 대장간

| 슬롯 | 경로 | 언제 울리나 |
|---|---|---|
| `Upgrading` | 코드 | 작업 진행 게이지가 도는 동안 (3개 지점) - 강화·진화, 제작, **2차 대화**(`AdventureTalkAnimationPopup`) |
| `BlacksmithSuccess` | 코드 | 강화·진화 성공 |
| `BlacksmithFailed` | 코드 | 강화·진화 실패 |
| `Craft` | 코드 | **제작 완료** (제작은 결과창이 없어 이 소리가 유일한 완료 피드백) |

#### 모험 진행 연출 (다시보기 노드)

전부 `AdventureResultMotionConfig`의 키로 재생된다. 코드에 문자열이 없으므로 **asset에서 키를 바꾸면 소리가 바뀐다.**

| 슬롯 | asset 필드 / 노드 | 언제 울리나 |
|---|---|---|
| `Run` | `runSfxKey` | 노드 사이 이동 - **노드 수만큼 반복** |
| `Pass` | 노드 `sfxKey` ×6 | 입장·함정 회피·후퇴·재도전·귀환·보호 발동 노드. 한 번의 다시보기에서 가장 자주 울림 |
| `Battle` | 노드 `sfxKey` ×2 | 일반 전투·중간보스 시작 -> `Battle1~5` 중 랜덤 |
| `BattleSuccess` / `BattleFailed` | 노드 `successSfxKey` / `failSfxKey` | 전투 승패 |
| `Hit` | Trap 노드 `sfxKey` | 함정 피격 |
| `Restore` | Rest 노드 `sfxKey` | 휴식 회복 |
| `GetItem` | 노드 `sfxKey` ×2, `materialCollectSfxKey` | 보물상자·희귀 드롭, 재료 획득 |
| `BossImpact` | `bossImpactSfxKey` | 보스 등장 충격 |
| `BossKill` | Boss 노드 `successSfxKey` | 보스 처치 |
| `BossRetry` | `bossRetrySfxKey` | 보스 재도전 |
| `ProtectionGained` | `protectionActivatedSfxKey` | 보호 **획득**(Rest 충전) / **발동**(차감) 양쪽. 한 키를 공유하므로 둘이 같은 소리다 |
| `Success` | `exitSuccessSfxKey` | 모험 성공 귀환 |

- **사망 퇴장은 무음이다.** 전용 SFX 키 필드를 두지 않으며(제거됨), 사망 피드백은 결과창의 `AdventureFail`이 담당한다.

#### 모험 결과 정산

| 슬롯 | 경로 | 언제 울리나 |
|---|---|---|
| `AdventureSuccess` | 코드 | 결과창 성공 |
| `AdventureGreatSuccess` | 코드 | 결과창 대성공 |
| `AdventureFail` | 코드 | 결과창 실패·사망 (2개 지점) |
| `GetGold` | 코드 | 골드 연출 - 아래 4종 |
| `GetItem` | 코드 | 결과 아이템 컨테이너(평판·호감도·재료) 등장 |

**`GetGold` 재생 지점** (스킵 시에는 전부 무음)

| 지점 | 횟수 |
|---|---|
| 전체 획득 카운트업 | 1회 |
| 페널티 카운트다운 | 페널티가 있을 때 1회 |
| 수수료 요약 행 등장 | 행당 1회 (기본 수수료 항상 + 무기 대여/상성 팁/특성 수수료 각 조건부 -> 1~4회) |
| 플레이어 수령 카운트업 | 1회 |

한 결과창에서 총 **3~7회**. 행 간격은 스케일 0.18초 + `rowDelay` 0.2초라 소리가 뭉치지 않는다.

- 결과 성공/실패음은 `PlayResultSfxOnce`로 **결과창당 1회**만 보장된다.
- 다시보기에서 골드가 날아와 꽂히는 소리는 위 결과창 호출이 아니라 `RewardFlyAnimator`의 `arrivalSFX`(인스펙터 지정, 현재 `GetGold`)다.
  - **pitch를 다시보기 배속에 맞춰 올려 재생한다** -> 배속에서 음이 찢어지고 노드마다 반복되므로 **2배속 이상에서는 재생하지 않는다**(`ArrivalSfxMaxSpeed = 2f`). 재생 자체를 막을 뿐 골드 비행 연출은 그대로 돈다.

| 슬롯 | 경로 | 언제 울리나 |
|---|---|---|
| `GameStart` | 코드 | 메인메뉴 -> 인게임 씬 진입. `SceneController.LoadGameScene()` 한 곳에 두어 **이어하기·새 게임 양쪽**을 덮는다 |
| `Buy` | 코드 | 골드를 치르는 거래 성공 - **8개 지점**(아래) |
| `GetGift` | 코드 | 아이템을 선물받는 순간 - 길드 사절단 선물 분기, 수수께끼 상자 개봉 결과 |
| `DoubleDungeon` | 코드 | 의뢰판 확정 연출에서 2배 던전 강조 - **던전 1개당 1회**(0.18초 간격) |
| `ScoutStart` | 코드 | 의뢰판 수색 파견 실행 - 파견 개수 무관 1회 |

**`Buy` 호출처 8곳** (동전 찰랑 소리. 전부 성공이 확정된 뒤 재생)

| 지점 | 위치 |
|---|---|
| 무기 구매 | `WeaponShopDetailController.DoPurchaseWeapon` |
| 무기 상점 새로고침 | `WeaponShopController.DoRefreshShop` |
| 의뢰판 새로고침 | `QuestBoardController.DoRefreshBoard` |
| 무기 재부여(리롤) | `BlacksmithController.ExecuteReroll` |
| 재료 구매 - 개별 / 일괄 | `AdventureResultController.ExecuteSinglePurchase` / `.ExecuteBuyAll` (일괄은 품목 수와 무관하게 1회) |
| 암시장 무기 구매 | `BlackMarketEventView.DoBlackMarketBuy` |
| 수수께끼 상자 구매 | `MysteryBoxEventView.DoBoxBuy` |

- `Buy`는 **"값을 치르고 무언가를 얻는 거래"** 에만 붙였다. 벌금 납부·길드 강제 납부·난민 기부·투자자 투자·모험가 부활·대화 지출은 성격이 달라 제외했고(별도 소리가 어울림), 강화·진화·제작(`Upgrading`/`Craft`)·점술가(`SeerConsult`)·수색 파견(`ScoutStart`)은 이미 전용 소리가 있어 제외했다.
- **`EconomyManager.SpendGold()` 전역 훅을 쓰지 않은 이유:** 코드는 한 줄로 끝나지만 ⑴ 수색 파견이 던전 수만큼 `SpendGold`를 반복 호출해 코인 소리가 N번 쏟아지고, ⑵ 위 전용 소리들과 겹치며, ⑶ 뜯기는 지출에도 구매음이 난다.
  > `EconomyManager`의 `OnGoldAdded` / `OnGoldSpent` 이벤트는 선언만 되어 있고 **구독자가 0명**이다. 훅을 붙인다면 이 자리가 후보다.
- 수수께끼 상자는 `Buy`(구매) -> 개봉 애니메이션 1.5초+ -> `GetGift`(결과) 순으로 두 소리가 이어진다.
- `DoubleDungeon`은 스킵 분기와 세이브 복원 경로(`ApplyConfirmedState`의 `skipAnimation`)에는 넣지 않았다 - 스킵인데 소리가 쏟아지거나 재접속마다 울리는 것을 막기 위함.

## 4. 소리를 붙이는 방법

### 4-1. 판단 기준

```
그 소리가 "버튼을 눌렀다"는 사실 자체에 대한 피드백인가?
  ├─ YES -> SfxButton 컴포넌트 (인스펙터, 핸들러 코드 무수정)
  └─ NO  -> 상황에 따라
            ├─ 패널이 열려 있는 동안 계속 흐르는 배경음  -> GetThemeBgmKey() 오버라이드
            ├─ 순간 강조음(성공/실패 팡파레)              -> PlayStinger
            └─ 연출 타이밍 / 매니저 상태 변화              -> PlaySFX 직접 호출
```

### 4-2. 버튼 클릭 - `SfxButton`

`Button`에 부착하고 `clipName`만 지정하면 끝. 기존 `onClick` 리스너와 별개로 동작해 핸들러 코드를 건드리지 않는다.

> ⚠️ 다수 View가 `UnsubscribeEvents()`에서 `onClick.RemoveAllListeners()`를 호출한다. 그래서 `SfxButton`은 **`Awake`가 아니라 `OnEnable`에서 매번 재등록**한다 - 안 그러면 두 번째 열림부터 클릭음이 사라진다. 이 구조를 바꾸지 말 것.

**Toggle에는 쓸 수 없다.** 탭·필터는 `Button`이 아니라 `Toggle`(`onValueChanged`)이므로 별도 컴포넌트가 필요하다(미구현, 5장).

### 4-3. 패널 테마 BGM

```csharp
// 단일 슬롯
protected override string GetThemeBgmKey() => "Seer";

// 변형 그룹 - 논리 키만 넘기고 곡 선택(고정/랜덤)은 SoundManager가 처리 (2장)
protected override string GetThemeBgmKey() => "Blacksmith";

// Open 이후에야 키가 정해지는 경우(던전 등급 등)
SetActiveThemeBgm($"AdventureReplay{adventure.dungeon.grade}");   // GetThemeBgmKey와 병용 금지
```

`BaseView`를 상속하지 않는 팝업(Instantiate 계열 등)은 이 경로를 타지 않는다 -> 필요하면 직접 `EnterTheme`/`ExitTheme`하되 **짝을 반드시 맞춘다**(안 맞추면 배경음이 무음 더킹된 채 남는다).

### 4-4. 호출 위치 규칙 (레이어 준수)

- Manager는 View/Controller를 모른다. SFX 호출은 가급적 **이벤트 구독측(View/Controller)** 에서.
- 단 `SoundManager`/`EffectManager`는 Manager끼리 호출 OK. 순수 "소리"라면 도메인 매니저에서 `SoundManager.Instance?.PlaySFX(...)` 직접 호출도 허용(선례 있음).
- 이벤트가 이미 있으면 구독측에서, 없으면 트리거 지점에서.

### 4-5. 새 슬롯 추가 절차

1. 오디오 파일을 `Assets/_Projects/Audio/SFX/` 또는 `Audio/BGM/`에 넣는다.
2. **MainMenuScene** -> `SoundManager` -> `Sfx Clips` 또는 `Bgm Clips`에 `{clipName, clip}` 추가.
3. 코드/인스펙터에서 문자열로 참조. **enum·상수가 없으므로 오타 주의** - 오타는 컴파일 통과 후 런타임 경고 로그로만 드러난다.

## 5. 남은 작업

### 5-1. ★ 가장 큰 누락 - 버튼 클릭음

`SfxButton`이 부착된 버튼은 **프로젝트 전체에 13개뿐**이다(옵션 팝업 4, 메인메뉴 옵션 3, 닉네임 변경 2, InGameScene 4). 반면 코드에서 클릭 핸들러를 등록하는 버튼은 225곳(89개 파일)이라 **상점·대장간·인벤토리·모험준비·아침이벤트·퀘스트의 버튼은 대부분 무음**이다.

- 공용/주요 버튼 프리팹에 `SfxButton`을 일괄 부착하는 작업이 남아 있다. 코드 수정은 필요 없다.
- **`SfxToggle` 미구현** - 탭·필터 토글용 컴포넌트가 없다. 탭 전환/필터 on-off는 전부 무음.
  > 만들 때 주의: `SetIsOnWithoutNotify`를 쓰는 초기화 코드는 이벤트를 안 쏘므로 소리가 안 난다(의도대로 좋음). 반면 `isOn = true` 직접 대입은 이벤트가 발생해 초기화 중에도 소리가 난다.
- **비활성 버튼 클릭(거부음)** 도 미구현. Unity `Button`은 `interactable=false`면 `onClick` 자체가 안 불리므로 `SfxButton`으로 못 잡는다 -> 핸들러 쪽에서 별도 처리해야 한다. 현재는 무반응이라 "눌렸나?" 헷갈린다.

### 5-2. 다시보기 배속에서 SFX 억제가 안 걸린다

`SoundManager`의 "배속 4배 초과 스킵"은 `TimeManager.CurrentTimeScale`을 본다. 그런데 모험 다시보기 배속은 `AdventureReplayView`의 로컬 값(1 -> 2 -> 4 순환)이고 최대치가 딱 4배이므로 **이 가드가 한 번도 걸리지 않는다.** 4배속에서 `Run`/`Pass`가 4배 빠르게 그대로 쏟아진다.

- **골드 도착음은 처리됐다** - `RewardFlyAnimator`가 2배속 이상에서 재생을 건너뛴다(3-1 참고). pitch까지 올라가 가장 거슬리던 소리였다.
- 남은 후보는 `Run`/`Pass`다. 대안: 다시보기가 2배 이상일 때 `SuppressSFX`를 걸거나, `Run`만 배속 구간에서 스킵.
- 그래도 산만하면 슬롯을 끄는 쪽으로 간다. **끌 후보는 `Run`** - 달리는 건 눈에 보이니 정보량이 0이다. `Pass`는 "이 노드는 별일 없었다"를 알려주므로 남긴다.

### 5-3. 아직 안 붙은 순간들

| 대상 | 비고 |
|---|---|
| 보호 획득 / 발동 구분 | 둘 다 `ProtectionGained` 한 키를 쓴다. 구분하려면 전용 클립 + Config 필드 추가 필요 |
| 2차 대화 성공·실패 시 | 진행 중 연출음은 `Upgrading`으로 붙었고, **결과 페이즈**가 아직 무음 |
| 아이템 대여·선물 시 | |
| TopBar 배속 버튼 | 클릭 빈도 최상위 컨트롤인데 무음 |
| 페이즈 전환(낮/저녁) | 이미 토스트를 띄우므로 소리만 붙이면 됨. 아침은 배경음 전환으로 대체됨 |
| 평판 등급 상승 | 승급 팡파레. `OnReputationLevelChanged`를 **구독하는 UI가 아직 없다** |
| 손님 참을성 한계 경고 / 화내며 퇴장 | `VisitorLeave`와 구분되는 소리 |
| 퀘스트 실패 / 수락 | |
| 정찰(수색) 결과 도착 | 파견 시작음(`ScoutStart`)은 붙었으나 **도착 시점**은 아직 무음 |
| 게임오버 | 엔딩 BGM 또는 스팅어 |
