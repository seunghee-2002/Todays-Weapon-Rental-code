# 일반 모험가 피부색을 8색 균등 -> 인종 비율 가중 추첨으로 (황인 85 / 백인 14 / 흑인 1)

> 기록: 2026-07-29 · 작성: /balance

## 근거 (왜)

**사용자 지시.** 등장하는 모험가의 피부색 비율을 **황인 85% / 백인 14% / 흑인 1%** 로 맞춘다.

기존 `skinColorPalette` 는 8색 단일 리스트를 `Random.Range` 로 균등 추첨했다.
같은 8색을 인종 기준으로 갈라 보면 실질 비율이 **황인 62.5% / 백인 25% / 흑인 12.5%** 였다.
백인이 목표의 약 1.8배, 흑인이 약 12배 나오던 상태다.

### 이 변경이 직업 정보를 흘리지 않는지 확인했다

외형 파츠 분류 작업(`Documents/외형_파츠_분류_기준.md`)의 확정 결정 Q3는
**"외형은 힌트여야 하며 최고 스탯을 확정시키면 안 된다"** 이다. 색상이 여기 걸리는지 점검했다.

`GetRandomSkinColor()` / `GetRandomHairColor()` 는 **인자를 하나도 받지 않는다.**
직업(`AdventurerJobType`)도 성별(`Gender`)도 참조하지 않으므로
**색상은 직업 정보를 전혀 흘리지 않는다.** 가중치를 넣어도 이 성질은 그대로다.

> 색상에 붙은 유일한 연결은 `beardColor = hairColor`, `browColor = hairColor x 0.8` 인데,
> 힌트를 흘리는 것은 색이 아니라 **수염 유무**다(남성 INT 80% / 나머지 20%).
> 이는 [[2026-07-29_외형_맨발확률|맨발 확률 조정]] 에서 허용 대역(57%)으로 이미 판정된 항목이다.

## 대상 시스템 (무엇을)

- **외형 생성**(`AppearanceGenerator.Generate` -> `AppearanceGeneratorData.GetRandomSkinColor`)
  — 일반 모험가 랜덤 외형의 Skin 색상
- 골드·성공률·평판·통찰에는 영향 없음. **순수 표현 계층 변경이다.**

### 적용 범위 (중요)

이 확률은 **랜덤 외형 경로에만** 걸린다.

| 대상 | 경로 | 팔레트 적용 |
|---|---|---|
| 일반 모험가 20종 | `AppearanceGenerator.Generate` | **적용** |
| 길거리 Walker NPC | `VisitorManager.Walker.cs:207` -> `Generate` | **적용** |
| `ADV_NAMED_001~008` (8종) | `GenerateFromFixed` | 미적용 - SO에 색상 고정 |
| `ADV_TUTORIAL_001~002` (2종) | `GenerateFromFixed` | 미적용 - SO에 색상 고정 |

`AdventurerData` 30개 중 `partsIndices` 가 차 있는 10개는 고정 외형이라 팔레트를 쓰지 않는다.
**이 10종의 피부색을 85/14/1에 맞추려면 각 SO를 개별 수정해야 한다. 이번에 하지 않았다.**

## 수정 전후 (어떻게)

### 구조

| 항목 | 전 | 후 | 위치(파일:필드) |
|---|---|---|---|
| 팔레트 필드 | `skinColorPalette` (8색 1개) | `skinColorAsian`(5) / `skinColorWhite`(2) / `skinColorBlack`(1) | `AppearanceGeneratorData.cs` |
| 황인 비율 | (없음) | `0.85f` | `AppearanceGeneratorData.skinRatioAsian` (신설) |
| 백인 비율 | (없음) | `0.14f` | `AppearanceGeneratorData.skinRatioWhite` (신설) |
| 흑인 비율 | (없음) | 나머지 `0.01` (암묵) | 별도 필드 없음 |
| 추첨 방식 | 8색 균등 `Random.Range` | 그룹 가중 추첨 -> 그룹 내 균등 | `AppearanceGeneratorData.cs:GetRandomSkinColor` |

| 그룹 | 색 (RGB 0~255) | 개수 |
|---|---|---|
| 황인 | (251,227,209) (243,201,173) (224,172,105) (213,160,125) (198,134,66) | 5 |
| 백인 | (255,245,235) (255,237,228) | 2 |
| 흑인 | (141,85,36) | 1 |

### 등장 확률 검산

| 그룹 | 전 | 후 | 색당 확률(후) |
|---|---|---|---|
| 황인 | 62.5% (5 x 12.5%) | **85%** | 17.0% |
| 백인 | 25.0% (2 x 12.5%) | **14%** | 7.0% |
| 흑인 | 12.5% (1 x 12.5%) | **1%** | 1.0% |

## 시뮬 / 검증 근거

**시뮬 없음.** 골드·평판·R 지표에 영향이 없는 표현 계층 변경이라 BalanceSim 대상이 아니다.
판단 근거는 사용자가 지정한 목표 비율과, 위 "직업 정보 누출 없음" 확인이다.

실제 확인은 `Tools > Today's Weapon Rental > Adventurer Preview` (**플레이모드 전용**)에서
반복 생성해 육안으로 한다. 흑인은 100명에 1명꼴이라 표본이 크게 필요하다.

## 기대 효과 / 리스크

**기대 효과**
- 등장 모험가의 피부색이 목표 비율에 맞는다.
- 비율이 인스펙터 필드(`skinRatioAsian` / `skinRatioWhite`)로 노출돼 코드 수정 없이 조정 가능하다.
- 색상이 직업을 흘리지 않는 성질은 그대로 유지된다.

**리스크 / 주의**
- **네임드 10종은 대상이 아니다.** 고정 색상이라 전체 화면 비율은 목표와 다르게 보일 수 있다.
- 흑인 1색 x 1% 라 사실상 거의 등장하지 않는다. 아트 다양성 관점에서 손실이지만 지시한 비율이다.
- `skinRatioAsian + skinRatioWhite > 1` 로 설정하면 흑인 그룹이 영원히 뽑히지 않는다.
  두 값의 합이 1을 넘지 않도록 인스펙터에서 관리해야 한다(코드 검증 없음).
- 각 리스트를 인스펙터에서 비우면 해당 그룹 추첨 시 기본색 `(1, 0.8, 0.7)` 이 나온다
  (기존 `skinColorPalette` 가 비었을 때와 같은 폴백).
