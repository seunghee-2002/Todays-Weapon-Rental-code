# 석궁 스탯 계수를 DEX+LUK -> STR+INT로 전환 (수요 0% 해소)

> 기록: 2026-07-29 · 작성: /balance
> 선행: [[2026-07-29_일반모험가_페르소나_20종|일반 모험가 페르소나 20종 개편]] 에서 "미해결" 로 남겼던 항목

## 근거 (왜)

**석궁은 어떤 스탯 분포에서도 최적 무기가 될 수 없었다.**

`weaponStatMultipliers` 에서 석궁 `(0.2, 0.9, 0.2, 0.8)` 은
수리검 `(0.2, 0.9, 0.2, 0.9)` 에 **성분별로 완전히 지배(dominated)** 당했다.
STR/DEX/INT가 동일하고 LUK만 0.1 낮으므로 수리검 점수가 항상 석궁 이상이다.
동률은 LUK=0일 때뿐이라 `GetBestWeaponType()` 이 석궁을 반환하는 경우가 사실상 없었고,
기본 무기 배정(최적 70% / 차선 20%)에서도 잡히지 않아 **수요가 정확히 0%** 였다.

밸런스 값 문제가 아니라 **테이블 구조 문제**라 스탯 분포로는 고칠 수 없었다.
(페르소나 20종 개편에서도 검 4.1->9.9%, 수리검 3.1->5.9%는 살렸지만 석궁만 0%로 남았다)

### 어디를 메울 것인가 - 단일 스탯이 아니라 스탯 쌍

"안 쓰이는 스탯을 석궁에 몰아준다"는 접근으로 확인해보니 **단일 스탯은 이미 균형**이었다.
석궁을 제외해도 주스탯 무기가 정확히 2개씩이다.

| 스탯 | 주스탯인 무기 (석궁 제외) |
|---|---|
| STR | 검, 도끼 |
| DEX | 활, 수리검 |
| INT | 지팡이, 마도서 |
| LUK | 단검, 수리검 |

비어 있던 건 **스탯 쌍**이었다. 2스탯 집중 페르소나의 최고 무기 점수를 재보면:

| 스탯 쌍 | 최고 무기 | 점수 |
|---|---|---|
| DEX+LUK | 단검 | 134.8 |
| INT+LUK | 마도서 | 133.8 |
| DEX+INT | 지팡이 | 129.5 |
| STR+LUK | 도끼 | 128.8 |
| STR+DEX | 검 | 127.5 |
| **STR+INT** | 마도서 | **121.2** <- 전용 무기 없음 |

STR과 INT를 동시에 쓰는 무기가 하나도 없어(검의 INT 0.2가 최대)
STR+INT 축이 다른 축보다 7~13점 낮은 "꽝 축"이었다. 석궁을 여기에 배치했다.

**테마 정합:** 석궁은 시위를 감아 장전하는 근력(STR)과 조준 장치·탄도 계산(INT)으로 쏘는
기계식 무기다. 활과 달리 손의 감각(DEX)이 거의 필요 없다.

## 대상 시스템 (무엇을)

- **성공률 계산**(`AdventureManager.Calculations`) — `GetStatScore` 가 이 테이블을 쓴다
- **기본 무기 배정**(`VisitorManager.CreateDefaultWeaponFor`) — 최적/차선 타입 판정
- **성공률 공개 조건**(`TypeAdvantage.IsStatMaskSatisfied` -> `InsightManager`) — required 마스크
- **무기 상세 패널 화살표**(`AdventurerMiniInfoPanel`, `PreparationWeaponDetailPanel`) — 계수에서 자동 계산되므로 코드 수정 불필요

## 수정 전후 (어떻게)

| 항목 | 전 | 후 | 위치(파일:필드) |
|---|---|---|---|
| 석궁 스탯 계수 (STR,DEX,INT,LUK) | `0.2, 0.9, 0.2, 0.8` | `0.9, 0.2, 0.9, 0.2` | `TypeAdvantage.weaponStatMultipliers[3]` |
| 석궁 성공률 공개 required 마스크 | `MaskDEX \| MaskLUK` | `MaskSTR \| MaskINT` | `TypeAdvantage.weaponRequiredStatMask[3]` |
| 석궁 anyOf 마스크 | `0` | `0` (불변) | `TypeAdvantage.weaponAnyOfStatMask[3]` |
| 석궁 화살표 표시 (STR/DEX/INT/LUK) | `0 / 2 / 0 / 2` | `2 / 0 / 2 / 0` | 자동 계산 (코드 변경 없음) |

계수 합은 2.1 -> **2.2**로, 활·수리검과 같은 최상단 대역이다(다른 무기 2.0~2.2).
DEX 0.2 / LUK 0.2는 화살표 임계값 0.3 미만이라 표시에는 잡히지 않는다.
required 마스크는 기존 규칙("최고 계수 스탯이 required, 동률이면 둘 다")을 그대로 적용한 결과다 - 수리검과 같은 논리.

`weaponArmorBonus` 의 석궁 행 `{-0.15, 0.45, -0.15, 0.30}`(경갑 특효)은 **건드리지 않았다.**

### 후보 비교

| 계수 | 합 | 석궁 | 검 | 최저 무기 | 판정 |
|---|---|---|---|---|---|
| `0.2, 0.9, 0.2, 0.8` (현행) | 2.1 | **0%** | 10.0% | 석궁 0% | 죽은 무기 1종 |
| `1.0, 0.4, 0.7, 0.0` (STR 주력) | 2.1 | 8.8% | 5.9% | 검 5.9% | 검을 잡아먹음 |
| `0.9, 0.2, 0.9, 0.1` (대칭) | 2.1 | 8.6% | 7.3% | 수리검 5.9% | 검토안 |
| **`0.9, 0.2, 0.9, 0.2` (대칭)** | 2.2 | **12.1%** | 6.8% | 수리검 5.8% | **채택** |
| `1.0, 0.2, 1.0, 0.0` (대칭 강화) | 2.2 | 15.8% | 5.2% | 검 5.2% | 과함, 검이 죽음 |

STR 주력형은 석궁이 STR 단독 축(도끼/검 영역)까지 침범한다.
**STR/INT를 대칭으로 둬야 "둘 다 높을 때만" 이기고**, 한쪽만 높으면 도끼/마도서에 진다.

## 시뮬 / 검증 근거

**프로젝트 BalanceSim은 돌리지 않았다.** `TypeAdvantage.cs` 를 파싱해 실제 배포된 계수를 읽고,
`Assets/_Projects/Data/Adventurers/ADV_NORMAL_*.asset` 20종의 range로 롤을 돌려
최적 무기 점수 분포만 계산했다 (페르소나당 40,000회 x 20종 = 80만 롤).
골드·평판·R 지표는 검증 범위 밖이다.

**완전 지배 쌍 검사: 8x8 전수 확인 결과 지배 관계 0쌍** (변경 전에는 석궁<-수리검 1쌍).

### 무기 수요 (기본 무기 배정 최적 타입 기준)

| 무기 | 전 | 후 |
|---|---|---|
| 도끼 | 22.1% | 18.4% |
| 활 | 18.0% | 17.6% |
| 단검 | 16.8% | 16.6% |
| 마도서 | 20.3% | 16.4% |
| **석궁** | **0.0%** | **12.1%** |
| 검 | 10.0% | 6.8% |
| 지팡이 | 6.9% | 6.3% |
| 수리검 | 5.8% | 5.8% |

**전 종목 5.8% 이상**으로, 최대/최소 비율이 무한대(0으로 나눔) -> 3.2배가 됐다.
석궁 수요는 `F_STR_INT` 90% / `M_STR_INT` 85%가 주축이고, `M_STR_LUK` 14% / `F_DEX_INT` 11% / `M_STR` 10%가 뒤를 잇는다.

**검 10.0 -> 6.8% (-3.2%p)는 절반 이상이 정상화다.** 변경 전 검 수요 중
`F_STR_INT` 35% + `M_STR_INT` 12% = 총 2.35%p가 "STR+INT 축에 무기가 없어 검이 대타로 뛰던" 몫이었고,
이게 석궁으로 이전됐다. 나머지 약 0.85%p는 `M_STR`(10%) 등에서 석궁이 실제로 잠식한 분이다.
검은 STR+DEX 전용으로 정리됐고, 최저 무기(수리검 5.8%)보다는 여전히 위에 있다.

### 인구 분포 / 성공률

| 지표 | 전 | 후 |
|---|---|---|
| 최적 무기 점수 평균 | 133.0 | 134.0 |
| 꽝 페르소나 | `F_STR_INT` 125.0 | `F_LUK` 127.2 |
| 당첨 페르소나 | `F_INT` 142.3 | `F_INT` 142.7 |
| Common 130 성공률 | 96.2% | 96.6% |
| Uncommon 155 | 85.4% | 86.0% |
| Rare 180 | 73.9% | 74.4% |
| Epic 230 | 57.8% | 58.2% |
| Legendary 280 | 47.5% | 47.8% |

성공률 변화는 전 등급 +0.6%p 이내로 무시 가능하다.

## 기대 효과 / 리스크

**기대 효과**
- 무기 8종 전부가 실질 수요를 갖는다. 죽은 재고가 사라졌다.
- STR+INT 페르소나 2종(`M/F_STR_INT`)이 전용 무기를 얻어 "꽝" 자리를 벗어났다.
  꽝 자리는 `F_LUK`(127.2)가 이어받아 **꽝/당첨 구조 자체는 유지된다**(스펙트럼 127.2~142.7).
- 석궁 성공률 공개 조건이 STR/INT로 바뀌어 통찰 공개 조합이 다양해진다.

**리스크 / 후속**
- **주간 퀘스트 난이도 재측정 필요.** WeeklyQuestGenerator.cs:558 (`Assets/_Projects/Scripts/Editor/WeeklyQuestGenerator.cs`)이
  석궁을 `HardScarceWeapon`(강한 병목)으로 잡고 있는데, 그 근거인 실측(상급자 석궁 6회 46.6%)은
  **석궁 수요가 0%이던 시절 데이터**다. 이제 플레이어가 석궁을 실제로 재고에 두게 되므로
  석궁 퀘스트가 쉬워질 가능성이 크다. `ScarceWeapons` 배정 자체는 무기 종류 수(석궁 5종) 기준이라
  이번 변경과 직접 충돌하지는 않는다.
- 석궁 상성표(`weaponArmorBonus`)는 경갑 특효로 남아 있다. STR+INT 무기가 경갑에 강한 것이
  어색하면 별건으로 조정한다.
- 기존 세이브의 대여 중인 석궁은 성공률이 달라진다(스탯 프로필이 바뀌었으므로). 진행 중 회차에서는 체감이 갈릴 수 있다.
