# 점술 이스터에그 발동 클릭 횟수를 3회에서 4회로 되돌림

> 기록: 2026-08-03 · 작성: /balance

## 근거 (왜)

`SeerConfig.asset`의 `easterEggConsultAtTouch`가 `3`으로 들어가 있어, **3회차 강한 경고 대사 풀(`easterEggLines3`, 5줄)이 인게임에서 도달 불가능**했다.

`SeerController.OnCrystalBallClicked`은 `crystalBallTouchCount < threshold`일 때만 경고를 출력한다. threshold가 3이면 실제 흐름은

- 1회차 클릭 -> `easterEggLines1` (경고)
- 2회차 클릭 -> `easterEggLines2` (경고)
- 3회차 클릭 -> 경고 없이 **결제 + 이스터에그 점술 발동**

이 되고, `SeerManager.GetEasterEggLine`의 `_ => easterEggLines3` 분기는 `touchCount >= 3`에서만 걸리므로 영원히 선택되지 않는다.

에셋 값이 outlier다. 근거 두 가지:
- `SeerConfig.cs:83`의 C# 기본값이 `4`
- 같은 필드의 툴팁이 `"이 횟수째 클릭부터 실제 결제+이스터에그 점술을 진행한다. 그 이전 클릭(1~3회차)은 경고 대사만 출력."` — 1~3회차 경고를 전제로 쓰여 있음

즉 대사 풀(1/2/3단계)과 툴팁 모두 threshold=4를 전제로 설계됐는데 에셋 값만 3이었다.

## 대상 시스템 (무엇을)

점술(`SeerManager` / `SeerController`) — 수정구 직접 클릭 이스터에그 분기. 상담 비용·확률 가중치·운세 보정값은 건드리지 않았다.

시뮬 없음 - 판단 근거: 코드 경로 추적. `SeerController.OnCrystalBallClicked`의 `crystalBallTouchCount < threshold` 조건과 `SeerManager.GetEasterEggLine`의 `touchCount switch { 1, 2, _ }` 분기를 대조해 `easterEggLines3` 도달 불가를 확인했다.

## 기대 효과 / 리스크

**기대 효과**
- 사장돼 있던 3회차 강한 경고 대사 5줄이 실제로 출력된다. 경고가 1단계(부드러움) -> 2단계 -> 3단계(강함) -> 발동으로 이어져 의도된 연출 계단이 복원된다.
- 유료 이스터에그 상담이 클릭 1회만큼 늦게 발동하므로, 수정구를 무심코 눌렀다가 상담비가 빠져나가는 사고가 조금 줄어든다.

**리스크**
- 이스터에그(LUK 무시 균등 25/25/25/25) 도달에 클릭이 1회 더 필요해진다. 저 LUK 모험가에게 균등 확률이 유리하므로 이론상 이 경로의 이용 빈도가 미세하게 줄 수 있으나, 클릭 1회 차이라 실질 영향은 무시할 수준으로 본다.
- 상담 비용·운세 보정값은 그대로라 골드 경제에 미치는 영향은 없다.
