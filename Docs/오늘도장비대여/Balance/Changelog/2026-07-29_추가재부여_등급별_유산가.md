# 추가 재부여 유산 비용을 등급 고정 5 -> 등급별 1/3/5/7/10으로 분리

> 기록: 2026-07-29 · 작성: /balance

## 근거 (왜)

추가 재부여(재부여 횟수를 다 쓴 무기에 유산으로 1회를 더 얹는 것)는 **무기 등급과 무관하게 5 고정**이었다.
같은 대장간의 유산 단발 소비인 **강화 즉시 재시도는 이미 등급별**(`1/3/5/8/15` + 강화레벨 x 3)로 갈라져 있어
두 창구의 가격 축이 어긋나 있었다.

재부여로 얻는 값어치는 등급에 비례한다 -- `WeaponInstance.Reroll`은 `RollOneEffect(currentGrade, ...)`로
**현재 등급 기준**으로 효과를 다시 뽑으므로, 전설 무기의 1회와 커먼 무기의 1회가 같은 값일 이유가 없다.
`reference/골드_경제_구조.md` 4장도 재부여를 "물건" 계열(강해질수록 값어치가 커짐 -> 등급 연동 가능)로 분류한다.

다만 **이번 조정은 골드가 아니라 유산 축이다.** 같은 문서 6-6에서 재부여 *골드* 등급 연동은
실측 결과 "함정/기형"으로 판정돼 적용되지 않았고(`rerollBaseGold` 2,500 고정 유지), 이번 변경도 골드는 건드리지 않는다.
후반 골드 싱크를 늘리는 게 아니라, 회차 간 자원(유산)의 소비 단가를 대상 무기 값어치에 맞추는 것이다.

곡선 값 `1/3/5/7/10`은 대화에서 확정했다. 현행 5를 **Rare 앵커로 유지**하고 상하단을 완만하게 벌린 형태이며,
Legendary 10은 강화 재시도 Legendary 기본값(15)보다 낮다.

참고로 추가 재부여의 성격은 코드상 이렇다 (가격 판단의 전제):
- **실패가 없다.** 결과가 마음에 안 들면 이전 효과를 고를 수 있다(before/after 선택).
- **무기당 1회로 제한**된다 (`isExtraRerolled` 플래그, 재부여 실행 후에도 해제되지 않음).
- 유산은 **충전 권리**에만 쓰이고, 실제 재부여 실행 시 **골드는 정상 소모**된다
  (`rerollBaseGold` x 잠금배율). 즉 유산 비용은 재부여 총비용의 일부다.

## 대상 시스템 (무엇을)

유산(`LegacyManager` / `LegacyConfig`) - 회차 도중 단발 소비 경로.
소비 지점은 대장간 재부여(`BlacksmithManager.TryAddExtraRerollCharge`).
효과·횟수 제한은 그대로이고 **비용만** 바꿨다.

## 수정 전후 (어떻게)

| 항목 | 전 | 후 | 위치(파일:필드) |
|---|---|---|---|
| 추가 재부여 유산 비용 (에셋 실값) | `5` (등급 무관 고정) | 등급별 **1 / 3 / 5 / 7 / 10** | LegacyConfig.asset: `extraRerollCost` -> `extraRerollCostByGrade` |
| 코드 기본값 | `int extraRerollCost = 2` | `int[] extraRerollCostByGrade = { 1, 3, 5, 7, 10 }` | LegacyConfig.cs:71-73 |
| 조회 API | `GetExtraRerollCost()` | `GetExtraRerollCost(WeaponInstance weapon)` | LegacyManager.cs:419-428 |

등급별 대비 (Common -> Legendary):

| 등급 | 추가 재부여 (이번) | 전 | 강화 즉시 재시도 기본 (참고, 불변) |
|---|---:|---:|---:|
| Common | 1 | 5 | 1 |
| Uncommon | 3 | 5 | 3 |
| Rare | 5 | 5 | 5 |
| Epic | 7 | 5 | 8 |
| Legendary | 10 | 5 | 15 |

- 조회는 `GetEnforceRetryCost`와 같은 패턴(`Mathf.Clamp((int)weapon.currentGrade, 0, len-1)`)을 쓴다.
- 호출부 2곳에 `weapon`을 넘기도록 시그니처만 맞췄다 -- `BlacksmithManager.cs:884`(차감), `BlacksmithRerollConfirmView.cs:218`(비용 표시).
- **함께 정리한 것**: `BlacksmithManager.ExecuteExtraReroll` 삭제(사용자 지시). 호출처가 없는 데드 코드였고,
  "유산 소비로 실행, 골드/재료 소모 없음"이라는 주석도 실제 흐름과 달랐다. 실제 흐름은
  충전(`hasExtraRerollCharge = true`) -> 일반 `ExecuteReroll`(골드 소모)이다. 수치 변경은 아니다.

### 함께 고친 동작 (수치 아님, 밸런스 영향 있음)

**1. 떠돌이 대장장이 무료 재부여가 재부여 횟수를 소모하던 것을 수정.**
`WeaponInstance.Reroll(lockedIndices, force: true)` 하나가 세 가지를 동시에 하고 있었다 --
`CanReroll` 체크 우회 / `isExtraRerolled = true` / `rerollCount++` + 충전분 소모.
그래서 **무료 이벤트로 재부여를 받으면 유료 재부여 3회 중 1회와 유산 추가 재부여 권리가 함께 날아갔다.**
파라미터를 `free`로 바꿔 의미를 "횟수 미소모 무료 재부여"로 좁히고, `isExtraRerolled` 설정은 삭제했다
(추가 1회 구매 기록은 `AddExtraRerollCharge()`가 이미 남긴다).
아침 이벤트의 실질 가치가 올라가는 방향이며, 유산 소비량에는 (권리가 살아남는 만큼) 소폭 증가 요인이다.

**2. 충전한 추가 1회가 UI에 드러나지 않던 것을 수정.**
유산을 내고 충전해도 표시가 `3/3` 그대로여서 무엇을 샀는지 보이지 않았다.
`WeaponInstance.DisplayMaxRerollCount`(= `Max(MaxRerollCount, rerollCount) + (충전 있으면 1)`)를 추가해
`3/3` -> **`3/4`** 로 최대 횟수가 실제로 늘어난 것처럼 보이게 했다. 소모 후에는 `4/4`, 진화로 횟수가
초기화되면 `0/3`으로 정확히 돌아온다.

## 시뮬 / 검증 근거

**시뮬 없음** - 밸런스 시뮬레이터(`Editor/BalanceSimulator/`)는 추가 재부여를 모델링하지 않는다
(`extraRerollCost` 참조가 시뮬 코드에 없다). 따라서 A/B로 측정할 수단이 현재 없다.

판단 근거:
1. 같은 유산 단발 소비인 **강화 즉시 재시도의 등급 곡선**(`1/3/5/8/15`)과의 축 정합성.
2. 현행 5를 **Rare 앵커**로 유지해 중간 등급의 체감 비용을 보존.
3. 재부여 결과가 등급 기준으로 굴려진다는 코드 사실(`RollOneEffect(currentGrade, ...)`).

## 기대 효과 / 리스크

- 기대: 초반 무기(Common/Uncommon)에서 진입 비용이 5 -> 1~3으로 낮아져, 유산이 귀한 1~2회차에도
  기능을 한 번 써 볼 수 있다. 고등급은 5 -> 7/10으로 올라 값어치에 맞는 단가가 된다.
- 리스크 (미측정): **총 유산 소모가 오히려 줄 수 있다.** 5개 등급 중 3개(Common/Uncommon/Rare)가
  같거나 싸졌고, 플레이어가 추가 재부여를 쓰는 무기가 저등급에 몰려 있으면 순감이다.
  다만 무기당 1회 제한이라 어느 쪽이든 절대량의 상한은 낮다.
- 리스크: 등급이 오르면(진화) 같은 무기의 표시 비용이 올라간다. 진화 -> 재부여 순서로 작업하는
  플레이어에게는 값이 바뀌어 보일 수 있다. 표시는 확인 팝업에서 실시간 계산되므로 불일치는 없다.
