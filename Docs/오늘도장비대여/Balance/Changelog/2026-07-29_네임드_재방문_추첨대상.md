# 네임드 재방문 추첨 대상을 자격자로 한정

> 기록: 2026-07-29 · 작성: /balance

## 근거 (왜)

테스터 중 네임드만 골라 모험에 보내는 유저가 있어 네임드 등장 확률을 점검하다가, 재방문 로직의 **게이트 조건과 추첨 대상이 어긋나 있는 것**을 발견했다.

- `ShouldSpawnReturningAdventurer()` 는 "호감도 50 이상 + 집에 있음 + 마지막 방문 후 3~5일 경과"인 **자격자가 1명이라도 있으면** 게이트를 연다.
- 그런데 실제 스폰하는 `SpawnReturningAdventurer()` 는 **집에 있는 네임드 전원**을 추첨 대상으로 삼았다. 호감도 필터도, 미방문일수 필터도 다시 걸지 않았다.

결과적으로 자격자 본인은 방문하지 않으므로 `lastVisitDay`(플레이어가 NPC를 클릭할 때만 갱신 - `VisitorNPC.cs:1120`)가 그대로 남고, **게이트가 한번 열리면 닫히지 않았다.** 호감도 50을 넘긴 네임드가 단 1명만 생겨도 그 시점부터 네임드 등장률이 상시 58% 이상으로 고정되는 구조였다.

의도된 설계가 아님을 확인받고 수정했다.

## 대상 시스템 (무엇을)

방문자 스폰(`VisitorManager`) - 네임드 재방문 판정. 밸런스 시뮬레이터(`SimCore`)의 미러 로직도 함께 정렬.

**Config SO 값 변경은 없다.** 재방문 확률(`baseRevisitChance` 0.5 / `maxAffectionBonusPerAdventurer` 0.2 / `maxRevisitChance` 0.9), 대기일수(3~6), 최소 호감도(50), 스폰 가중치(1:5) 모두 그대로다.

## 수정 전후 (어떻게)

| 항목 | 전 | 후 | 위치(파일:필드) |
|---|---|---|---|
| 재방문 추첨 대상 | 집에 있는 네임드 **전원** | 게이트를 통과한 **자격자만** | `VisitorManager.Spawn.cs:TrySpawnReturningAdventurer` |
| 게이트/스폰 메서드 구조 | `ShouldSpawnReturningAdventurer()` (bool) + `SpawnReturningAdventurer()` (무인자) | `TrySpawnReturningAdventurer()` (bool, 자격자 산출~스폰까지) + `SpawnReturningAdventurer(List<AdventurerInstance>)` | 동일 |
| 후보 0명 폴백 | `SpawnReturningAdventurer` 내부에서 `SpawnNewAdventurer()` 호출 | 제거 (자격자가 있을 때만 호출되어 도달 불가) | 동일 |
| 시뮬 미러 | `namedPool.Where(a => a.IsHome)` 전원 대상 | 자격자 리스트 대상 | `SimCore.cs:PickNamedVisitor` |

호출부 2곳도 `if (!TrySpawnReturningAdventurer()) SpawnNewAdventurer();` 형태로 교체 - `VisitorManager.cs:283`(`SpawnNextAdventurer`), `VisitorManager.cs:367`(Day 페이즈 진입).

**스폰 1회당 확률 공식 자체는 불변이다.** 달라지는 것은 자격자가 방문해 자격을 소모하고 3~5일 대기에 들어간다는 점이며, 이로 인해 하루 네임드 수의 상한이 "자격자 수 / 평균 대기 4일"로 잡힌다.

| 상태 | 스폰 1회당 네임드 확률 (전후 동일) |
|---|---|
| 자격자 0명 (게이트 닫힘) | 16.7% (가중치 1:5) |
| 자격자 있음, Max 달성자 없음 | 0.5 + 0.5x16.7% = 58.3% |
| Max 달성자 1명 | 0.7 + 0.3x16.7% = 75.0% |
| Max 달성자 2명 이상 (상한 0.9) | 0.9 + 0.1x16.7% = 91.7% |

## 시뮬 / 검증 근거

BalanceSimulator 미실행. **스폰 로직만 떼어낸 자체 몬테카를로**(800회차 x 30일, 네임드 8명, 네임드는 방문 즉시 모험 송출 = 테스터 시나리오)로 전후를 비교했다. 스크립트는 세션 스크래치패드에만 있고 저장소에 커밋하지 않았다.

하루 평균 네임드 방문 수 (괄호는 전체 방문자 대비 비율):

| 평판 | 호감도 상태 | 전 | 후 |
|---|---|---|---|
| Bronze (10.5명/일) | 전원 50 미만 | 1.75명 (16.6%) | 1.76명 (16.7%) |
| | 1명 50~70 | 2.73명 (25.9%) | 1.96명 (18.6%) |
| | 3명 50~70 | 3.68명 (34.9%) | 2.37명 (22.5%) |
| | 2명 Max + 4명 50~80 | 5.35명 (50.7%) | 3.10명 (29.4%) |
| | 8명 전원 Max | 5.61명 (53.2%) | 3.58명 (34.0%) |
| Gold (17.7명/일) | 전원 50 미만 | 2.94명 (16.6%) | 2.94명 (16.6%) |
| | 3명 50~70 | 4.76명 (26.9%) | 3.48명 (19.6%) |
| | 2명 Max + 4명 50~80 | 6.28명 (35.5%) | 4.09명 (23.1%) |
| | 8명 전원 Max | 6.55명 (37.0%) | 4.49명 (25.3%) |
| Diamond (25.6명/일) | 전원 50 미만 | 4.26명 (16.7%) | 4.27명 (16.7%) |
| | 3명 50~70 | 5.80명 (22.7%) | 4.69명 (18.3%) |
| | 2명 Max + 4명 50~80 | 7.08명 (27.7%) | 5.18명 (20.3%) |
| | 8명 전원 Max | 7.32명 (28.6%) | 5.51명 (21.5%) |

- **초반 구간(자격자 0명)은 전후 차이가 없다.** 게이트가 아예 열리지 않으므로 양쪽 다 16.7%.
- 감소폭은 호감도가 높을수록, 평판이 낮을수록 크다 (최대 -42%, Bronze 후반).
- 후반 비율이 고평판에서 낮게 보이는 것은 착시다. 자격자 공급은 하루 "인원수/4명"으로 고정인데 총 방문자가 평판에 비례해 늘어 희석된다. 절대 수는 Diamond 쪽이 많다(5.18 vs Bronze 3.10).

## 기대 효과 / 리스크

- **기대:** 호감도 50 돌파 순간의 계단식 점프(Bronze 16.6% -> 25.9%)가 사라지고, 호감도 투자량에 비례하는 완만한 커브가 된다. 재방문 대기일수(3~5일)가 비로소 의미를 갖는다.
- **리스크:** 호감도를 다 채운 만렙 구간의 네임드 등장이 하루 3.6~5.5명(전체의 21~34%)으로 내려간다. 유산 `NamedSpawnWeight` 만렙(+0.9)을 얹으면 +7~10%p. 이 정도가 호감도 육성 보상으로 충분한지는 테스터 피드백으로 재확인이 필요하다. 부족하면 레버는 `minRevisitDays`/`maxRevisitDays`(3~5 -> 2~4로 낮추면 만렙 구간 약 1.3배)가 1순위, `namedAdventurerSpawnWeight`는 초반까지 같이 올라가므로 2순위.
- 이번 수정과 무관하게 확인된 기존 사양: 네임드가 전원 자리를 비우면 `SpawnNamedAdventurer`가 최대 5회 재시도하며 매 회 30%로 "집에 아무도 없음" 이벤트를 띄우고 종료한다(방문자 0명). 5회 모두 통과하면 일반 모험가로 폴백한다. 의도된 동작이라 확인받아 손대지 않았다.
