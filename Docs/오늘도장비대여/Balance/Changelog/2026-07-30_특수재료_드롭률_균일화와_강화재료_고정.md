# 특수 재료 드롭률을 전 등급 10% 균일화 + 강화 재료를 던전별 고정 개수로

> 기록: 2026-07-30 · 작성: /balance

## 근거 (왜)

### 1) 등장 비율이 이미 등급 난이도를 담당하고 있었다

던전 등급별 등장 비율은 `questWeight x QuestBoardConfig.questWeightTiers[주차].gradeMultipliers`로 정해지는데,
주차에 따라 **100배 역전**된다.

| 구간 | 일반 | 고급 | 희귀 | 영웅 | 전설 |
|---|---:|---:|---:|---:|---:|
| ~4주 | 57.5% | 28.7% | 9.6% | 3.8% | **0.4%** |
| ~10주 | 35.9% | 38.5% | 17.1% | 6.8% | 1.7% |
| ~20주 | 18.8% | 28.1% | 31.2% | 15.6% | 6.2% |
| ~30주 | 6.5% | 12.9% | 28.8% | 34.5% | 17.3% |
| ~40주 | 2.0% | 5.0% | 13.3% | 39.9% | **39.9%** |

특수 재료 드롭률(2/4/6/10/20%)은 이 역전 위에 **같은 방향으로 한 번 더** 곱해졌다.
결과적으로 40주 평균, 특정 던전 1곳의 특수 재료 1개를 얻기까지 필요한 보스 성공 횟수가 **18배** 벌어져 있었다.

| 등급 | 특정 던전 1곳 선택률(40주 평균) | 필요 성공 횟수 |
|---|---:|---:|
| 일반 | 2.242% | **2,230회** |
| 고급 | 2.520% | 992회 |
| 희귀 | 5.463% | 305회 |
| 영웅 | 5.979% | 167회 |
| 전설 | 4.035% | **124회** |

### 2) 소비 성격이 공급과 정반대였다

특수 재료 28종의 소비처를 전수 조사한 결과, 등급별로 용도가 완전히 갈린다.

| 등급 | 소비처 | 소비 성격 |
|---|---|---|
| 일반 7종 | 액티브 아이템(보물지도·물약·부적·해체용단검·인형·강화석·황금아뮬렛) | **반복 소비** |
| 고급 4종 | 액티브 아이템(신속한신발·명예두루마리·강화석3·부적2) | **반복 소비** |
| 희귀 4종 | **없음** | - |
| 영웅 4종 | 영웅+전설 무기 | 1회성 |
| 전설 4종 | 전설 무기 | 1회성 |

**매 모험 쓰는 액티브 아이템 재료가 가장 안 나오고, 한 번 만들면 끝인 무기 재료가 가장 잘 나온다.**
40주 구간(주간 보스 성공 116회 실측, `sim_summary_20260729_233045`)으로 환산하면:

| 던전 | 특수재료 소비처 | 조정 전 획득 속도 |
|---|---|---|
| DGN_LEG_001 | 전설 무기 2종 | **주당 2.3개** |
| DGN_EPI_001 | 영웅+전설 무기 4종 | 주당 1.2개 |
| DGN_COM_001 | 보물지도 | **130주에 1개** |

전설 무기는 8종뿐인데 주당 2.3개가 쏟아진다. 반대로 같은 날 조정한
[[2026-07-30_액티브아이템_효과구조_전환|보물지도]]는 재료를 130주에 1개밖에 못 구한다.

### 3) 강화 재료는 랜덤이라 계획이 안 섰고, 시뮬이 25% 과다 계상 중이었다

강화 재료 개수가 `Random.Range(Config.enforceMaterialDropMin, Config.enforceMaterialDropMax)` =
`Random.Range(1, 4)`였다. `Random.Range(int, int)`는 max 배타적이라 실제로는 **1~3개(평균 2.0)** 인데,
필드명이 `Max = 4`라 4가 나올 것처럼 보였다.

더 문제는 시뮬 미러가 `rng.Next(min, max + 1)` = **1~4개(평균 2.5)** 로 구현돼 있어,
**시뮬이 강화 재료를 25% 과다 계상**하고 있었다. 이번 고정으로 양쪽 모두 해소된다.

## 대상 시스템 (무엇을)

- 모험 보상(`AdventureManager.Calculations`) - 특수 재료 드롭 판정, 강화 재료 드롭 개수
- 던전 정적 데이터(`DungeonData`) - 강화 재료 개수 필드 신설
- 대장간(`BlacksmithManager`) - 재료 종류 매핑은 불변(`GetEnforceMaterialByGrade`)
- 밸런스 시뮬레이터(`SimCore`) - 위 두 미러
- CSV 툴(`CSVExportTab` / `CSVImportTab`) - DungeonData 컬럼 동기화

## 수정 전후 (어떻게)

### 특수 재료 드롭률

| 항목 | 전 | 후 | 위치(파일:필드) |
|---|---:|---:|---|
| 일반 던전 | 0.02 | **0.1** | `AdventureConfig.specialDropCommon` |
| 고급 던전 | 0.04 | **0.1** | `AdventureConfig.specialDropUncommon` |
| 희귀 던전 | 0.06 | **0.1** | `AdventureConfig.specialDropRare` |
| 영웅 던전 | 0.10 | 0.1 (불변) | `AdventureConfig.specialDropEpic` |
| 전설 던전 | 0.20 | **0.1** | `AdventureConfig.specialDropLegendary` |

`GetSpecialDropChance`의 등급 switch는 **유지**했다. 값이 우연히 같아진 것이지
재조정 여지를 없앨 이유는 없다. 코드 기본값도 asset과 같은 0.1로 맞추고,
`// 1%` 류의 낡은 주석을 실제 값 기준으로 정리했다.

### 강화 재료 드롭 개수

| 항목 | 전 | 후 | 위치(파일:필드) |
|---|---|---|---|
| 개수 | `Random.Range(1, 4)` = 1~3 랜덤 (평균 2.0) | **던전별 고정** | `DungeonData.enforceDropCount` (신설, 전 던전 **2**) |
| Config 필드 | `enforceMaterialDropMin` = 1 | **제거** | `AdventureConfig` |
| Config 필드 | `enforceMaterialDropMax` = 4 | **제거** | `AdventureConfig` |
| 시뮬 미러 | `rng.Next(1, 4+1)` = 1~4 | `dungeon.enforceDropCount` | `SimCore.cs:1793` |
| 재료 종류 | 던전 등급 -> `MAT_ENF_001~005` | **불변** | `GetEnforceMaterialByGrade` |

**초기값을 전 던전 2로 잡아 총량을 보존했다.** 현재 런타임 기대값이 정확히 2.0이라
분산만 사라지고 공급량은 변하지 않는다. 같은 작업에서 특수 재료 드롭률을 움직이고 있어,
강화 재료 총량까지 동시에 바꾸면 시뮬 결과의 원인 분리가 안 되기 때문이다.
필드가 생겼으므로 던전별 차등(예: 소요시간 비례 45~55분 2개 / 60~75분 3개 / 85~100분 4개)은
언제든 값만 바꿔 적용할 수 있다.

**시뮬 미러 부수 수정**: 런타임은 대성공 배율을 기본량에만 곱하고 무기 효과
(`EnforceMaterialBonus`) 분에는 곱하지 않는데, 시뮬은 합산 후 곱하고 있었다. 런타임 기준으로 맞췄다.

### CSV 동기화

`DungeonData` 컬럼이 12 -> **13**으로 늘었다(`specialDropMaterialID` 다음에 `enforceDropCount` 삽입).

- `CSVExportTab.BuildRows_DungeonData` - 헤더/행 추가
- `CSVImportTab.Diff_DungeonData` - 헤더/행 추가
- `CSVImportTab.Apply_DungeonData` - `Validate(.., 13, ..)` + 규칙 배열에 `"int"` 추가, `Read(.., 13)`,
  뒤따르는 `dungeonIconPath`/`mapBackgroundPath` 인덱스를 10,11 -> 11,12로 이동
- `Assets/_Projects/Data/CSV/DungeonData.csv` - 기존 28행에 컬럼 삽입(전부 `2`)

## 시뮬 / 검증 근거

**드롭률 계산은 실측 데이터 기반, 회차 지표 시뮬은 미실행.**

- 등장 비율: `QuestBoardConfig.asset`의 `questWeightTiers` 5구간 x 던전 28종 `questWeight` 전수 계산
- 주간 보스 성공 116회: `Simulation/sim_summary_20260729_233045.md` 상급자 40주차 실측
- 소비처: 무기 레시피 16종 + 액티브 아이템 레시피 11종 + 코드 하드코딩 전수 검색
- 강화 재료 소비: `BlacksmithManager` 강화 1회당 5개(`ApplyMaterialReduction(5)`), 무기 등급 기준

조정 후 예상값:

| 등급 | 조정 전 | **조정 후** |
|---|---:|---:|
| 일반 | 2,230회 | **446회** |
| 고급 | 992회 | 397회 |
| 희귀 | 305회 | 183회 |
| 영웅 | 167회 | 167회 |
| 전설 | 124회 | 248회 |

**격차 18배 -> 2.7배.** 전설 무기 재료는 주당 2.3 -> 1.2개, 액티브 아이템 재료는 130 -> 26주에 1개.

## 기대 효과 / 리스크

**기대**
- 후반 전설 무기 제작이 지나치게 쉬워지던 문제 완화(주당 2.3 -> 1.2개).
- 액티브 아이템 재료 획득이 5배 빨라져, 같은 날 조정한 보물지도의 재료 병목이 일부 풀린다.
- 강화 재료 공급이 결정적이 되어 "이 던전 N회 = 강화 1회분(5개)" 계산이 선다.
- 시뮬-런타임 강화 재료 불일치(25% 과다) 해소.

**리스크**
- **액티브 아이템 재료는 여전히 부족하다.** 26주에 1개로, 회차가 40주인 것을 감안하면
  후반 제작은 사실상 불가능하다. 근본 원인이 등장 비율 쏠림이라 드롭률로는 여기까지다.
  보류 중인 "소비처 없는 특수 재료 9종"(희귀 4종 포함) 처리와 함께 풀어야 한다.
- 초반(~4주) 특수 재료가 3.33% -> 10%로 3배 완화된다.
  [[2026-07-28_무기제작_특수재료]]에서 드롭률을 이미 2배 올린 위에
  추가 완화라, 초반 제작 속도가 과할 수 있다 - **시뮬 미확인**.
- 강화 재료 총량은 불변이지만 분산이 0이 되어, 운 좋게 3개 나오던 경우가 사라진다.
  체감상 공급이 줄었다고 느낄 수 있다.
- `DungeonData`에 필드가 늘어 CSV 컬럼 인덱스가 밀렸다. 외부에 별도 보관된 구 CSV로
  임포트하면 컬럼 수 검증(`Validate`)에서 걸러지지만, 반드시 Export 후 사용해야 한다.
