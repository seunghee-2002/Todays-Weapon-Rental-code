# 밸런스 시뮬레이터 설계 — 하루 루프와 페르소나

> **목적**: [[주간퀘스트_레벨디자인]]의 실측 필요 항목(평판 곡선·주간 성공 수·
> 순수입·앵커)을 플레이테스트 전에 산출하기 위한 **페르소나 봇 시뮬레이터**의 명세.
>
> 핵심 원칙: **시간이 유일한 공유 자원이다.** 정보 행동(대화 테스트)은 전역 게임 시간을 전진시키고,
> 그동안 대기 손님의 체류 타이머가 흐르고 스폰이 진행되고 모험이 굴러간다. 하루 루프는 이 시간
> 예산의 배분 문제로 모델링한다.
>
> 모든 수치·규칙은 코드/에셋/씬에서 **검수 완료**했으며 출처를 병기한다 (2026-07-25).
> 초안의 "구현 중 검증 항목" 6건은 전부 해소되어 §8 검증 결과로 대체했다.
> **상태**: 설계 확정. 코드 없음. 구현 착수 대기.

---

## 1. 시간 모델

```
하루 = 06:00 ~ 21:00 = 900 게임분          (TimeManager, 1 실초 = 3 게임분)

아침  06:00~09:00  180분   NPC 상호작용 (스킵 가능 -> 시뮬에서는 "무료 페이즈")
낮    09:00~18:00  540분   모험가 스폰 + 의뢰판 + 모험 진행
저녁  18:00~21:00  180분   스폰 없음, 모험 진행, 18:00 보고 전령 스폰
밤    21:00~       시간 자동 정지 -> 다음날 (보고 전령의 보고 수령이 선행 조건)
```

- 의뢰판은 낮 진입(9시) 생성 -> 던전 확정·수색 파견은 낮부터.
- **모험은 아침·저녁에도 진행**된다 (`AdventureManager.OnTimeChanged -> UpdateAdventures`).
- **방문자 상호작용 중에는 전역 시간이 정지**한다 (`VisitorNPC.StartInteraction -> PauseTime`).
  화면을 보며 고민하는 시간은 무료고, 시간을 쓰는 건 **대화 테스트의 점프**뿐이다.
- **밤 점프**: `GoToNextDay`는 시간 좌표를 다음날 06:00으로 즉시 설정한다. 이월된 모험의
  "진행 중이던 이벤트 1칸"은 좌표 점프에 흡수되어 **아침 첫 틱에 즉시 완료**되고,
  이후 칸은 06:00부터 정상 속도로 진행된다 (`TryProcessNextEvent`가 `CurrentTime` 비교).

## 2. 시간 소비 행동 인벤토리 (전 시스템 조사 결과)

시뮬레이션 관점에서 모든 플레이어 행동은 4종으로 나뉜다.

### 2-1. 전역 시간 전진 (하루 예산을 실제로 깎는 행동)

| 행동 | 시간 비용 (게임분) | 출처 |
|---|---|---|
| 대화 테스트 (스탯 1개 / 특성 / 무기 힌트) | 통찰 0~29: **60** / 30~49: 42 / 50~69: 24 / 70+: 12 | `InsightManager.GetStatTalkTimeCost` |
| 종합 테스트 (전체 스탯) | 위의 **2배** (120 -> 24) | `GetAllStatTalkTimeCost` |
| (제약) | 비용 < 21시까지 남은 시간, 그리고 <= 180분 | `CanStartTalkAction` |

시간은 `AdventureTalkAnimationPopup`이 `TimeManager.AdvanceGameTime`으로 **3분 단위로 실제 전진**시킨다.
**테스트 중 그 모험가의 체류 타이머는 정지**(isInteracting), **다른 대기 손님의 타이머는 흐른다**
(`VisitorNPC.UpdateStayTimer`). 이것이 "테스트하면 다른 손님이 떠난다" 트레이드오프의 실체다.

### 2-2. 병렬 진행 (시간이 걸리지만 플레이어를 점유하지 않음)

| 프로세스 | 소요 (게임분) | 점유 자원 | 출처 |
|---|---|---|---|
| 모험 | **칸 수 x 60분 x 배율** (아래) | **무기 1자루** + 모험가 | `GetEventDuration` |
| 수색꾼 | 기본 120/80/40/20(통찰 구간) x 등급 배수 x 0.5~1.5 | 골드 (날짜 x 30 x 등급배수) | 통찰_시스템 §5 |

**모험 칸 수** = 입장 1 + 중간 (등급 이벤트 수 - 1) + 보스 1 + 귀환/후퇴 1 (삽입).
전 이벤트가 기본 60분이다 — **DungeonEvents 에셋 153개 전수 확인 결과 `intervalHours` 오버라이드 0건**,
삽입 이벤트(귀환·후퇴·재도전·보호·함정회피)도 예외 없이 60분씩 소모한다.

| 던전 등급 | 이벤트 수 | 성공 시 총 칸 | 소요 |
|---|---:|---:|---:|
| 일반 | 3 | 5 | **300분 (5시간)** |
| 고급 | 4 | 6 | 360분 |
| 희귀 | 5 | 7 | 420분 |
| 영웅 | 7 | 9 | 540분 (9시간) |
| 전설 | 10 | 12 | **720분 (12시간, 하루 초과)** |

강조 던전은 중간 칸이 2배(`(n-1)*2+1`), 보호/재도전 발동 시 +1칸씩. 배율: 특성 신속 0.5 /
집중 1.5, 무기 시간 단축(최대 -50%), 유산 모험 속도. 3분 단위 내림.

### 2-3. 즉시 행동 (시간 0)

| 행동 | 소모 | 비고 |
|---|---|---|
| 무기 배정·모험 출발 | - | 무기는 반환까지 점유. **던전별 동시 출발 제한 없음** (`StartAdventure`에 던전 가드 없음) |
| 점술 상담 | 골드 (날짜 x 50) | (모험가 x 던전) 쌍당 1회/일 |
| 무기 구매·상점 새로고침 | 골드 | 상호작용 중 시간 정지 |
| 대장간 작업 (강화·진화·재부여·분해·제작) | 골드+재료 | **즉시 판정 확정** — `BlacksmithManager`에 시간 참조 없음 |
| 의뢰판 새로고침·확정 | 골드 | |
| 모험 결과 확인 | - | **확인해야 보상 지급 + 무기 반환 + 퀘스트 갱신**. 낮에는 모험 목록 -> 결과창으로 개별 확인 가능 (`AdventureResultController`가 열리는 순간 확정) |
| 기본 무기 타입 관찰 | - | **무료 정보**: 기본 무기는 70% 최적 / 20% 차선 / 10% 무작위 타입 (`CreateDefaultWeaponFor`) |

**보고 전령(Herald)**: 18:00 스폰(체류 183분), 그 시점까지 완료된 미확인 모험을 스냅샷해 순서대로 보고한다.
**보고를 다 받아야 다음날로 넘어갈 수 있다** (`GoToNextDay`의 `HasPendingHeraldReport` 가드).
즉 게으른 플레이어도 하루 끝에는 강제로 결과를 확인하게 된다 — 확인 시점(낮 즉시 vs 저녁 보고 전령)이
무기 회전율을 가르는 페르소나 차별점이다 (§5).

### 2-4. 수동적 시간 경과 (플레이어와 무관하게 흐름)

| 항목 | 값 (게임분) | 출처 |
|---|---|---|
| 모험가 스폰 간격 (낮만) | Bronze 35~45 / Silver 30~40 / Gold 25~35 / Platinum 20~30 / Diamond 15~25, 클램프 15~45 | `ReputationConfig` + `VisitorConfig` |
| 방문자 체류 | 모험가 **45** (호감 Max 60) / 무기상 60 / 대장장이 60 / 이벤트 NPC 90. 떠나기 10분 전 경고 | `VisitorConfig` |
| 방문 구성 (낮 스폰) | 재방문 판정 -> 신규 (네임드 1 : 일반 5). **이벤트 NPC는 낮 스폰과 무관 — 아침 전용** (확률 5~20%, `CheckAndSpawnEventNPC`) | `VisitorManager` |
| 대기 상한 | **대기열 5 + 상호작용 5** (씬 실측). 대기열이 차면 스폰 보류 — 방문 손실이 아니라 **지연** (타이머 유지, 자리 나면 즉시 재개) | `IsVisitorCapReached` + `InGameScene` |
| 일반 모험가 풀 | 아침에 8명 사전 생성, 소진 시 즉석 생성 (하드캡 아님) | `VisitorConfig` |

> 스폰 간격·체류 시간의 Config 주석 "게임 시간 초"는 오기 — 실제 틱 단위는 **게임 분**이다
> (`CheckAdventurerSpawnByGameTime(gameMinutes)`, `VisitorNPC` 헤더 "게임 시간 분 단위").

## 3. 하루 루프 (시뮬레이션 의사코드)

```
[아침 06:00~09:00 — 시간 무료 페이즈]
  1. 이월 모험: 진행 중이던 1칸 즉시 완료 처리, 이후 06:00부터 정상 진행
  2. 대장장이(매일 확정): 페르소나 강화/제작 정책 실행 (즉시 판정)
  3. 무기상(등장일이면): 페르소나 구매/새로고침 정책 실행
  4. 이벤트 NPC (확률 5~20%, 평판): v1은 등장만 모델링하고 효과 제외 (§7)
  5. 아침 스킵 -> 09:00 (스킵 중에도 모험은 3분 단위로 진행)

[낮 진입 09:00]
  6. 의뢰판 생성 (questWeight 추첨 재현) -> 페르소나 새로고침/확정 정책
  7. 수색꾼 파견 (페르소나 정책, 병렬)

[낮 09:00~18:00 — 분 단위 진행]
  매 분:
    - 스폰 타이머 누적 -> 도착 시 방문자 큐에 추가 (대기열 5 초과 시 보류, 간격 재추첨)
    - 대기 방문자 체류 타이머 감소 -> 0이면 이탈
    - 진행 중 모험 이벤트 처리 (칸당 60분)
    - 완료 모험 -> 페르소나 확인 정책 (즉시 or 보고 전령 대기)
  플레이어 행동 (여유 시점마다, 의사결정 자체는 무료 — 상호작용 중 시간 정지):
    - 대기 모험가 중 1명 선택 (오래 기다린 순)
    - 페르소나 정보 정책 실행 (대화 테스트만 시간 점프 발생)
    - 페르소나 배정 정책: 무기 + 확정 던전 선택 -> 출발 (즉시)
    - 보낼 수 없으면(무기 없음/기본 무기 거부) 돌려보냄

[저녁 18:00~21:00]
  - 18:00 보고 전령 스폰: 미확인 완료 모험 스냅샷
  - 모험 진행 계속. 보고 전령의 보고 수령 (전 페르소나, 다음날 진행의 선행 조건)

[21:00 하루 종료]
  - 미완료 모험 이월. 날짜 +1 -> 주 경계면 주간 퀘스트 판정 (보상 지급 / 벌금 + 평판 페널티)
```

## 4. 병목 구조 — 무엇이 주간 성공 수를 결정하는가

하루 처리량은 세 자원의 MIN이다:

```
일일 모험 수 = MIN( 방문자 공급, 무기 회전, 의사결정 시간 )

방문자 공급  = 540 / 스폰 간격 = 13.5(Bronze) ~ 27(Diamond) 명
무기 회전    = 무기 수 x 일 2회 (일반 던전 5시간 기준, 낮 즉시 확인 시)
              + 저녁 출발 -> 밤 점프 -> 아침 완료 파이프라인 약 +0.5회
의사결정     = 대화 테스트 사용량에 좌우 (통찰 0: 60분/회 -> 통찰 70+: 12분/회)
```

- **초반 진짜 병목은 무기 수다.** 무기 2~3자루면 일 4~7회가 상한. 방문자 13명 중 나머지는
  기본 무기로 보내거나(성공률 x0.8, 파괴 위험 없음) 돌려보낸다.
- **확인 습관이 회전율을 가른다.** 낮에 개별 확인하면 무기당 일 2회, 보고 전령(저녁)에서만 확인하면
  일 1회다. 페르소나 차별점 (§5).
- **테스트는 통찰 0에서 60분/회** — 남발하면 하루가 증발한다. 기본 무기 타입 관찰(무료, 70% 정확)이
  초반 최적 정보 행동인 이유다. 통찰 70+면 12분이라 비용이 사실상 사라진다 —
  **통찰 성장 = 시간 예산 성장**이라는 숨은 곡선.
- **계수 문서 §2-3 가정(주간 성공 = SC x 1.5 = 초반 주 6회)은 보수적일 가능성이 높다.**
  무기 3자루 x 일 5회 x 성공률 50~60%만 잡아도 주 17~21 성공이 나온다. 시뮬의 1차 산출물이
  이 실효 곡선이고, 여기서 평판 곡선·티어 게이트가 전부 다시 나온다.

## 5. 페르소나 3종 — 의사결정 정책 (확정)

공통(전 페르소나): 보고 전령의 보고는 반드시 수령(강제) / 주간 벌금 자동 납부(골드 부족 시 폐업 = 시뮬 종료) /
유산·긴급 환전·액티브 아이템 미사용(v1) / 모험가 응대는 오래 기다린 순.

### 상급자 "민맥스" — 정보를 사서 상성을 맞춘다

| 국면 | 정책 |
|---|---|
| 아침-대장장이 | 주력 무기 강화: 골드 >= 비용 x 3이면 실행. 풀강화 무기는 진화 시도(성공률 >= 50%일 때만) |
| 아침-무기상 | 미보유 타입 우선 구매(타입 커버리지 확대), 골드 >= 가격 x 2일 때. 커버리지 부족하면 새로고침(최대 3회) |
| 의뢰판 | 퀘스트 목표 던전 우선 확정, 나머지는 (보상 x 예상 성공률) 최대 순. 목표 던전이 안 떴으면 새로고침 1~2회 |
| 수색 | 확정 던전 전부 파견 (골드 허용 시) -> 방어 타입 공개 후 상성 배정 |
| 모험가 응대 | ① 기본 무기 타입 관찰(무료) ② 그 타입의 보유 무기가 있으면 최고 등급 대여 ③ 없으면 무기 힌트 대화(**통찰 50+부터만** — 초반 60분은 비효율) ④ 배정 던전 = 공개된 방어 타입과 상성 최적 |
| 결과 확인 | **낮 즉시 확인** (무기당 일 2회 회전) |
| 대여 불가 시 | 기본 무기로 최저 등급 던전에 보냄 (탐험도·평판 적립) |

### 중급자 "감각파" — 하나만 확인하고 보낸다

| 국면 | 정책 |
|---|---|
| 아침-대장장이 | 주 1회 정도 강화 (골드 >= 비용 x 5일 때) |
| 아침-무기상 | 가장 싼 무기 1~2개 구매 (골드 >= 가격 x 3일 때). 새로고침 안 함 |
| 의뢰판 | 첫 풀에서 낮은 등급 위주로 확정. 새로고침 안 함 |
| 수색 | 안 함 (방어 타입 모름 -> 상성은 운) |
| 모험가 응대 | ① 스탯 테스트 1회 ② 성공하고 값이 높으면(>= 50) 해당 스탯 주력 무기 타입 대여 ③ 실패/낮으면 아무 무기나 |
| 결과 확인 | 낮 즉시 확인 |
| 대여 불가 시 | 기본 무기로 보냄 |

### 초급자 "막무가내" — 아무거나 쥐여 보낸다

| 국면 | 정책 |
|---|---|
| 아침-대장장이 | 안 함 |
| 아침-무기상 | 골드 절반 이하로 떨어지지 않는 선에서 가장 싼 것 1개 |
| 의뢰판 | 첫 풀에서 앞에서부터 확정 |
| 수색·점술·테스트 | 안 함 (시간 소비 0 — 처리량은 최대) |
| 모험가 응대 | 남는 무기 아무거나 대여, 던전도 아무거나. 무기 없으면 기본 무기 |
| 결과 확인 | **보고 전령이 왔을 때만** (무기당 일 1회 회전 — 결과를 낮에 안 챙기는 플레이 반영) |

> 페르소나 간 차이 = "성공률 품질 vs 시간 소비 vs 회전율"의 3축 트레이드오프. 상급자는 회당
> 성공률·회전율이 높지만 초반 응대 폭이 좁고, 초급자는 다 보내지만 상성 운 + 회전 반토막.
> 통찰이 크는 중반 이후 상급자가 전 축에서 역전하는 구조로 예상 — 시뮬이 검증한다.

## 6. 산출물 (주차별 x 페르소나 x 시드 100)

| 지표 | 보정 대상 |
|---|---|
| 누적 평판, 평판 등급 도달 주차 | 레벨디자인 문서 §4 도입 스케줄, 계수 문서 §2-3 |
| 주간 모험 성공 수 (시도/성공/대성공) | SC 곡선, 앵커 (§3-1) |
| 주간 순수입 골드 | 벌금 기울기 (§8-4), 골드 목표 (계수 §6) |
| 등급별 무기 첫 확보 주차, 보유 무기 수 추이 | 등급 요구 게이트 (§3-1) |
| 주간 퀘스트 통과율 (기존 100주 데이터 대입) | 시험주 합격선: 중급 ~70% / 상급 95%+ / 초급 <40% |
| 하루 시간 사용 내역 (테스트/대기/유휴) | 페르소나 검증, 통찰 성장 효과 확인 |

## 7. v1 단순화 (명시적 오차 요인)

| 제외 항목 | 예상 편향 |
|---|---|
| 기분(Mood) 배율 | 평균 ~1.0이라 중립 (자기과신 -7.5% 꼬리만 손실) |
| 특성 16종 | 성공률 소폭 보수 (Rising/Focused 등 상향 특성 무시) |
| 아침 이벤트 효과 | 수입 소폭 보수 (상자/사절단 수입 누락). 등장만 모델링 |
| 네임드·호감도·재방문 | 성공률 보너스(최대 +5%)와 단골 흐름 누락 — 일반 모험가만 시뮬 |
| 액티브 아이템·선물 | 부적/포션 보정 누락 |
| 유산·회차 반복 | 1회차 신규 유저 기준 (보수적 하한 — 계수 문서와 같은 방향) |
| 함정 누적 패널티·점술 운세 보정 | 성공률 소폭 중립~보수 |

전부 "성공률/수입을 약간 낮게" 방향이므로, 시뮬 결과는 **보수적 하한**으로 읽는다.

## 8. 검증 결과 (초안의 검증 항목 6건 — 전부 해소)

| # | 질문 | 결론 | 근거 |
|---|---|---|---|
| 1 | 21시 정지 시 모험 이월 | 시간 좌표가 다음날 06:00으로 점프 -> **진행 중이던 1칸은 아침 첫 틱에 즉시 완료**, 이후 정상 진행. 모험은 아침·저녁에도 진행 | `TimeManager.GoToNextDay`, `AdventureManager.OnTimeChanged` |
| 2 | 대장간 작업 시간 | **즉시 판정** (시간 참조 없음). 상호작용 중 전역 시간 정지라 화면 체류도 무료 | `BlacksmithManager`, `VisitorNPC.StartInteraction` |
| 3 | 이벤트 NPC 스폰 편입 | **아침 전용** (확률 5~20%, 유산 보장 별도). 낮 모험가 스폰 슬롯과 무관 | `VisitorManager.Npc.CheckAndSpawnEventNPC` |
| 4 | 동시 대기 상한 | **대기열 5 + 상호작용 5** (씬 실측). 초과 시 스폰 보류 = 지연이지 손실 아님 | `IsVisitorCapReached`, `InGameScene.unity` |
| 5 | 삽입 이벤트 시간 | **전부 60분** — 153개 에셋 전수에서 `intervalHours` 오버라이드 0건, 기본값 1시간 적용 | `Data/DungeonEvents/*.asset`, `GetEventDuration` |
| 6 | 같은 던전 동시 다수 모험 | **허용** — `StartAdventure`에 던전 기반 가드 없음 (null 체크뿐) | `AdventureManager.Calculations` |

추가 확정 사항:
- **상호작용 = 전역 시간 정지** -> 의사결정은 무료, 대화 테스트 점프만 시간 소비 (§2-1).
- **보고 전령의 보고 강제** -> 미확인 결과는 하루를 넘기지 못한다. 확인 시점이 페르소나 차별점 (§2-3, §5).
- 모험 성공 시퀀스 = 입장 + 중간 + 보스 + 귀환 = 등급 이벤트 수 + 2칸 (§2-2 표).

## 9. 구현 형태 (확정)

- `Scripts/Editor/BalanceSimulator/` 4파일 (Window / SimCore / SimPersona / SimReport) — 에디터 전용,
  런타임 코드 무변경. 수식은 미러링하되 원본 파일·라인을 주석으로 박는다.
- 진행 단위: **분 단위 틱** (모험 60분, 테스트 12~120분, 체류 45분이 모두 분 해상도. 3분 내림 규칙 준수).
- 데이터는 실제 SO/CSV를 AssetDatabase로 로드 (Config·Dungeon·Weapon·Adventurer·WeeklyQuest·DungeonEvents).
- 출력: `Documents/Simulation/` 아래 CSV + 요약 md.
- 파라미터 확정: **시드 100회 / 기간 100주 (폐업 시 조기 종료) / 페르소나 3종**.
- 상급자 대화 테스트 정책(통찰 50+)은 Window에서 토글 가능하게 두어 A/B 비교를 지원한다.

## 남은 위험 (구현이 아닌 해석의 문제)

1. 페르소나 임계값(골드 배수 3/5, 스탯 50 등)은 합리적 추정 — 시뮬 결과가 극단적이면 재조정한다.
2. v1 단순화(§7)로 인한 하한 편향 — 라이브 데이터가 들어오면 상한 보정.
3. 수식 미러링의 원본 이탈 위험 — 원본 파일·라인 주석 + 대표 케이스 손계산 대조로 완화.
